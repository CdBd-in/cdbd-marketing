## 🚨 실제로 일어났던 사고 3종 — 반드시 통과

> 과거 사용자가 직접 지적했던 사고. 같은 실수 반복 = 신뢰 손실.

### ☐ ① 원본 텍스트 손대지 않았나
**과거 사고 (2026-06-04)**: "고객도 지치는," "전화 핑퐁 모바일," 쉼표 임의 추가 → 정정 시도에서 "줄 끝 쉼표 제거" 룰을 또 임의로 만듦 → 결국 사용자가 "원본 그대로 + `\n` 추가만"으로 룰 단순화.

- **체크**: 입력 타이틀 원문 vs 각 안 `TITLE.characters` (단 `\n` 제거 후) 문자 단위 비교.
- **❌ 실패**: 쉼표·마침표·느낌표·물음표 추가 / 띄어쓰기 추가·삭제 / 글자 변경 — **1개라도 있으면 전체 재작업**.
- 📌 [[2. 자동화 체크리스트|2]] §텍스트 절대원칙 ① / [[1. 블로그/썸네일/1. 디자인 가이드/1-1. 스타일]] §3.

### ☐ ② 어절이 두 줄에 걸쳐 잘리지 않았나
**과거 사고**: 자동 줄바꿈에 맡겨서 "고객도 지치는 전 / 화 핑퐁" 같은 사고. 폭 검수 누락 사례 06-04에도 명시.

- **체크**: 각 줄 끝 글자와 다음 줄 첫 글자가 한 어절을 이루지 않는지 육안 + `TITLE` 노드 width = 350 + `textAutoResize = HEIGHT` 둘 다 강제 적용됐는지.
- **❌ 실패**: 어절 중간 잘림 / 강조 키워드가 두 줄에 걸침 / width 350 아님.

### ☐ ③ 가이드 표를 그대로 인용했나 (임의 추측·즉석 키워드 ❌)
**과거 사고**: 레이아웃 유형을 임의 키워드로 분류 (06-01 사용자 강조) / 코드에 즉석 매핑 키워드 추가 (06-01 "자꾸 임의 키워드 만들지 말고 §5.1·§5.4 그대로 인용") / 3D 아이콘 AI 생성 (Thiings 카탈로그 무시).

## 🟡 사용자가 첫눈에 알아채는 마무리 4종

> 사고는 아니지만 빠뜨리면 사용자가 보자마자 "이건 좀…"하고 지적하는 항목.

### ☐ ④ 강조 영역 1개 / 의미 단위 / 서브 그린
- TITLE 강조 **영역 1개**만 Purple `#8F80FF` 인라인 — 영역 안 내용은 **의미 단위 1개** (단어 1개 또는 한 구(phrase), 단어 수 무관).
- SUBTITLE 전체 Green `#4DE98B` / E 유형은 전부 흰색.
- ❌ 흰색 그대로 / 강조 **영역**이 2개로 갈라짐 ("**5분**에 만드는 **법**") / 의미 단위 중간에서 잘림 ("5분에 **만드는**") / E인데 강조색.
- 📌 캐논 규칙 → [[1. 블로그/썸네일/1. 디자인 가이드/1-1. 스타일#강조-키워드-선택-원칙|강조 키워드 선택 원칙]]

### ☐ ⑤ 의미 영역 크롭 — viewer 상단만 보이지 않나
- A/B/C 유형 `VISUAL_SLOT`에 **타이틀이 가리키는 그 기능·섹션**이 실제로 보이는가.
- ❌ `scaleMode: 'FILL'`만 적용 → 프로필·헤더만 보이고 핵심 기능 안 보임 / "예약 관리" 타이틀인데 viewer 상단 명함만 보임.
- 📌 [[1-3. 이미지 규칙]] §1.1.b / [[1-3. 이미지 규칙]] §3.1 영역 좌표 표.

### ☐ ⑥ 슬롯 점선 placeholder 안 남았나
- 모든 슬롯 노드 순회 — `strokes` 비어있고 임시 회색 fill 없는지.
- ❌ 점선 stroke 그대로 출력 / 빈 fills 슬롯 노출.

### ☐ ⑦ 출력 페이지 + 유형별 안 패턴 + 하단 슬롯 y 검증
- **출력 페이지**: 시안이 **AI 제작 이미지 (`26:2`)** 페이지에 있는가. 슬롯 원본 페이지(🧩 `338:3221`)에 부착됐으면 ❌.
- **유형별 안 패턴**: A·B·D는 상단·서브 + 하단·서브 / C·E는 다른 자산 조합 2안.
- 🆕 **하단 슬롯 TEXT_BLOCK y 재계산 검증** (2026-06-18 추가) — A·B·D 하단·서브 변형에서 TITLE width 확장(강조어 길이 사고 대응)이나 줄 수 변동으로 TEXT_BLOCK 높이가 바뀌면 **y = 410 - height** 공식으로 재정렬 필수. 410 고정 좌표로 둔 채 폭만 늘렸으면 하단 잘림 또는 텍스트 상단 정렬 어긋남 ❌. ([[1. 블로그/썸네일/1. 디자인 가이드/1-1. 스타일]] §3 하단 슬롯 y 공식 · [[1-2-1. 레이아웃 규칙]] §2.2-4).
- 📌 4-6안 총량·유형 다중 룰은 → **⓪-①** 참조 (중복 방지).

### ☐ ⑨ 캡처 이미지 비율 보존 — 모자/콘텐츠 stretch ❌ (2026-06-12 추가)
**과거 사고** (2026-06-12 AIC 올인컴플리트): 풀페이지 캡처(750×8090, aspect 10.79)를 mockup screen(aspect 2.21)에 `imageTransform: [[1,0,0],[0,1,ty]]` (y-scale=1)로 fill → 모자 grid가 **가로로 늘어남**. y-scale=0.205로 수정 후 정상.

- **체크 1 — 시각 확인**: mockup 안 콘텐츠가 가로/세로로 **stretch·압축**돼 보이지 않나? (인물 얼굴 가로 늘어남, 모자 가로 폭 비정상, 텍스트 가로 압축 등)
- **체크 2 — 매트릭스 검증**: `imageTransform = [[1, 0, 0], [0, yScale, ty]]` 형식인가? **`yScale = slot_aspect / image_aspect`** 공식 따르나? 단순 `[[1,0,0],[0,1,ty]]` (y-scale=1) ❌
- **체크 3 — 데코 영향 없음**: sparkle·crown 데코 instance의 PNG가 정상 표시? mockup만 노린 매트릭스가 데코까지 잡아 비율 깨졌으면 ❌
- **체크 4 — 자동 측정 코드**:
  ```js
  const imgSize = await figma.getImageByHash(hash).getSizeAsync();
  const yScale = (screen.height / screen.width) / (imgSize.height / imgSize.width);
  ```
