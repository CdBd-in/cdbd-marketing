## 1. 입력 분석 (타이틀 + 내용)

### 1a. 입력 원본

**타이틀**: `PDF·플립북 카탈로그의 한계 — 진짜 모바일 카탈로그로 바꾸는 법`

**내용**:
1. 모바일 카탈로그란, PDF를 변환한 문서가 아니라 모바일 화면을 기준으로 구성된 제품 카탈로그 페이지를 말한다.
2. PDF·플립북 카탈로그의 한계 3가지: 모바일에서 확대·축소해야 읽힘 / 수정하려면 다시 변환·재업로드 / 단순 변환만으로는 문의·영상 동선을 넣기 어려움.
3. 모바일 카탈로그에 진짜 필요한 것: 모바일 화면 기준 구성·발행 후 수정·문의로 이어지는 동선·열람 데이터.
4. CdBd 모바일 카탈로그가 1:1로 해결: 카탈로그가 변환된 PDF가 아니라 제품 상세·영상·문의가 담긴 모바일 페이지가 됨.

## 5. 발견·수정 사항 (사고 기록)

### 사고 #1 — TITLE 어절 중간 wrap (해결)

**증상**: 6안 모두 TITLE "진짜 모바일 카탈로그로\n바꾸는 법"이 width 285(D/A) / 266(C)에서 자동 wrap → "진짜 모바일 카탈로 / 그로 / 바꾸는 법" **3줄로 강제 분리**. "그**로**"가 어절 중간에 잘림 ⛔ — 자동화 체크리스트 §텍스트 절대원칙 ② 위반.

**원인**: 강조어 "진짜 모바일 카탈로그"(10자) 한 줄 fit 요구 + 첫 줄 "진짜 모바일 카탈로그로"(11자) 폰트 size 36 한글 폭 약 30px/char → 약 330px 필요. width 285에 9자만 fit.

**해결**: D/A TITLE width **350**으로 확장 + TEXT_BLOCK width도 350으로 동시 확장. C TITLE width **460**으로 확장 (SUBTITLE 460 확장과 함께). characters 재set + setRangeFills 보라 재적용 + 하단 변형은 TEXT_BLOCK y 재계산 (450 - 40 - tb.height).

**룰 갱신 후보**:
- [[1-1-4. 검수 체크리스트]] §자주 놓치는: "강조어 길이 사전 측정 — N자 × 30px ≤ TITLE width인지 빌드 전 검사" 추가
- 자동화 코드: **강조어 width 검사 함수** — `if (emphasis.length * 30 > titleWidth) titleWidth = Math.max(titleWidth, emphasis.length * 32)`. C는 460까지 확장 OK, D/A는 슬롯 mockup 위치 충돌 검사 필요.

### 사고 #2 — A3·A4 TITLE 우측 "로" 글자가 mockup과 미세 overlap (사용자 검수 항목)

**증상**: A3·A4 TITLE width 350 + 좌측 margin 40 = right edge 390. mockup x=366 → **24px overlap**. TITLE 마지막 글자 "로"가 mockup 좌측 edge에 살짝 겹침 — 가독성에 큰 문제 없으나 시각적 정합성 미세 어긋남.

**원인**: 강조어 길이가 슬롯 디폴트 width를 초과 → width 확장으로 mockup 영역 침범.

**현재 결정**: 그대로 두고 사용자 검수에서 결정. 옵션:
- A) 그대로 유지 (mockup 좌측 빈 영역에 살짝 침범, 시각 OK)
- B) TITLE fontSize 36 → 32 축소 + width 326 (mockup x=366 - 40 = 326) → mockup 침범 0
- C) mockup x 366 → 400 우측 이동 + sparkle 같이 이동 → 텍스트 width 350 유지

**룰 갱신 후보**:
