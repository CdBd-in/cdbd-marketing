## 1. 라우팅 — 파트 메시지 → 목적 1개 ⭐

> 입력: **본문 파트 1개 + "이 자리에 어떤 이미지가 필요한가"** → 출력: **목적 1개 + 크기 1개**

**Step 1 — 목적 결정 (위→아래, 먼저 맞는 것)**

1. 파트가 **"기존 vs CdBd" · "전 vs 후" · "비용/절감"** 을 말함 → **③ 비교**
2. 파트가 **"1→2→3 순서" · "사용법" · "플로우" · "이렇게 만든다"** → **⑤ 프로세스**
3. 파트가 **여러 항목(유형·조건·카테고리·카드구성)을 동등하게 나열** → **④ 나열**
4. 파트가 **특정 버튼·기능·데이터 한 곳을 콕 집어 설명**(확대·마킹 필요) → **② 강조**
5. 그 외 — **결과 화면/페이지를 그냥 보여주기**(사례·대표·소개) → **① 기본**

**Step 2 — 크기 결정**

| 문맥 신호 | 크기 |
|---|---|
| 글의 메인 시각 / 섹션 도입 / 비교·프로세스 핵심 | **1920×1200 (가로)** |
| 본문 흐름 중간 포인트·짧은 보조·정사각 삽입 | **1000×1000 (정사각)** |

> 📌 같은 파트에 같은 목적 2장+ → 자산 차별화([[1-2-3. 검수 체크리스트]]): 3D 오브젝트는 다른 아이콘, 목업은 다른 페이지/카탈로그. "같은 이미지 또 나왔네" ❌.
> 📌 이미지가 불필요한 파트(FAQ·짧은 CTA·단순 도입)는 **건너뛴다**.

## 2. 신규 템플릿 = 단일 제작 출처 ⭐

- **clone 소스 = 「템플릿」 섹션** `383:5681` 안의 각 목적 프레임. `clone()` → 출력 페이지(`1:20182`)에 붙이고 → **교체 대상 레이어만** 바꾼다.
- ⚠️ **신규 템플릿은 "예시 완성형"** — 의미론적 슬롯명(`SCREEN_1`·`EMPHASIS_SLOT`)이 아니라 **일반 레이어명**(스크린샷 rect `이미지/스크린샷…`, 3D 아이콘 instance, 텍스트 노드)을 쓴다. → **레이어 타입+위치로 식별**(이름 `findOne` 의존 ❌).
- 교체 대상 3종:
  | 종류 | 식별 | 교체 방법 |
  |---|---|---|
  | **화면(스크린샷)** | 폰/데스크탑/카드 안의 `rounded-rectangle`(이미지 fill) | 캡처 IMAGE fill 교체 ([[1-2-2-2. 이미지 제작 가이드]] §2) |
  | **3D 오브젝트** | `instance`(자산 라이브러리 Problem·Expensive·Templates·3d Icons) | thiings 아이콘 swap/IMAGE ([[1-2-2-2. 이미지 제작 가이드]] §4) |
  | **텍스트** | `text` 노드(라벨 pill·타이틀·특징) | `loadFontAsync`(Pretendard) 후 `characters` 교체 ([[1-2-2-3. 텍스트 작성 가이드]]) |
- **고정(건드리지 않음)**: 폰·노트북 베젤, 화살표·커넥터 vector, 마킹 박스 스트록·데코 → clone 시 함께 상속. (배경 색상은 아래 5옵션 중 택1 — 나머지는 유지)

> 🎨 **배경 색상 — 5가지 중 1개 선택** (2026-07-02, 소스 `536:4153`(회색·퍼플·그린 3안) · `383:6048` · `383:5699`)

> | 1 | 회색(기본) | `#EFF0F0` (Gray-50) | 중립 기본 — 대부분의 목적에 |

rect.fills = [{ type:'IMAGE', imageHash:HASH, scaleMode:'FILL', imageTransform:[[1,0,0],[0,1,0]] }];

## 4. 출력 페이지 배치 규칙 ⭐

> 출력 페이지 **`💻 AI 블로그 이미지 제작`(`1:20182`)**. **한 글 = 가로 한 줄, x만 STEP씩 증가**.

### 4.0. 🔴 글마다 Figma **Section**으로 묶기 — Section 이름 = 글 제목 (2026-07-22 사용자 지시)

> **한 글의 본문 이미지 프레임들은 반드시 하나의 Figma Section 안에 넣는다. Section 이름 = 블로그 본문 타이틀(글 제목).**
> - 📌 예시: Section `773:4592` **"사진·파일 말고 링크 한 줄로 보내는 모바일 명함"** 안에 그 글의 hero·body01~05·process_usage 이미지가 전부 들어가 있음.
> - Section 안에서 이미지는 **가로 한 줄 + 100px 패딩**(만든 순서 = 좌→우 = 파트 순서). Section은 내용에 맞게 크기(예 11710×1400).
> - 코드: 프레임 생성/clone 후 `const sec = figma.createSection(); sec.name = '<글 제목>';` → 각 프레임 `sec.appendChild(f)` + 아래 STEP 좌표로 나열. **새 글마다 새 Section.**
> - 장점: 한 글의 모든 이미지를 함께 찾고·이동·관리. (구 방식 = 페이지에 프레임만 흩어 놓기 ❌)

| 상수 | 값 | 뜻 |
|---|---|---|
| `ORIGIN_X` | `0` | 줄 시작 x |
| `STEP_X` | `2100` | 셀 폭 (1920 + 여백 180, 정사각도 같은 셀) |
| `STEP_Y` | `1500` | 셀 높이 (1200 + 여백 300) |

```js
const page = await figma.getNodeByIdAsync('1:20182');
const ORIGIN_X = 0, STEP_X = 2100, STEP_Y = 1500;
const bottom = Math.max(0, ...page.children.map(c => c.y + c.height));
const baseY = Math.ceil((bottom + 300) / STEP_Y) * STEP_Y;
newFrames.forEach((f, i) => { f.x = ORIGIN_X + i * STEP_X; f.y = baseY; }); // 만든 순서 = 좌→우 = 파트 순서
```
- 기존 산재 작업물(`x=-3417`~, `y=-397`~)은 건드리지 않는다. 새 글만 위 규칙으로 줄 세움.
