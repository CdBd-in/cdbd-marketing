# 주제 → 이미지 세트 결정 (자동화 1단계)

> **자동화의 최상위 라우팅 계층.** 본문 한 단락이 아니라 **글 전체**를 먼저 읽고 "이 글은 어떤 주제인가 → 이미지를 몇 장, 어떤 **목적**으로, 어디에 배치할 것인가"를 결정한다.
> 각 이미지의 **목적 유형·템플릿 노드**는 [[1-2-3-0. 개요 · 라우팅 · 노드 인덱스]]에서, **기초 토큰**은 [[1-2-2. 스타일]], **자산·캡처**는 [[1-2-4. 이미지 규칙]], **카피**는 [[1-2-5. 카피 규칙 (라벨·캡션 텍스트)]]에서 결정.
> 🔁 **2026-06-30 재편**: 구 "레이아웃 유형 A~G / 외부·실사 L~R" 축 폐기 → **5개 목적 분류(① 기본 · ② 강조 · ③ 비교 · ④ 나열 · ⑤ 프로세스)**.

> 📊 **근거**: 블로그 15페이지 / 게시물 약 90개 / 이미지 390장 직접 분석. (결론은 본 가이드에 모두 반영)

---

## 0. 왜 주제가 먼저인가

390장을 분석해 보니 **글의 "주제"가 이미지 세트를 거의 결정**한다. 단락별로 유형을 고르기 전에, 글 전체 주제를 맞히면 **어떤 목적을 몇 장 쓸지**가 80% 정해진다.
→ **주제 분류 정확도 = 자동화율.** 이 문서가 자동화의 첫 관문이다.

핵심: 사례·소트리더십·라운드업 글은 **CdBd 화면이 아닌 것**(실사진·경쟁사 캡처)을 많이 쓴다 → 자동 합성 불가, **소싱/캡처 트랙**으로 분기(§4).

## 1. 주제 분류기 — 제목·본문 신호 → 주제 1개

> 입력: **글 제목 + 도입부 + 소제목 목록** → 출력: **주제 1개** (+ 시리즈 여부)

| 주제 | 판별 신호 (제목/내용) | 예시 글 |
| --- | --- | --- |
| **① 사례 (case_study)** | "~사례", 특정 브랜드명, "후기", "인터뷰", "비하인드" | 인하대 졸업패션쇼 · 올인컴플리트 · 귤메달 팝업 |
| **② 가이드 (guide_howto)** | "만들기", "5분", "방법", "가이드", "~하는 법", "셀프 제작" | 기업 행사 초대장 5분 · 모바일 명함 만들기 |
| **③ 비교 (comparison)** | "vs", "대안", "한계", "왜 안 되나", "차이", "그만 쓸까" | 이벤터스 대안 · PDF·플립북 한계 · 구글폼 한계 |
| **④ 비용/ROI (cost_roi)** | "ROI", "절감", "비용", "원", "무료 vs 유료", "단가" | 50인 명함 ROI · 모바일 명함 도입 ROI |
| **⑤ 소트리더십 (thought_lead)** | 외부 브랜드 분석(레드불·넷플릭스·성심당), "전략", "인사이트", "GEO" | 레드불 · 넷플릭스 하우스 · 성심당 |
| **⑥ 기능 출시 (feature_launch)** | "출시", "업데이트", "NEW", "소개", "기능", "레이어 추가" | 상품 카드 출시 · 룩북 템플릿 소개 |
| **⑦ 프로필링크 (profile_link)** | "프로필 링크", "링크인바이오", "링크트리", "미니 홈페이지" | 비즈니스 프로필링크 · 인스타 미니홈페이지 |
| **⑧ 라운드업 (roundup)** | "추천 N가지", "Best N", "툴 N가지", "사이트 N곳" | AI툴 5가지 · 무료 이미지 Best 18 |
| **(수식) 시리즈 (series)** | 제목에 "시리즈 #N", "(시리즈 #N: ...)" | 디지털 카탈로그 #1~6 · 명함 시리즈 |

**분류 규칙**
- 한 글은 **주제 1개** (가장 강한 신호). 애매하면 우선순위: 사례 > 비교 > 비용 > 라운드업 > 가이드 > 기능출시 > 프로필링크 > 소트리더십.
- **시리즈는 수식어** — 본문 세트는 위 주제를 따르되, **커버(썸네일)에 "시리즈 #N" 라벨** ([[1. 블로그/1-1. 썸네일]] 영역).

## 1.1. 분류 기준 (결정론적 규칙) ⭐

> 같은 글이면 누가 돌려도 **같은 주제**가 나오도록 점수·오버라이드·동점 규칙을 고정한다.

### 1단계 — 신호 점수 계산
각 주제의 신호어(§1)가 등장하면 **위치별 가중치**로 합산: 제목 ×3 / 소제목(H2·H3) ×2 / 본문 ×1. → 최고점 주제 채택.

### 2단계 — 하드 오버라이드 (점수보다 우선, 위→아래 먼저 맞는 것)
1. 제목이 **외부 브랜드 전략 분석**(CdBd 고객 아님) → **소트리더십**
2. 제목에 **"사례 / 후기 / 비하인드"** 또는 `「브랜드」의 「행사/제품」` → **사례**
3. 제목에 **"추천 / Best N / N가지 / N곳 / 비교 N"**(열거형) → **라운드업**
4. 제목에 **숫자+"% / 원 / ROI / 절감 / 단가 / 무료 vs 유료"** → **비용/ROI**
5. 제목에 **"vs / 대안 / 한계 / 왜 안 / 차이 / 그만"** → **비교**
6. 제목에 **"출시 / 업데이트 / NEW / 소개 / 기능"** → **기능 출시**
7. 제목에 **"만들기 / N분 / 가이드 / ~하는 법 / 방법 / 셀프"** → **가이드**
8. 제목에 **"프로필 링크 / 링크트리 / 링크인바이오 / 미니 홈페이지 / 멀티링크"** → **프로필링크**

> 오버라이드 충돌 시 **번호 작은 것 우선**. (예: "프로필링크 추천 3" → 3번(라운드업) 우선)

### 3단계 — 동점/무신호
1·2단계로 안 갈리면 §1 동점 우선순위. 어떤 신호도 없으면 기본값 **가이드**.

### 4단계 — 시리즈 플래그 (주제와 독립)
제목에 **"시리즈 #N"** → `series=true`. 주제는 그대로, 커버에 시리즈 라벨.

> **출력 형식**: `{ genre, series:bool, scores:{...}, applied_override:번호|null }`

## 2. 주제 → 목적 세트 (핵심 매핑) ⭐

> 출력: 글 1편에 들어갈 **목적 시퀀스**. (목적 = ① 기본 · ② 강조 · ③ 비교 · ④ 나열 · ⑤ 프로세스 / 상세 [[1-2-3-0. 개요 · 라우팅 · 노드 인덱스]])
> 장당 평균 2~9장. 도입 1장(기본 히어로) → 본문 파트별.

| 주제 | 표준 목적 세트 | 주력 목적 | 비고 |
|---|---|---|---|
| **① 사례** | 기본(결과 히어로) → **실사진 다수** → 비교(전후) | 실사진(소싱) | 실사진이 핵심 → 합성 불가, 촬영/수집 |
| **② 가이드** | 기본(소개) → **프로세스·강조(에디터 사용법)** → 나열 | **프로세스·강조** | CdBd 화면 합성으로 커버 ✅ |
| **③ 비교** | **비교(Before/After)** → 강조(해결 화면) | **비교** | 비교가 글의 뼈대 |
| **④ 비용/ROI** | **비교(비용 저울)** → 기본 → 강조(통계) | **비교(#비용)** | 큰 숫자·저울·돈자루 |
| **⑤ 소트리더십** | **실사진** + 나열(개념도) + 외부캡처 | 실사진·나열 | CdBd 목업 거의 없음 |
| **⑥ 기능 출시** | 강조(기능 UI) + 프로세스(사용법) + 기본(결과) | **강조·프로세스** | NEW 옐로 배지 |
| **⑦ 프로필링크** | 기본 → **강조·프로세스(에디터)** → 비교(폼 vs CdBd) → 외부캡처(경쟁사) | **강조·비교** | 경쟁사 캡처 빈출 |
| **⑧ 라운드업** | **외부 캡처(항목당 1장)** + 나열(가격/콜라주) | 외부캡처 | 거의 전부 캡처. 합성 X |
| (공통) | **커버 1장** = 썸네일 (타이틀 박힘) | — | [[1. 블로그/1-1. 썸네일]] 영역 |

> ⚠️ **②·⑥·⑦의 일부만** 신규 템플릿 clone으로 자동 합성. **①·⑤·⑧은 캡처/촬영 비중이 높음** → 사람·스크래퍼 개입(§4).

## 2.1. 주제별 정밀 플랜 ⭐ (결정론적)

> 주제가 정해지면 **이미지 플랜(순서·목적·크기·개수·필수여부)**이 자동으로 나온다.
> 표기: `목적(크기)×개수 [필수|선택]` — 크기 `L`=1920×1200, `S`=1000×1000.

| 주제 | ① 도입/훅 | ② 본문 핵심 | ③ 보조 | ④ 마무리 |
|---|---|---|---|---|
| **① 사례** | `기본(L)×1 [필수]` 결과 히어로 | `실사진×2~4 [필수]` 현장 | `비교(L)×0~1 [선택]` 전후 | — |
| **② 가이드** | `기본(L)×1 [필수]` | `프로세스(L)·강조(L/S)×본문 [필수]` 에디터 how-to | `나열(L)×0~1 [선택]` | — |
| **③ 비교** | `비교(L)×1~2 [필수]` Before/After | `강조(L/S)×0~3 [선택]` 해결 화면 | — | — |
| **④ 비용/ROI** | `비교(L)×1 [필수]` 비용 저울 | `기본(L)×1 [선택]` 결과물 + `강조(L)×0~2 [선택]` 통계 | — | — |
| **⑤ 소트리더십** | `실사진×1 [필수]` | `나열(L)×0~2 [선택]` 개념도 | `외부캡처×0~2 [선택]` | — |
| **⑥ 기능 출시** | `기본(L)×1 [필수]`(NEW) | `강조(L/S)×2~4 [필수]` 기능 UI | `프로세스(L)×0~1 [선택]` | `기본(L)×0~1 [선택]` |
| **⑦ 프로필링크** | `기본(L)×1 [필수]` | `강조·프로세스(L/S)×2~5 [필수]` 에디터 | `비교(L)×0~1 [선택]` 폼 vs CdBd | `외부캡처×0~2 [선택]` |
| **⑧ 라운드업** | `외부캡처×항목 [필수]` | `나열(L)×0~1 [선택]` 가격/콜라주 | — | `기본(L)×0~1 [선택]` CdBd 소개 |

**플랜 적용 규칙**
1. **①은 항상 1장**(도입 히어로/훅).
2. **②(본문 핵심)는 필수** — 그 주제의 정체성.
3. **③·④는 선택** — 본문에 해당 파트가 실제로 있을 때만.
4. **개수 상한**: 총 9장 권장. 초과 시 ②를 우선 유지하고 ③·④부터 줄임.
5. **트랙 주의**: ①사례 실사진·⑤⑦⑧ 외부캡처는 합성 불가 → §4 캡처/소싱 큐로.

## 2.2. 이미지 빌드 플랜 (최종 출력) ⭐ — 글 → 자동 결정

> 🔑 **이미지는 "파트(divider 선)별"로 배치한다 — 가장 중요한 원칙.**
> CdBd 블로그 글은 **선(divider)으로 파트(보통 H2 섹션)가 나뉜다.** 주제 일반론으로 N장을 찍는 게 아니라, **각 파트를 읽고 "이 파트를 이해시키는 이미지 1장"**의 목적을 정한다.
> - 절차: ① 본문을 divider로 파트 분할 → ② 각 파트 핵심 메시지 1줄 → ③ 그 메시지에 맞는 **목적 1개**([[1-2-3-0. 개요 · 라우팅 · 노드 인덱스]] §1 라우팅) → ④ 빌드 플랜.
> - **파트와 무관한 이미지는 만들지 않는다.** 이미지가 불필요한 파트(FAQ·짧은 CTA)는 **건너뛴다**.
> - 주제 플랜(§2.1)은 **후보 풀**일 뿐 — 실제 선택은 파트 내용이 결정.
> - 🔴 **같은 목적 2장+ 쓰면 자산 차별화** — 3D 오브젝트는 다른 아이콘, 목업은 다른 페이지/카탈로그. ([[1-2-6. 검수 체크리스트]])

### 파트 메시지 → 목적 → 템플릿 (자동 결정)

| 파트가 말하는 것 | 목적 | 대표 템플릿 노드 | 트랙 |
|---|---|---|---|
| 결과 페이지/사례를 그냥 보여줌 | **① 기본** | 3단 `347:2809` · 모바일+데스크탑 `358:2034` | 합성 |
| 특정 버튼·기능·데이터를 콕 집어 설명 | **② 강조** | 버튼 강조 `347:2957` · 개인화 데이터 `363:1541` | 합성 |
| 기존 vs CdBd / 비용 대비 | **③ 비교** | 키워드 하단 `367:2459` · 비용 저울 `371:2246` | 합성 |
| 유형·조건·카테고리·카드구성 나열 | **④ 나열** | 카테고라이징 `347:3473` · 그리드 `347:3547` | 합성 |
| 사용법·플로우(1→2→3, 트리) | **⑤ 프로세스** | 사용법 `347:3268` · 개인화 URL 트리 `347:4251` | 합성 |
| 현장 실사진 | (실사진) | — | 소싱 |
| 경쟁사·외부툴·인스타 캡처 | (외부캡처) | — | 캡처 |

- **viewer 슬러그 결정**: 본문 키워드 → [[1-2-4. 이미지 규칙]] §2 카탈로그(17 슬러그). 매칭 없으면 fallback(seminar/personalized/rsvp/oak_table…).
- **에디터 컴포넌트 결정**: [[1-2-4. 이미지 규칙]] §1 키워드표.

### 출력 스키마 (per 이미지)
```json
{
  "order": 1,
  "section": "도입부",
  "purpose": "기본",
  "size": "1920x1200",
  "templateNodeId": "347:2809",
  "captureSource": { "kind": "viewer", "ref": "invitation/seminar", "sections": 3 },
  "replace": { "screens": ["sec:hero","sec:rsvp","sec:contact"], "texts": [], "icons": [] },
  "track": "composite"
}
```
→ 글 1편 = 이 객체의 배열. **합성(composite)**은 곧장 fill 파이프라인, **캡처/소싱**은 사람·스크래퍼 큐로 분기(§4).

## 3. 배치 순서 (글 내 위치)

```
[커버/썸네일]  ← 글 대표 (썸네일 폴더)
   │
[도입부]       ← ① 기본 (결과 히어로) 또는 주제별 대표 1장
   │
[본문 파트 1..N] ← 파트 메시지마다 1장:
   │   · "이렇게 하세요/사용법"  → ⑤ 프로세스 · ② 강조
   │   · "기존 vs CdBd / 비용"   → ③ 비교
   │   · "유형/조건/카드구성"     → ④ 나열
   │   · "결과/사례를 보여줌"     → ① 기본
   │   · "현장/경쟁사"           → 실사진(소싱)/외부캡처
   │
[마무리/CTA]   ← ① 기본(결과) 또는 ③ 비교(비용 절감)
```

- **빈도**: 가이드·비교·비용 글은 본문 이미지가 많음(4~9장). 소트리더십·라운드업은 외부 캡처 위주.
