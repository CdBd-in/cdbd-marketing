# 목표와 비전

## 목표

디자이너가 아닌 사람도 블로그 이미지를 손쉽게 만들 수 있도록, **Claude에 내용을 던져주면 Figma에 자동으로 이미지를 생성**하는 워크플로우를 구축한다.

## 비전

- **누구나 디자이너처럼**: 디자인 지식이 없어도 블로그 게시물 내용을 입력하면 완성도 있는 블로그 이미지가 나온다.
- **Claude → Figma 자동화**: 사용자가 Claude에게 블로그 내용(제목, 본문, 키워드 등)을 전달하면, Claude가 Figma MCP를 통해 자동으로 이미지를 생성한다.
- **일관된 브랜드 톤**: 자동 생성이지만 CDBD 브랜드 가이드와 일관된 스타일을 유지한다.

## 핵심 원칙

1. **입력 최소화**: 사용자는 "내용"만 던지면 된다. 레이아웃, 색상, 폰트 등은 Claude가 가이드에 따라 자동 결정.
2. **Figma 네이티브 결과물**: 결과물은 편집 가능한 Figma 파일로 산출되어, 필요 시 미세 조정이 가능하다.
3. **재현 가능성**: 같은 내용이면 같은 품질의 결과가 일관되게 나와야 한다.
4. **순서대로 꼼꼼히 (절차 준수)** 🔴: 모든 블로그 이미지는 **아래 자동화 파이프라인 순서(①캡션 추출 → ②빌드 플랜 → ③트랙 분기 → ④자산 확보 → ⑤Figma 합성 → ⑥검수)를 건너뛰지 않고 단계별로 꼼꼼히** 밟아 만든다. 단계를 생략하거나 짐작으로 만들지 않고, 마지막 ⑥검수([[1-2-3. 검수 체크리스트]])를 통과하기 전엔 사용자에게 보여주지 않는다.
5. **이미지만 봐도 이해된다 (자기설명성)** 🔴: **CdBd를 전혀 모르는 사람이 블로그 글의 이미지만 보고도 무엇을 말하는지 알 수 있어야 한다.** 이미지는 글의 장식이 아니라 **그 파트를 시각적으로 이해시키는 설명**이다.
   - 각 이미지는 담당 파트(divider)의 메시지를 한눈에 전달 — 무관한 화면·일반 컴포넌트 삽입 ❌.
   - 맥락이 필요하면 **컨텍스트 라벨**(무엇을 보여주는지 5~12자)로 보완하되, 이미지 자체로 명확하면 생략.
   - 제품 화면(목업·에디터·통계)도 **"이 화면이 왜 여기 있는지"**가 직관적으로 읽혀야 한다 (비교=좌/우 대비, QR 배포=폰+QR, 통계=핵심 수치 강조).
   - 전문 용어·내부 명칭에 기대지 말고, **일반 독자 눈높이에서 "보면 안다"** 가 되도록 구성.
6. **텍스트는 읽는 즉시 이해된다 (카피 규칙 준수)** 🔴: 이미지에 텍스트(라벨·서브라인·특징·캡처·수치)를 넣을 때는 **[[1-2-4. 텍스트 작성 가이드]]를 최대한 지킨다.** 목표는 **구독자가 그 텍스트를 읽는 순간 무슨 뜻인지 바로 아는 것**.
   - **함축**: 명사형 압축("가격 실시간 수정")·구체어("페이지뷰·CTR 데이터")·기호(`·` `/` `→` `vs`)·숫자(`0원`·`5분`)로 짧게.
   - **어미**: 라벨은 **명사형 종결 + 마침표 없음**, 특징은 동사 명사화("수정 가능"·"데이터 수집"), 문장체(`~합니다/~해요`)·광고체·CTA ❌.
   - **일관**: 본문(특히 캡션)이 실제로 쓰는 용어와 같은 말을 쓴다. 비교는 좌/우 대칭.
   - ⑦검수에서 **카피 항목까지 통과**해야 사용자 제시.

## 사용자 시나리오

> "이번 블로그 글 '모바일 명함이 주목받는 이유'에 들어갈 본문 이미지 만들어줘"
> 
> → Claude가 본문 핵심 키워드와 메시지를 추출
> → 디자인 가이드(레이아웃·스타일·이미지 규칙)에 맞춰 Figma에 자동 생성
> → 사용자는 완성된 Figma 링크를 받음

## 자동화 파이프라인 (글 1편 → 이미지 N장) ⭐ 2026-06-23 갱신

> **본문에 이미지 자리마다 `*캡션*` 마커가 박힌 블로그 글**을 받아 이미지 세트를 만드는 실제 흐름. (`*…*` 줄 = 이미지 위치 + 내용.) **글을 장르로 분류하거나 몇 장 찍을지 추론하지 않는다 — 캡션이 위치·개수·내용을 이미 정한다.** Claude는 캡션마다 목적·템플릿·트랙만 결정한다.
> ⚙️ **실행 방식**: 아직 전용 자동화 코드는 없고, **이 가이드 문서 + Figma MCP(`use_figma`) + 캡처 스크립트(`자동화 도구/cdbd-capture/`)** 를 Claude가 단계별로 수행한다. (600×450 썸네일 플러그인은 별개)
> 🧱 **현 유형 체계 = 5개 목적 분류 (2026-06-30 재편)**: **① 기본 · ② 강조 · ③ 비교 · ④ 나열 · ⑤ 프로세스** (각 크기 가로 L / 정사각 S). 구 레이아웃 유형 축은 폐기 — 상세 → [[1-2-1-1. 공통]].
> 🆕 **빌드 모델 = 신규 템플릿 clone·자산교체**: 「템플릿」 섹션 `377:5848`의 목적별 프레임을 복제해 **화면(스크린샷 rect)·3D 오브젝트·텍스트 레이어만 교체**(폰 베젤·BG·그리드·화살표·데코 보존). **기존 v1·v2 노드(`15:xx`·`165:23`·`167:xx`·`173:xx`)는 폐지 — 신규 `377:5848`이 유일 제작 출처.**

```
[블로그 글 (본문에 *캡션* 마커 포함)]
   │
 ① 캡션 추출        → 본문의 *…* 자리 = 이미지 위치·개수·내용 확정
   │
 ② 빌드 플랜        (1-3 §5)   → 캡션별 사양: 목적·크기(가로/정사각)·템플릿노드·캡처source·교체레이어
   │
 ③ 트랙 분기        (1-3 §6)
   ├─ 합성(기본·강조·비교·나열·프로세스) ─┐   ← 신규 템플릿 clone
   ├─ 캡처(외부 화면) ──────────────┤→ ④ 자산 확보 → ⑤ Figma 합성(자산 교체) → ⑥ 검수·전달
   └─ 소싱(실사진) ────────────────┘
```

### ① 캡션 추출 — "어디에 어떤 이미지가 필요한가"
- 본문을 훑어 `*…*` 줄(이미지 자리 마커)을 **순서대로 추출** → **이미지 위치·개수가 그대로 확정**된다. (글을 장르로 분류하지 않는다.)
- 각 캡션 = 그 자리에 들어갈 이미지의 **내용·메시지**. 캡션 1개 = 이미지 1장.
- 출력: `[{ order, section, caption }]` — 캡션 없는 자리엔 이미지를 만들지 않는다.

### ② 빌드 플랜 — "각 캡션의 fill 직전 사양"
- 캡션 메시지를 읽어 **목적 1개**([[1-2-1-1. 공통]] §1 라우팅)·크기·템플릿·캡처source·트랙을 결정.
- 각 이미지 = `{ 목적, 크기, templateNodeId, captureSource, replace(screens/texts/icons), track }` JSON.
- 목적은 **5분류(기본·강조·비교·나열·프로세스)** 중 선택, 크기는 **가로 1920×1200 / 정사각 1000×1000**.
- 캡처 대상까지 자동 결정: viewer 슬러그(키워드→1-3 §2) / 에디터 컴포넌트(키워드→1-3 §1) / 외부 URL / 3D 자산.
- **참조**: [[1-2-3. 이미지 제작 가이드]] §5 (캡션→목적·템플릿·트랙 매핑 + 출력 스키마)

### ③ 트랙 분기 — 3갈래

> 🔑 **② 빌드 플랜 vs ③ 트랙 분기 — 헷갈리지 말 것**
> - **② 빌드 플랜 = "무엇을 만들까"** — 이미지별 설계도(유형·크기·내용·라벨)를 적은 **주문서**.
> - **③ 트랙 분기 = "그걸 어떻게 만들까"** — 그 주문서의 각 이미지를 **제작 방법(합성/캡처/소싱)으로 분배**하는 신호등.
> - 식당 비유: ②는 *주문서*("스테이크·샐러드·디저트"), ③은 *주방 분배*("스테이크→그릴, 샐러드→콜드, 디저트→제과"). ②가 먼저, ③이 그걸 라인별로 줄 세움.

- **합성**(기본·강조·비교·나열·프로세스): 신규 템플릿 clone → 화면/3D/텍스트 레이어 교체. — [[1-2-1-1. 공통]]
- **캡처**: 외부 화면 Playwright 캡처(사람 승인). **소싱**: 실사진 아카이브에서 선택. (둘 다 자동 합성 불가)
- **참조**: [[1-2-3. 이미지 제작 가이드]] §6

### ④ 자산 확보 — 픽셀 소스 마련
> ⚠️ CdBd 이미지는 **본문 텍스트를 그리지 않는다** — 실제 제품 화면(viewer·에디터·통계)을 보여준다. 본문은 "어떤 화면 + 라벨"을 정할 뿐.
- **viewer 캡처**: `자동화 도구/cdbd-capture/capture-seminar-3sections.mjs <viewer-url> <prefix>` → 3 의미섹션(hero/RSVP/contact). **공개 페이지라 로그인 불필요.** (유효 invitation viewer: seminar·personalized·rsvp / 일부 슬러그는 빈 렌더)
- **에디터 화면**: `에디터 캡처본/` 라이브러리(에디터·카드·통계·답변…) 또는 Playwright 로그인 캡처.
- **컴포넌트**: `페이지 통계`(`159:6406`, 단일 통합)·`질문과 답변`(`1:11480`) 등 인스턴스.
- **업로드 → imageHash**: `upload_assets`(count=N) → 단일사용 URL에 `curl -F "file=@cap.png"` POST → `imageHash` 확보. ⚠️ **`nodeId` 직접 배치는 fill 안 됨** — 해시만 받아 ⑥에서 대입.
- **참조**: [[1-2-3. 이미지 제작 가이드]] §1~§4

### ⑥ Figma 합성 (use_figma) — 신규 템플릿 clone
- **목적별 템플릿 clone**: 「템플릿」 섹션 `377:5848`에서 해당 목적 노드 clone([[1-2-1-1. 공통]] §3 노드 인덱스) → 출력 페이지 **`💻 AI 블로그 이미지 제작`(`1:20182`)** 에 append. **배치 = [[1-2-1-1. 공통]] §4** — 한 글 = 가로 한 줄, **x만 `STEP_X=2100`씩 증가** / 새 글은 아래 줄(`STEP_Y=1500`).
- 🆕 **교체 대상 레이어만**: 화면(스크린샷 `rounded-rectangle`)·3D 오브젝트(instance)·텍스트. **폰/노트북 베젤·화살표·커넥터·BG·그리드·마킹 박스 데코는 건들지 않음** ← clone으로 상속. (신규 템플릿은 의미론적 슬롯명이 아니라 일반 레이어명 → **타입+위치로 식별**)
- **fill ① — 화면(스크린샷 `rounded-rectangle`)**: viewer/에디터 캡처를 IMAGE fill로 교체(`scaleMode:'FILL'`, identity transform). 캡처 aspect = 슬롯 aspect(폰 0.464)면 왜곡 0. 같은 종류 다중이면 **위치(y,x)순**으로 개별 식별.
- **fill ② — 3D 오브젝트(instance)**: 자산 라이브러리(Problem `377:3936`·Expensive `377:4011`·Templates `377:4999`·3d Icons `377:5070`)에서 항목 의미에 맞게 swap/IMAGE. 비교 좌측·비용 무거운 쪽은 무채색.
- **fill ③ — 에디터/모달 컴포넌트**: DS 인스턴스(`createInstance`)를 강조/프로세스 콘텐츠 영역에 배치. 통계는 핵심지표 확대 강조.
- **텍스트(라벨 pill·타이틀·특징)**: `loadFontAsync`(Pretendard) 후 `characters` 교체. 컨텍스트(5~12자) 없으면 해당 텍스트/pill `remove()`. 🔴 **문구는 [[1-2-4. 텍스트 작성 가이드]] 준수** — 명사형 종결·마침표 없음·함축·구체어.
- **참조**: [[1-2-1-1. 공통]] §2 (fill 2-스텝) + 목적별 슬롯 [[1-2-1-2. 기본]]~[[1-2-1-6. 프로세스]]

### ⑦ 검수·전달
- **사용자에게 보여주기 전 [[1-2-3. 검수 체크리스트]] 전 항목 통과** (A 캡처의도 ~ H 최종게이트). `get_screenshot`으로 실제 렌더를 눈으로 확인.
- 핵심: 캡처 의도(초점)·중앙정렬·텍스트 무결성(`rescale` 주의)·수치=본문 일치·더미데이터·점선/임시프레임 정리.
- **카피 게이트**: 모든 텍스트가 [[1-2-4. 텍스트 작성 가이드]] §5를 통과 — 명사형 종결·마침표 없음·문장체/광고체 없음·구체어·비교 대칭. **구독자가 읽고 바로 이해**되지 않으면 다시 쓴다.
- 결과 노드 링크 전달 + (필요시) vault 저장. manual 조정은 디자인 가이드 갱신 로그로 피드백.
