## 🔴 사고 빈발 TOP 6 — 먼저 확인 (실제 사고 재발 방지)

> 이 6개에서 사고가 가장 많이 났다. **여기부터 점검.**

> 🔴🔴 **0. (절대 최우선) 캡처 의미 적합성 — 사람이 이 이미지만 보고 블로그 내용을 이해하는가**
> 캡처할 **페이지/영역을 템플릿·이미지 분석으로 의도적으로 선택**했는지부터 확인. "아무 페이지나/스크롤 아무 데나" ❌ → **"이 메시지를 가장 잘 설명하는 화면"** 을 골라 캡처.
> - [ ] **카탈로그 = 표지(cover) 캡처** — 브랜드명·컬렉션 타이틀이 보여 "모바일 카탈로그"임이 한눈에. **상품 상세 페이지 캡처 ❌**(그냥 제품 사진으로 읽혀 의미 전달 실패).
> - [ ] **여러 목업은 표지로 통일** (목업마다 제각각 상품 페이지 ❌).
> - [ ] 글을 모르는 사람이 이 이미지만 보고 **"무엇을 말하는지" 즉시 이해**되는가.
> - 📌 사례: 2026-06-23 TCO 환경 — 상품 상세(p3) 캡처 → 표지로 교체.

1. [ ] **상단 로고/헤더 잘림 ❌** — 풀페이지(y=0부터) 캡처 + 화면비 **FILL**. "화보만 확대"로 로고 사라지면 실패.
2. [ ] **통계/대시보드 단순 캡처 ❌** — 핵심 지표 카드를 **확대·팝업(강조 마킹)**해 시선 유도. (안 하면 뭐가 핵심인지 안 보임) ※ 통계는 **② 강조** 유형([[1-2-1-3. 강조]]) — 핵심지표 확대 강조 필수.
   - 🔴 **상단 설명 라벨(퍼플 pill) 기본 ON** — 강조 화면은 "이 화면에서 무슨 일이 일어나는지" **한 줄 설명 pill**을 단다. 텍스트만 교체(Pretendard Bold / pill `#6C4CFF` / HUG 후 가로중앙). 화면이 완전 자명할 때만 생략.
   - 🔴 **페이지명 헤더 크롭 제외** — 캡처에 "◯◯ 통계 확인하기" 같은 **특정 페이지 이름이 노출되면 ❌** (글 주제와 안 맞아 보임). **통계 요약 영역만** 크롭해 토픽 무관하게.
   - 🔴 **강조 = 글이 강조한 지표** — 본문이 강조하는 데이터(예 "어떤 세트가 가장 많이 클릭" → 링크별 클릭 요약)를 파악해 **그 지표를 강조 영역에** 넣음. 아무 지표나 강조 ❌.
   - 🔴 **통계는 로그인 캡처 대신 벡터 컴포넌트 사용** — **`페이지 통계` 컴포넌트(`159:6406`)** 인스턴스 → 필요 섹션(통계요약 / 링크별 클릭 / 제출 답변 / 예약·구독 현황) **크롭** → **데이터를 글에 맞게 편집**(기본값 0/placeholder). 벡터라 무한 선명·빨간박스 없음·헤더(페이지명) 크롭으로 제외. (구 캡처 방식 폐기 — 흐림·페이지명·빨간박스 문제) → **그대로 넣지 말 것**: 의미 영역 크롭 후 **그 안에서 1위 데이터를 스포트라이트 카드로 중첩 강조**(인쇄 vs 모바일이면 "어떤 세트가 1위" = 인쇄가 못 하는 측정). 레퍼런스 `233:63` · 상세 §3.4 모드②.
     - 폰트 주의: 숫자가 `Indivisible`(미설치)이면 `loadFontAsync` 실패 → **Pretendard로 폴백** 후 편집.
     - 🔴 **스포트라이트 콜아웃 내부 = 오토레이아웃 (손배치 ❌)** — 크기 다른 텍스트(라벨·수치·항목·보조)를 y좌표로 손배치하면 정렬·간격이 어긋남(2026-06-24 사고). **가로 AL 2열(간격 80) → 각 열 세로 AL(간격 20·CENTER)**: 좌열=라벨pill+항목명 / 우열=수치+보조. (상세 [[1-2-1-3. 강조]])
3. [ ] **`rescale()` ❌** — 컴포넌트는 **원본 크기 배치**. (rescale이 컴포넌트 텍스트/숫자 파손)
4. [ ] **콘텐츠 점유율 ≥ 55%** (빈 공간 ≤ 45%) — 모든 시각 요소를 감싸는 **bounding box 면적 ÷ 캔버스 면적 ≥ 0.55**. 또한 **상단·하단 단일 여백 각 ≤ 25%**.
   - **미달 시 (= 너무 휑함)**: 본문을 **재분석**해 보강안 결정 — ① 전후 대비(예 "재인쇄 100%"(취소선)→↓→"0원") · ② 보조 수치/요소 추가 · ③ **1000×1000(Square) 전환**.
   - 🔴 **수정 전 사용자 확인 필수** — 점유율 미달로 이미지를 고쳐야 하면, **"여백 N% / 점유 M% → 이렇게 보강하겠다(또는 1000×1000 전환)"** 를 먼저 보고하고 **사용자 승인 후 수정**. 임의 보강 ❌.
5. [ ] **aspect = 슬롯 aspect** — 다르면 FILL이 핵심을 crop. identity `imageTransform` + 정확한 비율.
6. [ ] **`upload_assets` nodeId 직접배치 ❌** — 해시 받아 `use_figma`로 fill. (nodeId 배치는 fill 안 됨)

## ✅ 기본 검수 (빠르게 훑기)

**의도·내용**
- [ ] 이미지가 **해당 divider 파트와 직접 관련** (무관한 파트에 억지 삽입 ❌)
- [ ] 전달 메시지 1줄 + **그 영역만** 캡처 (풀 에디터 덤프 ❌)
- [ ] 멀티 화면(기본 3폰 · **비교 우측 폰** · 나열 4폰 · 프로세스 스텝)은 **같은 캡처 복붙 ❌** — **서로 다른 viewer** 또는 **같은 viewer의 다른 페이지/섹션**을 각 화면에 넣음
- [ ] **소재 일치**: "모바일 카탈로그"를 보여줄 땐 **카탈로그 viewer**(oak_table·newarrival·lookbook 등) 캡처 — 초대장·예약 viewer로 대체 ❌
- [ ] 🔴 **한 게시글에 같은 목적 2장+ → 서로 다른 자산** (장끼리 동일 이미지 ❌) — 3D 오브젝트는 다른 아이콘(예 paper booklet↔book), 목업은 다른 카탈로그 또는 다른 페이지. 같은 글에서 똑같아 보이는 2장 금지
- [ ] **③ 비교**: 좌=비교대상(부정)·우=우리 제품(긍정) / **좌측 자산 채도 다운(무채색, `filters.saturation=-1`)** · 우측 컬러 유지
- [ ] 라벨 ↔ 콘텐츠 일치 / 빈 화면(lazy-load 실패) 아님
- [ ] 수치가 본문과 모순 ❌ / 더미 데이터(실명·실로고 ❌) / 오타 없음

**배치·무결성**
- [ ] 중앙 정렬 (**상하도** — `y=(H-h)/2`)
- [ ] z-order: 캡처(화면 rect)가 폰 베젤 위
- [ ] 이미지 왜곡(늘어짐) 없음
- [ ] 한글 안 깨짐 (Pretendard 로드 후 작성) / 컴포넌트 숫자 살아있음

**라벨·카피** (상세 → [[1-2-2-3. 텍스트 작성 가이드]])
- [ ] 라벨 **필요할 때만** (① 기본은 보통 없음 / ② 강조·③ 비교·⑤ 프로세스는 라벨·pill 사용) / 컨텍스트 5~12자 / 자연스럽지 않으면 `remove()`
- [ ] 카피 = **명사형 종결·마침표 없음** / 문장체·광고체·CTA ❌ / 추상어→구체어 / 비교 좌우 대칭 / 본문 용어와 일관
- [ ] 🔴 **함축 과다 금지 — 보면 이해되게** (사용자 반복 강조 / [[1-2-2-1. 목표와 비전]] §5 자기설명성): 단어 1개로 너무 줄이지 말 것. **일반 독자가 이미지만 보고 뜻을 아는** 구체 어구로.
  - 예: `설계` ❌ → **`페이지 구조 설계`** ✅ · `입력` ❌ → **`박스·가격 입력`** ✅ · `배포` ❌ → **`QR·링크 배포`** ✅ · `데이터` ❌ → **`클릭 데이터 확인`** ✅
  - 판별: 그 라벨만 보고 **"무슨 설계? 무슨 입력?"** 이 떠오르면 너무 줄인 것 → 목적어·맥락을 넣어 다시. (⑤ 프로세스 스텝 라벨·② 강조 카드·③ 비교 라벨 모두 해당)
