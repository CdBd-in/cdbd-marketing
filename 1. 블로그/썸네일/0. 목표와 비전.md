# 🌟 목표 & 비전 — 블로그 썸네일 자동 생성

## 한 문장으로

## 🧩 How — 3개 기둥

```
                  🌟 타이틀 → 자동 썸네일
                          │
   ┌──────────────────────┼────────────────────┐
   │                      │                    │
 [디자인 가이드]        [자동 캡처 인프라]      [Figma MCP]
 규칙 + 소재집            최신 자료 수집          제작 엔진
"어떻게 + 무엇을"         Playwright            생성 엔진
```

> **디자인 가이드**가 "어떻게 그릴까(규칙)"와 "무엇을 넣을까(소재집)"를 모두 포함.
> 소재집은 이미지 규칙이 정의한 슬롯에 넣을 실제 자산을 결정하므로 디자인 가이드 하위(`1-3. 이미지`)에 속함.

| 기둥 | 역할 | 위치 | 현재 상태 |
|------|------|------|----------|
| **디자인 가이드** | 어떻게 그릴까(규칙) + 무엇을 넣을까(소재집) | `1. 디자인 가이드/` — [[1. 블로그/썸네일/1. 디자인 가이드/1-1. 스타일]] · [[1-2-1. 레이아웃 규칙]] · [[1-2-2. 레이아웃별 레퍼런스 노드]] · [[1-3. 이미지 규칙]] | 🟢 성숙 |
| **자동 캡처 인프라** | 최신 콘텐츠 자동 수집 (로그인 필요 화면 포함) | `자동화 도구/cdbd-capture/` | 🟡 구축됨 |
| **Figma MCP** | 실제 제작 엔진 (공식 목업 + 규칙 적용) | CdBd 블로그 템플릿 파일 | 🟢 검증됨 |

## ⚙️ 파이프라인 (타이틀+본문 → 썸네일)

> **순서 원리 — 다중 유형 비교 (2026-06-19 갱신)**: 타이틀+본문 1쌍 → **본문 구조 분석으로 이미지 유형 2-3개 격상** → **각 유형별 2안 = 총 4-6안 자동 제작** → 사용자 선택. 단일 유형 결정이 아니라 **유형 자체부터 비교 + 변형 매트릭스**. 본문은 유형 격상·자산 매칭·강조어 결정의 핵심 근거.

1. **입력 (intake)** — 사용자가 "블로그 썸네일을 만들거야" / "썸네일 만들어줘"로 시작하면 Claude가 입력을 먼저 요청 (스킬 `blog-thumbnail` 트리거):
   > 썸네일 만들 정보를 알려주세요.
   > - **타이틀 (필수)**: 블로그 제목 원문 — em dash·쉼표·콜론·시리즈 마커 그대로
   > - **본문 (필수)**: 본문 전체 또는 본문 요지 — 정의 박스 📌, 한 사이클 흐름, 대비 구조가 보이도록 충분히. 짧은 요약보다 본문 풀 텍스트가 §0 ③ 본문 구조 분석에 유리.
   
   서브타이틀은 타이틀 안 마커(`-` · `/` · `,` · em dash · 시리즈 명) 또는 별도 필드 — [[1. 블로그/썸네일/1. 디자인 가이드/1-1. 스타일#서브타이틀 판단 기준 — 입력 타이틀 분석 (2026-06-12 추가)|서브타이틀 판단 기준]] 적용.
   강조 키워드·강조색·레이아웃·이미지는 이후 단계에서 Claude가 **본문 구조 분석** 기반으로 자동 결정 (사용자 지정 시 우선) — [[2. 자동화 체크리스트]] §0 입력 분석 5단계.
2. **이미지 유형 2-3개 결정** — 타이틀+본문에서 [[1-2-1. 레이아웃 규칙]] §1.1 신호어 매칭 + 본문 구조 분석(정의 박스→D 격상 / 한 사이클→C 격상 / 대비 구조→C 멀티 격상)으로 **1·2순위 유형 필수 + 3순위 유형 선택**. 신호어 폭 좁으면 2개·넓으면 3개.
3. **자산 후보 추출** — 각 유형별 1a 기능·1b 산업·1d 톤 다층 분석 → 1순위 자산 후보 → [[1-3. 이미지 규칙]] §1 Step 2. (A·B·D·C는 유형별 1자산, 자산 변형 없이 위치 변형으로 2안 / E는 자산 변형으로 2안)
4. **자산 수집** — Microlink 캡처 / Thiings 다운로드 / Playwright (유형별)
5. **N안 자동 제작** — **각 유형별 2안 × 유형 2-3개 = 4-6안** 자동 생성:
   - **A·B·D 유형 (위치 변형 가능)**: 상단·서브 + 하단·서브 = 2안
   - **C 유형 (상단 고정)**: 다른 자산 조합 2안
   - **E 유형 (중앙 고정)**: 다른 자산 2안
   - 각 안: 슬롯 clone → 타이틀 의미 단위 줄 나누기·강조색([[1. 블로그/썸네일/1. 디자인 가이드/1-1. 스타일]]) + 이미지 슬롯에 의미 영역 크롭 fill + DECO 톤 매칭 (자동화 #7)
6. **검수·선택** (휴먼) — 4-6안 중 1개 선택 → home.cdbd.in/blog 발행. 유형 자체부터 비교해서 콘텐츠에 가장 맞는 시각 선택 가능.

> 2단계에서 유형 2-3개가 정해지면 → 4단계에서 각 유형별 자산 + 위치 변형 → 5단계에서 슬롯의 정해진 자리에 텍스트·이미지를 채운다.
> 위치 기준: 슬롯 템플릿([[1-2-1. 레이아웃 규칙]] §2) — 주 이미지는 슬롯이 자동 정의 / 보조 이미지(`DECO`)는 슬롯 박힌 placeholder 활용.

## 🤔 왜 지금은 플러그인 안 쓰고 Claude(use_figma) 직접 모드인가? (2026-06-12 신규)

> 이 섹션은 **"지금 이 시점에 왜 use_figma인가"** 의 시점 분석.

### 짧은 답

**가이드가 한참 진화 중이고, 플러그인 코드(`code.js`)가 새 규칙을 아직 못 따라가서.**

2026-06-12 하루에만 가이드 **8건 갱신**:
- mockup ID `1:1368` → `338:3224` ([[1-3. 이미지 규칙]])
- C 유형 Microlink viewport 정책 ([[1-3. 이미지 규칙]])
- DECO 75×75 + 위치(503.5, 58.5) + sparkle 화이트리스트 (sparkle2/3/4) ([[1-2-1. 레이아웃 규칙]] §2.4)
- SUBTITLE 정책 — A·B·D·E 모두 **width 285 / 1줄** ([[2. 자동화 체크리스트]] #4)
- A 슬롯 VISUAL_SLOT 좌표 통일 (x365.5/y86/192×404.35)
- A 상단·서브 슬롯에 DECO placeholder 박힘 (`338:3136`)
- em dash 서브타이틀 분리 마커 ([[1. 블로그/썸네일/1. 디자인 가이드/1-1. 스타일]] §2)

→ 플러그인을 쓰면 위 갱신 모두 **이전 룰**로 적용됨. 가이드와 결과가 어긋남.

### 비교 표 (2026-06-12 시험 실측 기반)

| 항목 | 플러그인 | Claude 직접 (use_figma) |
|------|---------|------------------------|
| 사용자 액션 | **버튼 1클릭** | 자동 — 입력만 |
| 호출 수 | 사용자 1번 | use_figma 3-6번 + upload_assets |
| 시간 (4안) | ~35-55초 | ~90-200초 |
| 토큰 | ~550 | 1,600-3,000 |
| 정확도 | **100%** (구현 그대로) | 70-95% (Claude 추론 의존) |
| 트랜잭션 | atomic | 안별 독립 — 중간 실패 시 부분 잔존 |
| 재실행 | 버튼 1번 | 호출 시퀀스 재현 필요 |
| 새 룰 반영 | `code.js` 수정 필요 | **가이드 읽고 즉시 적용** ⭐ |
| C 유형 지원 | ❌ (멀티 슬롯 미구현) | ✅ |

### 지금 시점에 use_figma 직접이 맞는 이유

### 안정화 후 플러그인 회귀 시점

다음 조건이 모두 갖춰지면 **플러그인으로 회귀**:

1. ✅ 가이드 변경 빈도 ↓ (한 달에 0-1회)
2. ✅ A·B·C·D·E 슬롯 룰 안정
3. ✅ DECO·SUBTITLE 룰 안정
4. ✅ `code.js`에 누적 새 룰 반영 + C 유형 함수 추가
5. ✅ 반복 제작 (주 5건+) 시작

→ 이후엔 플러그인 = 누적 비용 절감 우위.
