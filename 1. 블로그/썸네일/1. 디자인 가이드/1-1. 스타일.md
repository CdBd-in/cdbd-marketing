## 2. 컬러 시스템

### 배경색
| 역할 | HEX | 설명 |
|------|-----|------|
| **Primary BG** | `#141414` | 모든 썸네일 공통 배경 (피그마 실측값) |

### 텍스트 색상
| 역할 | HEX | 사용 위치 |
|------|-----|-----------|
| **타이틀** | `#FFFFFF` | 메인 제목 전체 기본값 |
| **강조어 Purple** | `#8F80FF` | **타이틀 강조 문구 인라인** (서브 유무 무관, 항상) |
| **서브타이틀 Green** | `#4DE98B` | **서브타이틀 전체** (서브가 있을 때만) |

### 강조색 사용 원칙 (2026-05-31 단순화)
- **타이틀 강조어 = 항상 Purple `#8F80FF`** (서브타이틀 유무와 무관)
- **서브타이틀 = 항상 Green `#4DE98B`** (있을 때 전체)
- 한 썸네일에 **강조 영역은 1개** — 단, 강조 영역 안의 내용은 **의미 단위**로 잡음 (1단어일 수도, 한 구(phrase)일 수도). 영역이 2개로 나뉘면 ❌ (시각 균형·임팩트 분산). 서브 있을 때도 동일.

### 서브타이틀 판단 기준 — 입력 타이틀 분석 (2026-06-12 추가)

> 입력으로 받은 타이틀 안에 서브타이틀이 섞여 있을 수 있다. **의미 추론이 아닌 마커 기반**으로 분리한다.

**마커 규칙 — 다음 중 하나라도 있으면 서브타이틀로 분류**

| 마커 | 서브타이틀 범위 | 예시 |
|------|----------------|------|
| **시리즈 명** ("시리즈", "Part N", "에피소드", "#N" 등) | **시리즈 라벨 전체** (시리즈 명을 포함한 앞 구간 전부) | `CdBd 프로필 링크 시리즈 #6` → 서브: "CdBd 프로필 링크 시리즈 #6" |
| **`-` (하이픈)** | **`-` 이전 텍스트 전체** | `프로필 링크 - 모바일 페이지 빌더 CdBd` → 서브: "프로필 링크" / 타이틀: "모바일 페이지 빌더 CdBd" |
| **`/` (슬래시)** | **`/` 이전 텍스트 전체** | `도입 멘트 / 본문 타이틀` → 서브: "도입 멘트" / 타이틀: "본문 타이틀" |

**판단 절차**
1. 입력 타이틀에서 마커 탐색 — 시리즈 명 · `-` · `/`
2. 마커 발견 → **마커(또는 마커 이전) 텍스트**를 서브타이틀로 분리, 나머지는 메인 타이틀
3. 마커 없음 → 서브타이틀 없음 (단독 글, `1:1262` 슬롯 사용)

**렌더링 — 별도 SUBTITLE 노드 사용**
- 서브타이틀은 항상 **별도 SUBTITLE 노드**에 들어간다 (인라인 그린 처리 ❌)
- 타이포: Pretendard Medium **24px** / 그린 `#4DE98B`
- 슬롯 선택: 서브 있음 → `1:1294` (배경·중앙·서브) / 없음 → `1:1262` (배경·중앙) — [[1-2-1. 레이아웃 규칙]] §2 베리에이션 규칙

**원문 보존**
- 마커(`-` · `/`) 자체는 분리 후 **제거** (서브/타이틀 각각의 텍스트에서 빠짐). 그 외 글자·구두점은 그대로 보존.
- 시리즈 명 라벨은 그대로 SUBTITLE 노드에 들어감 (`#6` 등 포함).

## 3. 타이포그래피

### 폰트 사양
| 역할 | 폰트 | 웨이트 | 크기 | 행간 | 색상 |
|------|------|--------|------|------|------|
| **타이틀** | Pretendard | Bold | 36px | 1.3 | `#FFFFFF` (+ 인라인 강조색) |
| **서브타이틀** | Pretendard | Medium | 24px | 1.3 | `#4DE98B` |

### 텍스트 작성 규칙

> 프롬프트에는 줄바꿈 없는 타이틀 한 문장만 들어온다. **강조 키워드와 줄 나누기는 Claude가 직접 결정**한다.
> **순서**: 강조 키워드 결정 → 줄 나누기 (강조어가 줄 끝에서 쪼개지지 않게)

**강조 키워드 선택 원칙** (2026-06-12 재정립)

> 🔴 **1차 원칙 — 사람이 읽는 것처럼 의미 단위로 선정**
>
> 타이틀을 사람이 처음 읽었을 때 **"이 글이 알리고 싶은 핵심 메시지"라고 직관적으로 느껴지는 부분**을 강조 영역으로 잡는다.
> 단어 1개일 수도, **여러 단어로 이뤄진 한 구(phrase)일 수도** 있다 — 단어 수가 아니라 **의미 단위**가 기준.

- **강조 영역**: **1개** (시각 균형) — 영역이 2개로 갈라지면 ❌
- **그 1개 영역의 내용**: **의미 단위 1개** — 단어 수 제한 ❌
  - 한 단어: "RSVP", "끝내기", "대신"
  - 여러 단어로 된 의미 단위: "**5분에 만드는 법**", "**CdBd 모바일 명함**", "**진짜 이유**", "**갈아타는 이유**"
- **길이**: 한 줄에 통째로 들어가야 함 (Bold 36px 한글 기준 약 12–14자 / 14자 초과 시 [[1-2-1. 레이아웃 규칙]] §3.4 검토)

**의미 단위 판단 기준**

> 사람이 직관적으로 안 잡히면 다음 4가지 질문을 순서대로:

1. **"이 글이 알리고 싶은 게 뭐야?"** — 한 마디로 줄였을 때 남는 부분
2. **그 부분이 "체언+용언" 또는 "수식어+명사"처럼 의미가 통째로 묶이는가** — 묶이면 통째로 강조 (예: "**5분에 만드는 법**"은 [수단:5분]+[행위:만드는 법] 통째 = 1 의미 단위)
3. **광범위 추상어**("좋은", "최고의", "제대로") **단독은 피함** — 임팩트 약함
4. **조사·연결어로 끝나면 거기까지 포함**할지 직관 판단 — 의미가 끝나는 자연 경계로 (예: "갈아타는" 보다 "**갈아타는 이유**"가 자연)

**참고 — 자주 등장하는 강조 유형** (선정 시 약한 안내, 절대 룰 ❌)

| 유형 | 예시 | 비고 |
|------|------|------|
| **제품·기능명** | "CdBd 모바일 명함", "RSVP", "프로필 링크", "예약 관리", "비공개 초대장" | CdBd 마케팅 본질. 명백하면 우선. |
| **가치 제안 (행위·결과)** | "**5분에 만드는 법**", "끝내기", "사로잡는", "해결", "기능 업데이트" | 글의 약속이 강조어 후보 |
| **차별점·비교** | "대신", "갈아타는 이유", "안전하고", "예쁘게", "무료로" | "왜 이걸 써야 하나" 메시지 |
| **핵심 개념** | "디지털 카탈로그", "진짜 이유", "Best N" | 타이틀의 주제어 |

> ⚠️ **위 4유형은 순위가 아님** — "사람 직관 1차" 원칙이 우선. 직관이 명백하게 가치 제안을 가리키면(예: "5분에 만드는 법") 제품명보다 가치 제안을 잡는다.

**예시 적용** (의미 단위로 — 단어 수 무관)

| 타이틀 | 강조 영역 (선정) | 의미 단위 근거 |
|--------|------------------|-------------|
| **자사몰 상품 큐레이션 카탈로그를 5분에 만드는 법** | **"5분에 만드는 법"** (7자, 4어절) | 글의 약속·핵심 가치 제안. 사람이 읽으면 "5분에 만든다"가 임팩트 |
| 행사 RSVP, 엑셀 입력 말고 모바일 초대장으로 끝내세요 | **"RSVP"** (4자, 1단어) | 글이 알리는 기능 자체 |
| 전화 핑퐁 모바일 초대장으로 끝내기 | **"끝내기"** (3자, 1단어) | "전화 핑퐁을 끝낸다"가 약속 |
| 홈페이지 대신 프로필 링크로 갈아타야 하는 이유 | **"갈아타야 하는 이유"** (9자, 3어절) — *또는* "**대신**" | 비교형 가치 제안. 둘 다 가능, 사람 판단 |
| 전 세계 파트너를 사로잡는 CdBd 모바일 명함 | **"CdBd 모바일 명함"** (9자, 3어절) | 제품명. "사로잡는"이 임팩트면 그것도 가능 |
| 기업이 비공개 초대장을 고집하는 7가지 이유 | **"비공개 초대장"** (7자, 2어절) | 글의 주제어 |

> ⛔ **하지 말 것**
> - 의미 단위를 두 영역으로 쪼개기 ("**5분**에 만드는 **법**" ❌ — 영역 2개)
> - 단어 수가 적다는 이유로 의미 단위를 잘라내기 ("5분에 **만드는**" ❌ — "만드는 법"이 자연스러운 의미 단위)
> - 영역 안에 조사만 또는 광범위 추상어만 ("**의**", "**제대로**") ❌

**줄 나누기 원칙**
- **의미 단위(어절·구문)로 끊는다** — 한 줄이 그 자체로 읽히는 완결된 구가 되도록. 명사구·조사를 줄 끝에서 어색하게 자르지 않는다.
- **강조 키워드는 한 줄 안에** 통째로 둔다 (줄바꿈으로 쪼개지 않음).
- **각 줄 길이를 비슷하게** 맞춰 시각적 균형을 잡는다.
- 한 줄은 한글 기준 **대략 10~12자 이내** (Bold 36px Pretendard / TEXT 노드 가로 폭 ≤ 350px).
- 줄 수는 **타이틀 길이가 결정** — 위 조건을 지키면서 끊을 수 있는 **가장 적은 줄 수**를 택한다 (보통 2~4줄).
- 서브타이틀(시리즈명 등)은 줄 수에 포함하지 않는다.
- **C 멀티 목업 (`1:1287`) — SUBTITLE·TITLE 모두 hug(자동 폭), 한 행(1줄)** ⭐ — SUBTITLE은 한 행(1줄) hug / TITLE도 한 행(1줄) hug (의미 단위). 폭은 텍스트 콘텐츠에 맞춰 자동(hug). **mockup_2 y=199와 24px 세로 여유로 가로 hug 폭이 늘어도 시각 충돌 없음**.
  - 단계: ① SUBTITLE 한 행(1줄) hug 시도 → 안 되면 입력 단계 축약 요청. ② TITLE 한 행(1줄) hug 시도 → 안 되면 의미 단위 분리.
  - 사례: ① "디자인·RSVP·룩북을 한 페이지로" → 1줄 ⭕ ② INHA "인하대 졸업패션쇼 모바일 초대장 사례" → 의미 단위 분리.
  - 상세 룰: [[1-2-1. 레이아웃 규칙]] §3.4 / 자동화 분기: [[2. 자동화 체크리스트\|2]] §자주 놓치는 #4.
- **서브타이틀 — 1줄** — `SUBTITLE`은 항상 **1줄**.

  | 유형·슬롯 변형 | TEXT_BLOCK y | mockup 충돌 | 정책 |
  |---------|--------------|----------|------|
  | **A·B·D 상단·서브** (`1:1269` 등) | y=40 | y로 분리되지만 mockup이 큰 단일 덩어리 | **width 285 + 1줄** |
  | **A·B·D 하단·서브** (`1:1246` 등) | y=244 | 세로 겹침 | **width 285 + 1줄** |
  | **C 멀티·상단·서브** (`1:1287`) | y=40 | mockup 3개가 y=199~ 세로 분리 (24px 여유) | **hug(자동 폭), 한 행(1줄)** — SUBTITLE 1줄 + TITLE 1줄. §3.4 |

  의미 단위 분리: 브랜드명·고유명사+수식어구 단위 ("**올인컴플리트** / 첫 플래그십 초대장" ⭕ / "올인컴플리트 첫 / 플래그십 초대장" ❌).
- **원본 텍스트 보존** (2026-06-04 추가) — `\n` **추가만** 허용. 글자·띄어쓰기·구두점(쉼표·마침표·느낌표·물음표) 일체 **추가·삭제·변경 ❌**. 받은 타이틀을 그대로 쪼개기만 한다.

**TEXT 노드 폭 규칙 (자동 줄바꿈 보장)** 🔴 — **유형별로 다름**

| 유형 | TITLE 폭 | SUBTITLE 폭 | 줄 수 정책 | 비고 |
|------|---------|------------|----------|------|
| **A·B·D·E (기본)** | **350px** | **285px** (D 포함 모든 유형 통일) | TITLE 2~4줄 / **SUBTITLE 1줄** | A·B·D·E 모두 TITLE 350·SUBTITLE 285 / 서브타이틀 1줄 |
| **C 멀티·상단 (`1:1257`, 서브 ❌)** | **484px** | — | TITLE **1~2줄** | mockup y=175~ → 텍스트 자유 폭 확보. 강조어 한 줄 안에 통째 |
| **C 멀티·상단·서브 (`1:1287`, 서브 ✅)** | **hug(자동 폭)** | **hug(자동 폭)** | **SUBTITLE 한 행(1줄)** + **TITLE 한 행(1줄)** — 폭은 텍스트 콘텐츠에 맞춰 자동(hug). 1줄 안 들어가면 입력 단계 축약 요청. | 텍스트 y=40~175 (TEXT_BLOCK h=135) / mockup_2 y=199~ **세로 분리** 24px 여유 → 가로 hug 폭이 늘어도 시각 충돌 ❌. |

- 자동화 상수: `TITLE_MAX_WIDTH=350` / `SUBTITLE_MAX_WIDTH=285` / `TITLE_MAX_WIDTH_D=350` / `SUBTITLE_MAX_WIDTH_D=350`
- TEXT 노드의 `textAutoResize`는 **`HEIGHT`** (가로 고정, 세로만 자동 늘어남)
- Plugin 자동화: 노드의 width를 강제 350(또는 D SUBTITLE 350·A·B·C·E SUBTITLE 285)으로 강제 → Figma 자동 줄바꿈은 **fallback** → **줄 나누기 원칙(상단)을 따라 의미 단위로 `\n` 명시**가 우선
- **SUBTITLE도 TITLE과 동일하게 줄 나누기 원칙 적용** — 의미 단위로 끊되, 강조어(서브는 전체가 그린) 시각적 균형 고려
- TITLE 350 ↔ 이미지 영역 위치 관계:
  - A·B·C: VISUAL_SLOT 시작 x=365.5(A, 2026-06-12 조정) / 395(B·C) → TITLE 끝 x=390(=40+350)과 미세 겹침/안전. **y로 분리** (TITLE 상단 y40 / 하단 y는 자동 보정). 시각적 임팩트 확장.
    - A는 x=365.5로 우측 이동 → TITLE 끝(x=390)과 약 24.5px 여유 (이전 x=353에선 겹쳤음)
  - D: VISUAL_SLOT x=300/y=160(상단)/y=31(하단, 2026-06-12 조정 — 이전 50), w·h=260 → TITLE 350 안전.
  - E: 텍스트 중앙 정렬 (배경 위) — 폭 무관.

**하단형 슬롯 y 자동 보정** ⭐ (2026-05-31 추가)
- 하단 슬롯(A `1:1251/1246` · B `1:1304/1314` · D `1:1274/1277`)은 텍스트가 슬롯 하단에 정렬
- 줄 수 바뀌면 height 변화 → 자동화가 `y = 410 - height` 재계산 (TEXT_BOTTOM_Y = 450 - bottom padding 40)
