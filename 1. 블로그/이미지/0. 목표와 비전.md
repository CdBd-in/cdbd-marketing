# 0. 목표와 비전

## 목표

디자이너가 아닌 사람도 블로그 이미지를 손쉽게 만들 수 있도록, **Claude에 내용을 던져주면 Figma에 자동으로 이미지를 생성**하는 워크플로우를 구축한다.

## 비전

- **누구나 디자이너처럼**: 디자인 지식이 없어도 블로그 게시물 내용을 입력하면 완성도 있는 블로그 이미지가 나온다.
- **Claude → Figma 자동화**: 사용자가 Claude에게 블로그 내용(제목, 본문, 키워드 등)을 전달하면, Claude가 Figma MCP를 통해 자동으로 이미지를 생성한다.
- **일관된 브랜드 톤**: 자동 생성이지만 CDBD 브랜드 가이드와 일관된 스타일을 유지한다.

## 핵심 원칙

1. **입력 최소화**: 사용자는 "내용"만 던지면 된다. 레이아웃, 색상, 폰트 등은 Claude가 가이드에 따라 자동 결정.
2. **Figma 네이티브 결과물**: 결과물은 편집 가능한 Figma 파일로 산출되어, 필요 시 미세 조정이 가능하다.
3. **재현 가능성**: 같은 내용이면 같은 품질의 결과가 일관되게 나와야 한다.
4. **순서대로 꼼꼼히 (절차 준수)** 🔴: 모든 블로그 이미지는 **아래 자동화 파이프라인 순서(①주제 분류 → ②세트·플랜 → ③빌드 플랜 → ④트랙 분기 → ⑤자산 확보 → ⑥Figma 합성 → ⑦검수)를 건너뛰지 않고 단계별로 꼼꼼히** 밟아 만든다. 단계를 생략하거나 짐작으로 만들지 않고, 마지막 ⑦검수([[2. 검수 체크리스트]])를 통과하기 전엔 사용자에게 보여주지 않는다.
5. **이미지만 봐도 이해된다 (자기설명성)** 🔴: **CdBd를 전혀 모르는 사람이 블로그 글의 이미지만 보고도 무엇을 말하는지 알 수 있어야 한다.** 이미지는 글의 장식이 아니라 **그 파트를 시각적으로 이해시키는 설명**이다.
   - 각 이미지는 담당 파트(divider)의 메시지를 한눈에 전달 — 무관한 화면·일반 컴포넌트 삽입 ❌.
   - 맥락이 필요하면 **컨텍스트 라벨**(무엇을 보여주는지 5~12자)로 보완하되, 이미지 자체로 명확하면 생략.
   - 제품 화면(목업·에디터·통계)도 **"이 화면이 왜 여기 있는지"**가 직관적으로 읽혀야 한다 (비교=좌/우 대비, QR 배포=폰+QR, 통계=핵심 수치 강조).
   - 전문 용어·내부 명칭에 기대지 말고, **일반 독자 눈높이에서 "보면 안다"** 가 되도록 구성.
6. **텍스트는 읽는 즉시 이해된다 (카피 규칙 준수)** 🔴: 이미지에 텍스트(라벨·서브라인·특징·캡처·수치)를 넣을 때는 **[[1-4. 카피 규칙 (라벨·캡션 텍스트)]]를 최대한 지킨다.** 목표는 **구독자가 그 텍스트를 읽는 순간 무슨 뜻인지 바로 아는 것**.
   - **함축**: 명사형 압축("가격 실시간 수정")·구체어("페이지뷰·CTR 데이터")·기호(`·` `/` `→` `vs`)·숫자(`0원`·`5분`)로 짧게.
   - **어미**: 라벨은 **명사형 종결 + 마침표 없음**, 특징은 동사 명사화("수정 가능"·"데이터 수집"), 문장체(`~합니다/~해요`)·광고체·CTA ❌.
   - **일관**: 본문/주제의 실제 용어([[1-0. 주제]] 빈출 어휘)와 같은 말을 쓴다. 비교는 좌/우 대칭.
   - ⑦검수에서 **카피 항목까지 통과**해야 사용자 제시.

## 사용자 시나리오

> "이번 블로그 글 '모바일 명함이 주목받는 이유'에 들어갈 본문 이미지 만들어줘"
> 
> → Claude가 본문 핵심 키워드와 메시지를 추출
> → 디자인 가이드(레이아웃·스타일·이미지 규칙)에 맞춰 Figma에 자동 생성
> → 사용자는 완성된 Figma 링크를 받음

## 자동화 파이프라인 (글 1편 → 이미지 N장) ⭐ 2026-06-23 갱신

> **블로그 글 전체**를 받아 이미지 세트를 만드는 실제 흐름. (옛 "단락 1개 → 1장" 흐름을 **글 1편 → N장**으로 확장.)
> ⚙️ **실행 방식**: 아직 전용 자동화 코드는 없고, **이 가이드 문서 + Figma MCP(`use_figma`) + 캡처 스크립트(`자동화 도구/cdbd-capture/`)** 를 Claude가 단계별로 수행한다. (600×450 썸네일 플러그인은 별개)
> 🧱 **현 유형 체계 (의도 기준)**: **A 소개·대표 · B 대비 · C 나열·다양성 · D 화면설명 · E 인과 · F 시연 · G 보조강조(sq)** + 정사각 변형(C·D·G). *(I 통계→D 통합, 구 H→G 개명, 외부·실사 L~R 전용 템플릿 폐지)*
> 🆕 **빌드 모델 = v2 자산교체형**: 빈 슬롯을 채우는 대신, **검증된 실제 블로그 디자인을 복제해 `SCREEN`/`ASSET`/`EDITOR_CANVAS` 레이어만 새 자산으로 교체**(베젤·BG·화살표·데코 보존). **v1(빈 슬롯) 템플릿은 폐지·삭제(2026-06-23) — v2 자산교체형이 유일 제작 템플릿.**

```
[블로그 글 (제목+본문)]
   │
 ① 주제 분류        (1-0 §1.1)   → 주제 1개 + 시리즈 플래그
   │
 ② 이미지 세트·플랜  (1-0 §2.1)   → 유형 시퀀스 (①도입~④마무리)
   │
 ③ 빌드 플랜        (1-0 §2.2)   → 이미지별 사양: 유형·크기(가로/정사각)·v2템플릿노드·캡처source·라벨
   │
 ④ 트랙 분기        (1-0 §4)
   ├─ 합성(A~G) ─────┐   ← v2 자산교체형 템플릿 사용
   ├─ 캡처(M) ───────┤→ ⑤ 자산 확보 → ⑥ Figma 합성(자산 교체) → ⑦ 검수·전달
   ├─ 소싱(L) ───────┤
   └─ 자유합성(N·O·R / P·Q) ┘   ← 전용 슬롯 없음(A/C 차용 또는 freeform)
```

### ① 주제 분류 — "이 글은 어떤 종류인가"
- 제목·소제목·본문 신호를 **위치 가중치(제목×3·소제목×2·본문×1)**로 점수화 → **8개 하드 오버라이드** → 동점 우선순위 → **시리즈 플래그**.
- 출력: `{ genre, series, scores, applied_override }` (9개 주제 중 1개)
- **참조**: [[1-0. 주제]] §1.1

### ② 이미지 세트·플랜 — "이미지를 몇 장, 어떤 유형으로"
- 주제 → **①도입 / ②본문핵심 / ③보조 / ④마무리** 4단계 유형 시퀀스 (`유형(크기)×개수[필수/선택]`). 글 1편 ≈ 2~9장.
- 유형은 **합성 코어 A~G** 중 선택, 크기는 **가로 1920×1200 / 정사각 1000×1000**(C·D·G 정사각 변형 있음).
- 🔑 실제 선택은 **파트(divider)별 메시지**가 결정 — 일반론으로 N장 찍지 않고, 이미지 불필요 파트는 건너뜀.
- **참조**: [[1-0. 주제]] §2.1·§2.2

### ③ 빌드 플랜 — "각 이미지의 fill 직전 사양"
- 각 이미지 = `{ 유형, 크기, slotTemplateNodeId, captureSource, slots, label, track }` JSON.
- 캡처 대상까지 자동 결정: viewer 슬러그(키워드→1-3 §4.1) / 에디터 컴포넌트(키워드→1-3 §3) / 외부 URL / 3D 자산.
- **참조**: [[1-0. 주제]] §2.2

### ④ 트랙 분기 — 3갈래

> 🔑 **③ 빌드 플랜 vs ④ 트랙 분기 — 헷갈리지 말 것**
> - **③ 빌드 플랜 = "무엇을 만들까"** — 이미지별 설계도(유형·크기·내용·라벨)를 적은 **주문서**.
> - **④ 트랙 분기 = "그걸 어떻게 만들까"** — 그 주문서의 각 이미지를 **제작 방법(합성/캡처/소싱)으로 분배**하는 신호등.
> - 식당 비유: ③은 *주문서*("스테이크·샐러드·디저트"), ④는 *주방 분배*("스테이크→그릴, 샐러드→콜드, 디저트→제과"). ③이 먼저, ④가 그걸 라인별로 줄 세움.

- **합성**(A~G): v2 자산교체형 템플릿에 viewer/에디터 캡처·컴포넌트 fill. — [[1-2-1. 레이아웃 유형 — 합성 (A~G)]]
- **캡처**(M): 외부 화면 Playwright 캡처(사람 승인) → C틀 또는 단순 배치. **소싱**(L): 실사진 → A/C틀 또는 캔버스 배치.
- **자유합성**(N·O·R / P·Q): 전용 슬롯 없음 — 다이어그램·문제신·수치는 freeform 합성, 가격표·스티커는 필요 시 freeform. (패턴 사전 → [[1. 디자인 가이드/1-2. 레이아웃/1-2-2. 외부·실사 유형 (L~R)]])
- **참조**: [[1-0. 주제]] §4

### ⑤ 자산 확보 — 픽셀 소스 마련
> ⚠️ CdBd 이미지는 **본문 텍스트를 그리지 않는다** — 실제 제품 화면(viewer·에디터·통계)을 보여준다. 본문은 "어떤 화면 + 라벨"을 정할 뿐.
- **viewer 캡처**: `자동화 도구/cdbd-capture/capture-seminar-3sections.mjs <viewer-url> <prefix>` → 3 의미섹션(hero/RSVP/contact). **공개 페이지라 로그인 불필요.** (유효 invitation viewer: seminar·personalized·rsvp / 일부 슬러그는 빈 렌더)
- **에디터 화면**: `에디터 캡처본/` 라이브러리(에디터·카드·통계·답변…) 또는 Playwright 로그인 캡처.
- **컴포넌트**: `페이지 통계`(`1:11483`)·`질문과 답변`(`1:11480`) 등 인스턴스.
- **업로드 → imageHash**: `upload_assets`(count=N) → 단일사용 URL에 `curl -F "file=@cap.png"` POST → `imageHash` 확보. ⚠️ **`nodeId` 직접 배치는 fill 안 됨** — 해시만 받아 ⑥에서 대입.
- **참조**: [[1-3. 이미지 규칙]] §3·§4

### ⑥ Figma 합성 (use_figma) — v2 자산교체형 (우선)
- **v2 우선**: 해당 유형의 **자산교체형 템플릿 clone**(가로 `x=7500` / 정사각 `x=9700` 컬럼; A `165:23`·B `167:23`·C `167:52`·D `167:154`·E `167:279`·F `173:23` / G-sq `173:292`·D-sq `174:23`·C-sq `173:150`) → 출력 페이지 **`💻 AI 블로그 이미지 제작`(`1:20182`)** 에 append.
- 🆕 **교체 대상 레이어만 fill**(`SCREEN_*`·`ASSET_*`·`EDITOR_CANVAS`·`PHOTO/ICON_SLOT` 등). **폰 베젤·화살표·BG·데코·라벨 스타일은 건들지 않음** ← 검증된 완성도 보존. (v2에 없는 특수 케이스 → 가장 가까운 v2 템플릿 차용 또는 freeform 합성. v1 fallback 폐지)
- **fill ① — 화면 슬롯 = `#ffffff` 프레임(`clipsContent=true`)** 🆕 (2026-06-23 사용자 전환 — 구 IMAGE-fill rect 대체) — viewer/시안 캡처를 **프레임 안에 자식으로 넣어** 채운다: `screen.appendChild(captureRect)` → 프레임 크기에 맞춰 resize (자식에 `scaleMode:FILL`). ⛔ **프레임에 직접 IMAGE fill ❌ — 자식 배치 ⭕**. 프레임이 화면 모서리 모양대로 자동 클립 → 캡처·시안 헷갈림·잘림 0. *(아직 rect인 슬롯: D `EDITOR_CANVAS`, E 에디터 `SCREEN_1/2/3/8` — 프레임 전환 전까지 rect에 IMAGE fill 허용)*
- **fill ②** 에디터/통계 캡처 PNG → `EDITOR_CANVAS`/`EDITOR_PANEL` (통계는 `EMPHASIS_SLOT`로 핵심지표 강조)
- **fill ③** 컴포넌트 인스턴스(`createInstance`) → 슬롯 영역 배치
- **라벨·모든 텍스트**: 컨텍스트(5~12자)가 도출되면 `LABEL_PILL`에 **Pretendard SemiBold** 흰 텍스트 + `#6C4CFF` 알약(상단 중앙); 없으면 `remove()`. 🔴 **문구는 [[1-4. 카피 규칙 (라벨·캡션 텍스트)]] 준수** — 명사형 종결·마침표 없음·함축·구체어, 구독자가 읽는 즉시 이해. (라벨뿐 아니라 서브라인·특징·캡션 전부 동일)
- 중복명 슬롯(C의 `SCREEN_*`)은 **위치(y,x)순 정렬**로 개별 fill.
- **참조**: [[1-2-1. 레이아웃 유형 — 합성 (A~G)]] §2 "✅ 캡처 fill 실전 절차"

### ⑦ 검수·전달
- **사용자에게 보여주기 전 [[2. 검수 체크리스트]] 전 항목 통과** (A 캡처의도 ~ H 최종게이트). `get_screenshot`으로 실제 렌더를 눈으로 확인.
- 핵심: 캡처 의도(초점)·중앙정렬·텍스트 무결성(`rescale` 주의)·수치=본문 일치·더미데이터·점선/임시프레임 정리.
- **카피 게이트**: 모든 텍스트가 [[1-4. 카피 규칙 (라벨·캡션 텍스트)]] §5를 통과 — 명사형 종결·마침표 없음·문장체/광고체 없음·구체어·비교 대칭. **구독자가 읽고 바로 이해**되지 않으면 다시 쓴다.
- 결과 노드 링크 전달 + (필요시) vault 저장. manual 조정은 디자인 가이드 갱신 로그로 피드백.
