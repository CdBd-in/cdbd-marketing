# 레이아웃 유형 — 합성 (A~G)

> **이미지 1장 = 출력 크기(1920×1200 · 1000×1000) × 구성 유형(A~G).** 제작은 **v2 자산교체형 템플릿**(§2) clone → `SCREEN`/`ASSET` 레이어만 교체(베젤·BG·데코 보존).
> - **① 합성 유형(CdBd 화면)** = **4유형: 소개 · 설명 · 대비 · 흐름** (정의·구 A~G 매핑은 §0 표) → **이 문서**
> - **② 외부·실사(L~R)** = 실사진·외부캡처·인포그래픽·문제신·가격표·수치 — 전용 슬롯 폐지(A/C 차용·자유합성) → [[1-2-2. 레이아웃 유형 — 외부·실사 (L~R)]]
> ⬆️ 상위: [[1-0. 주제]] · 노드 인덱스 [[1-2-3. 유형별 레퍼런스]] · 토큰 [[1-1. 스타일]] · 카피 [[1-4. 카피 규칙 (라벨·캡션 텍스트)]] · 컴포넌트 [[1-3. 이미지 규칙]]

## 0. 유형 — "요소를 어떤 관계로 보여주나" 4가지 ⭐

> 🎯 **분류 기준 = 요소 간 관계(move) 한 축** — 같은 CdBd 화면이라도 **그냥 보여주나 / 견주나 / 이어주나**로 갈린다. 그 안에서 **소재·개수·크기**로 템플릿을 고른다(형태 변형 — 유형 아님).
> 🧭 **2026-06-24 재정의**: 옛 A~G(템플릿별로 쪼갬)를 **의도 4유형으로 묶음** — C·D·G는 같은 "**설명**"이라 합치고, E·F는 같은 "**흐름**"이라 합침. (노드·코드는 그대로, 묶음만 바뀜)

| 유형     | 관계(move)     | 언제 쓰나                                              | 한 줄 메시지             | 템플릿(형태) · v2 노드                                                                           |
| ------ | ------------ | -------------------------------------------------- | ------------------- | ----------------------------------------------------------------------------------------- |
| **소개** | 대표를 보여줌      | 글 도입/결론, "이 제품·페이지가 이거다"                           | "이게 그 결과물이다"        | 폰3 히어로 `165:23` (구 A)                                                                     |
| **설명** | 화면을 보여주며 알려줌 | "이 화면(들)이 무엇/어떻게" — viewer·에디터·통계·관리               | "이 화면에서 이런 일이 일어난다" | 여러 폰 `167:52`(sq `173:150`) · 풀스크린+강조 `167:154`(sq `174:23`) · 폰+보조카드 `173:292` (구 C·D·G) |
| **대비** | 둘을 견줌        | "기존 vs CdBd" · "전 vs 후" (좌 부정 / 우 긍정, **문제제기=좌측**) | "이쪽이 낫다"            | 좌·우 50:50 `167:23` (구 B)                                                                  |
| **흐름** | 순서·인과로 이음    | "만들면→나온다"(인과) · "1→2→3"(시연)                        | "이렇게 → 이렇게"         | 인과 2단계 `167:279` · 시연 N단계 `173:23`(3)·`237:3459`(4) (구 E·F)                               |

**유형 안에서 템플릿 고르기**
- **설명**: 여러 화면(라인업) → `167:52` / 화면 1개(+핵심 강조) → `167:154` / 폰+보조카드(QR·뱃지, 정사각) → `173:292`.
- **흐름**: 2단계(에디터→결과폰) → `167:279` / 3~4단계 → `173:23`(3)·`237:3459`(4).

### 0.1. 직교 축 (유형 아님) 📐

- **크기**: 가로 **L**(1920×1200) / 정사각 **S**(1000×1000). 정사각 노드: 설명 C-sq `173:150`·D-sq `174:23`·폰+카드 `173:292`.
- **강조(EMPHASIS)**: 핵심 부분 스포트라이트 — **소개·설명·대비·흐름 어디든 붙는 공통 옵션**(특히 통계 화면).

> **구 A~G 매핑**: A→**소개** / C·D·G→**설명** / B→**대비** / E·F→**흐름**.
> **헷갈리면** → §1 Step3 (소개↔설명 · 대비↔수치훅 · 설명 viewer↔admin).
> **L~R**(외부·실사·개념·수치)은 CdBd 화면이 아님 → 별도 군, 소개/설명 틀 차용 또는 자유합성 → [[1-2-2. 레이아웃 유형 — 외부·실사 (L~R)]].

## ⚡ 30초 사용법

이미지 1장을 만들 때 순서:

1. **크기** 정하기 — 메인/도입=가로(L) · 본문중간 보조=정사각(S) → **§1 Step 1**
2. **유형** 정하기 — **소개·설명·대비·흐름 중 1개**(§0) → 그 안에서 소재·개수·크기로 템플릿 픽. (헷갈리면 **§1 Step3**)
3. **유형별 v2 템플릿 clone** — 해당 유형의 **v2 자산교체형 노드**(§0 표 / §3.9)를 출력 페이지(`1:20182`)로:
   A `165:23` · B `167:23` · C `167:52`(sq `173:150`) · D `167:154`(sq `174:23`) · E `167:279` · F `173:23`(3스텝)·`237:3459`(4스텝) · G `173:292`(sq). *(구 v1 빈 슬롯 `15:xx`/`160:xx`은 삭제됨 — 쓰지 말 것)*
4. **교체 레이어만 fill** — `SCREEN`·`ASSET`·`EDITOR_CANVAS`·`STEP_SCREEN`에 캡처/아이콘 IMAGE fill + 텍스트 `characters` 교체. **폰 베젤·BG·화살표·데코는 고정** → §3 유형별 상세 스펙
5. **검수** — [[2. 검수 체크리스트]] 통과 후 제시

## 1. 결정 매트릭스 — 어떤 유형을 쓸 것인가

> ⚠️ **전제**: 이 매트릭스는 [[1-0. 주제]]에서 **글 주제 → 이미지 세트(유형 시퀀스)**가 정해진 뒤, **개별 이미지 1장의 크기·패턴**을 고르는 단계다. 유형이 L~R(외부·실사)로 결정됐다면 본 매트릭스 대신 [[1-2-2. 레이아웃 유형 — 외부·실사 (L~R)]]을 따른다.
>
> 입력: **본문 한 단락 + "이 자리에 어떤 메시지의 이미지가 필요한가"**
> 출력: **출력 크기 1종 + 구성 패턴 1종**

### Step 1 — 출력 크기 결정

| 문맥 신호 | 선택 |
|---------|------|
| 글의 **메인 시각** / 섹션 도입부 / 비교·시연 핵심 | **1920×1200 (Landscape)** |
| 본문 흐름 중간 **포인트 강조** / 모달·디테일 줌인 / 짧은 보조 시각 | **1000×1000 (Square)** |
| 같은 내용을 가로·세로 두 곳에 모두 보여줘야 할 때 | **두 크기 모두 제작** |

### Step 2 — 구성 유형 결정 (본문 메시지 → 유형)

> **먼저 유형군 분기**: 만들 이미지가 **CdBd 화면(목업·에디터·통계)**인가 → **① 합성 4유형(소개·설명·대비·흐름)**. **외부 화면·실사진·개념도·문제신·수치 일러스트**인가 → **② 외부·실사 (L~R)** ([[1-2-2. 레이아웃 유형 — 외부·실사 (L~R)]]). 주제별 유형군은 [[1-0. 주제]] §2.1 플랜이 지정.

→ **4유형(소개·설명·대비·흐름)의 정의·신호·구성·템플릿은 §0 표 참조.**
> ※ **통계**는 별도 유형 아님 → **D(화면설명)** 가 담당(통계 화면일 때 `EMPHASIS_SLOT`로 핵심지표 강조).

### Step 3 — 헷갈릴 때만: 혼동 페어 판별 ⭐

> **유형 선택의 기본 = §0 정의표(의도 → 유형 → 노드).** 대부분 §0 한 줄로 정해진다. 아래는 §0로 안 갈리는 **겹치는 후보**를 가를 때만 본다.
> *(구 "4축 · 결정 절차 · 상황별 빠른 색인"은 §0 정의표와 중복이라 폐지 — 2026-06-24. 유형↔상황 매핑의 단일 출처 = §0 "언제 쓰나" 열.)*

**🔑 혼동 페어 판별 규칙** (가장 헷갈리는 지점)

- **소개 ↔ 설명** — 소개=결과물 **대표 1개**(도입/결론 히어로 폰3) / 설명=본문에서 **화면을 보여주며 알려줌**(여러 폰 or 1개+강조). 도입 대표면 소개, 본문 설명이면 설명.
- **설명: viewer ↔ admin** — 보여줄 게 **모바일 결과화면(viewer) 여러 개** → `167:52`(폰 그리드) / **관리·에디터·통계 화면 1개(+핵심 강조)** → `167:154`.
- **흐름: 인과 ↔ 시연** — 2단계(에디터→결과폰) → `167:279` / 3~4단계(1·2·3) → `173:23`·`237:3459`.
- **대비 ↔ 수치 훅** — 대비=두 **방식/화면**을 좌우 대조(좌우 라벨+자산) / 숫자 **하나**를 크게(0원·N% 절감)=전용 슬롯 없음 → **자유합성**.
- **통계는 "설명 + 강조"** — 통계/대시보드면 **`EMPHASIS_SLOT`로 핵심지표 확대 필수**(단순 캡처 ❌).
- **L(가로) ↔ S(정사각)** — L=도입/섹션 메인·비교/시연 / S=본문 중간 포인트·짧은 보조.

**구 L~R 라우팅** (전용 슬롯 폐지 후)

| 구 유형 | 지금 |
|---|---|
| L 실사진 | 실사진 소싱 → 풀스크린/A틀 차용 |
| M 외부캡처(경쟁사·툴·인스타) | 캡처 → **C틀(나열)** 또는 단순 배치 |
| N 개념도·O 문제신·R 수치 | **자유합성**(다이어그램/메모지+아이콘/큰 숫자) |
| P 가격표·Q 콜라주 | 캡처 또는 freeform |

> 📌 **상황 → 유형 매핑은 §0 "언제 쓰나" 열이 단일 출처** (옛 "상황별 빠른 색인"은 §0와 중복이라 폐지).
> 📌 **역할 분리**: [[1-0. 주제]] §2.1 = 주제별 **후보 풀** / 본 §1 = 개별 이미지 1장의 **최종 픽**. 파트(divider)별 매핑 원칙은 [[1-0. 주제]] §2.2.

### 2.1. 슬롯 운영 규칙 (모든 유형 공통)

**슬롯 종류**
- **`BG_CANVAS`** — 캔버스 컴포넌트 instance(`1:10840` 가로 / `1:10841` 비교 / `1:10838` 라벤더 sq / `1:10839` 화이트 sq). **`locked=true`, 자동화가 건들지 않음.** BG는 **마스터 컴포넌트만 고치면 전 layout 자동 전파**. 그리드 라인은 Figma 표시용(출력 export 제외).
- **`MOCKUP_PHONE_*`** — 폰 프레임 PNG(`36c4ee…`). 건들지 않음.
- **채울 슬롯**(점선 보라 stroke + 회색 fill) — `SCREEN_*` · `EDITOR_*` · `*_ASSET`. 캡처/자산으로 fill.
- **`*_LABEL_PILL`**(점선 pill) — 라벨 자리. **선택**(내용 없으면 `remove()`).

**라벨 규칙**
- 라벨류 슬롯은 **선택적**. 컨텍스트(5~12자)가 자연스럽게 안 나오면 `pill.remove()`. (A = 시각만으로 명확 → 라벨 없음 / **B·C·D·E·F·G = 라벨 사용** — C는 폰별 `SCREEN_LABEL_1~4` 4개를 개별로 채우거나 remove, §3.3)
- 문구는 [[1-4. 카피 규칙 (라벨·캡션 텍스트)]] 준수.

2. **`use_figma`로 대입**:

> 출력 페이지 **`💻 AI 블로그 이미지 제작`(`1:20182`)** 위 위치 규칙. 기존엔 글마다 제각각(컬럼·먼 y)이라 정의가 없었음 → **"한 글 = 가로 한 줄, x만 일정 STEP씩 증가"** 로 고정.

**규칙 (그리드)**
- **한 블로그 글 = 가로 한 줄(row).** 그 글의 이미지들을 **왼쪽 → 오른쪽**으로, **x만 `STEP_X`씩 더해** 나란히 (같은 `y`).
  - `x_i = ORIGIN_X + i × STEP_X` (i = 그 글 안 이미지 순번 0,1,2…) · `y = 그 글의 baseline`
- **새 글 = 아래 새 줄.** `baseline_y += STEP_Y` (글 간 한 칸 내려감).
- **라벨/메모**(시리즈#N 등)는 그 줄 **위**: `y = baseline − 300`, `x = ORIGIN_X`.

**상수** (가로 1920 / 정사각 1000 혼재여도 셀 폭·높이 고정 → 정렬 유지)

| 상수 | 값 | 뜻 |
|------|----|----|
| `ORIGIN_X` | `0` | 줄 시작 x |
| `STEP_X` | **`2100`** | 셀 폭 = 1920 + 여백 180 (정사각도 같은 셀, 셀 안 좌측 정렬) |
| `STEP_Y` | **`1500`** | 셀 높이 = 1200 + 여백 300 |

**적용 코드** (새 글 = 기존 콘텐츠와 안 겹치는 다음 빈 줄에서 시작)
```js
const page = await figma.getNodeByIdAsync('1:20182');
const ORIGIN_X = 0, STEP_X = 2100, STEP_Y = 1500;
// 새 글 baseline = 기존 모든 프레임 아래의 빈 줄(그리드에 스냅)
const bottom = Math.max(0, ...page.children.map(c => c.y + c.height));
const baseY = Math.ceil((bottom + 300) / STEP_Y) * STEP_Y;
// 이 글의 이미지들(newFrames: 만든 순서)을 한 줄에 x만 증가시켜 배치
newFrames.forEach((f, i) => { f.x = ORIGIN_X + i * STEP_X; f.y = baseY; });
// (선택) 라벨: labelNode.x = ORIGIN_X; labelNode.y = baseY - 300;
```

- ⚠️ **기존 산재 작업물**(`x=-3417`~`14000`, `y=-397`~`32000`)은 건드리지 않는다. 새 글만 위 규칙으로 깔끔히 줄 세움.
- 한 글 안에서 **만든 순서 = 좌→우 순서**(파트/divider 순서와 맞춤). 그래서 페이지를 가로로 읽으면 그 글의 이미지 흐름이 그대로 보인다.
