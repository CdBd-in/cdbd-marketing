## 4. 자산 출처 — 새 자산을 받아올 때

> §1~§3는 **이미 컴포넌트화된 자산** 목록. 본문이 요구하는 시각이 기존 컴포넌트로 부족할 때 **여기서 새 자산을 받아와 컴포넌트로 등록**한 뒤 사용한다.
> 블로그 이미지는 썸네일과 출처를 공유 — 동일한 카탈로그·캡처 인프라·Thiings 라이브러리를 사용한다. 따라서 **자산 결정의 1차 참고는 항상 썸네일 가이드**.

### 4.1. CdBd viewer 캡처 (목업 화면용) ⚡

> 본문이 특정 viewer 페이지(프로필 링크·예약·룩북·초대장 등)를 보여줘야 할 때.

**참고 카탈로그**: [[1-3-2. 이미지 출처]] §2 — **17개 viewer URL 슬러그 + 산업·태그 매트릭스 그대로 재사용**.

#### 🔴 절대 원칙 — 사람이 보는 것처럼 분석 후 섹션 분할 캡처 (2026-06-19 추가)

> **여러 폰 목업이 있는 유형(A·C·F·G)은 같은 캡처를 그냥 복붙하지 않는다. viewer를 사람처럼 읽어서 구조를 분석하고, 각 폰에 다른 의미 섹션을 캡처해서 넣는다.**

**왜 필요한가**
- 폰 3~4개에 같은 캡처를 넣으면 시각이 단조롭고 메시지가 약함
- viewer는 자연스러운 사용자 여정 (소개 → 정보 → 액션)을 갖고 있음 — 그 흐름을 폰 시리즈로 시각화해야 본문과 어울림
- 정답 ref `1:12129` (Heritage Summit)이 보여주는 패턴: phone 1 = 인사말 / phone 2 = RSVP form / phone 3 = 문의처

**절차** (모든 멀티 폰 유형 공통)

1. **viewer 풀페이지 캡처** — thum.io `fullpage` 또는 Playwright로 viewer 전체 PNG 확보
2. **사람 관점 구조 분석** — 캡처를 직접 보고 의미 섹션 식별:
   - "이 viewer는 어떤 메시지를 어떤 순서로 전달하는가?"
   - 자연스러운 사용자 여정 (예: 정체성 → 핵심 정보 → 액션 / Welcome → RSVP → 연락처)
   - viewer가 **distinct 섹션을 갖는 경우** (Welcome / Schedule / RSVP / Contact 등 명확히 구분됨)
3. **섹션 분할 매핑** — 슬롯 개수에 맞춰 N개 의미 섹션 선정 (A=3개, C=4개, F=3~4개)
4. **각 섹션을 mockup screen 비율로 crop** — 비율 0.4535 (원페이지) 또는 슬롯 실측 비율
5. **N개 PNG 업로드 → N개 imageHash 확보** (`upload_assets count=N`)
6. **각 슬롯에 해당 hash fill**

**예시 — `1:12129` Heritage Summit (모범 사례)**

| Phone | 의미 섹션 | viewer 영역 |
|-------|-----------|------------|
| Phone 1 (좌) | **정체성 / 인사말** — 행사 소개 + 수신자 이름 | Hero section (y=0~1411) |
| Phone 2 (중앙) | **핵심 정보 / RSVP** — 일정 + 참석 폼 | RSVP section (y=2533~3944) |
| Phone 3 (우) | **액션 / 연락처** — 시간 선택 + 문의 | CTA section (y=3944~5355) |

→ 3개 폰이 자연스러운 **사용자 여정 흐름**을 시각화. 같은 viewer지만 시각적으로 풍부.

**Fallback — viewer가 단일 흐름일 때**

> viewer가 distinct 섹션 없이 hero 중심으로 짧은 경우 (예: TRINTAS 비공개 초대장 — RSVP form lazy-load 누락).

- 같은 viewer를 **다른 vertical scroll position**으로 crop
- y=0 / y=200 / y=500 등 progressive offset → 자연스러운 "스크롤 진행" 시각화
- 캡처 인프라(thum.io)가 lazy-load 섹션을 못 잡을 때도 적용
- 마지막 폰은 빈 BG가 들어가도 OK (viewer 톤과 어울리면 자연스러움)

**🆕 캡처 인프라 — Playwright 기반 (2026-06-19 구축) ⭐ 권장 1순위**

> **블로그 이미지 viewer 3 섹션 자동 캡처 인프라 구축 완료** — A 유형 (3 폰)의 SCREEN_1/2/3 fill용.

**위치**: `자동화 도구/cdbd-capture/capture-seminar-3sections.mjs`

**사용법**:

**동작 (2026-06-19 hero 잘림 사고 후 개정)**:
1. viewer 진입 → 천천히 풀스크롤로 **lazy-load 모두 트리거**
2. **`SECTION_HINTS` 분기 처리**:
   - `1-hero`: **`forceY: 0` 강제** ⭐ — 키워드 매칭 안 함, 페이지 진짜 상단부터 잡음 (로고·타이틀 잘림 방지)
   - `2-rsvp`: zone-restricted 키워드 검색 (zone 30~75%) — "참석 및 사전", "정보 등록", "RSVP" 등
   - `3-contact`: zone-restricted 키워드 검색 (zone 65~100%) — "문의처", "문의하기", "전화" 등
3. 각 섹션을 **A 유형 SCREEN aspect (390×838 = 0.4654)** 로 캡처
4. `screenshots/blog-image-A/` 에 3장 + 풀페이지 + 메타 저장

**🔴 hero `forceY: 0` 룰 (2026-06-19 추가) — 다른 viewer에도 일반 적용**
- hero는 **항상 페이지 진짜 상단 (y=0)** 에서 캡처
- 키워드("회장님께", "Welcome" 등)는 종종 본문 중간에 매칭되어 **로고·타이틀이 잘림** (Heritage Summit 사고: 키워드 매칭 y=393 → THE SAGE 로고 + "2025 The Heritage Summit" 잘림)
- 모든 CdBd viewer의 hero는 페이지 상단에 위치 → `forceY: 0`이 안전한 일반 룰
- 다른 viewer 캡처 스크립트 만들 때도 동일 룰 적용 (`{ name: '1-hero', forceY: 0 }`)

**기존 단순 캡처 도구 (Fallback용)**
- **thum.io fullpage** — lazy-load 누락 발생 (TRINTAS·seminar 둘 다 hero만 잡힘)
- **Microlink** — CdBd 페이지에서 27s 타임아웃 빈번
- → 이 두 도구는 **Playwright 인프라가 사용 불가능할 때만** Fallback 용도

#### 🔴 캡처 유의사항 체크리스트 (2026-06-19 추가)

> **업로드 전 반드시 확인.** 3~4개 폰에 같은 콘텐츠가 들어가는 사고 방지.

**❌ 흔한 실수**

- [ ] **같은 캡처 복붙** — 3개 폰에 같은 imageHash fill ❌
- [ ] **scroll position이 너무 가까움** — y=0/200/500처럼 좁은 간격이면 모두 비슷한 콘텐츠 → 시각 단조 (콘텐츠 영역이 1500px일 때 y=200 차이는 13%밖에 안 됨)
- [ ] **콘텐츠 영역 밖 crop** — viewer 콘텐츠가 y=1500까지인데 y=2000 crop하면 빈 BG만 나옴
- [ ] **lazy-load 미스를 인지하지 못함** — 풀페이지 7000px 캡처했는데 실제 콘텐츠는 1500px만 로드된 경우, 나머지는 빈 BG. 검수 단계에서 발견하지 못하고 진행하면 빈 화면이 들어감
- [ ] **첫 viewer 실패 후 포기** — TRINTAS lazy-load 실패 시 다른 viewer(seminar·rsvp·personalized 대체) 시도 안 함

**✅ 업로드 전 필수 확인**

- [ ] **3~4개 crop을 나란히 시각 비교** — Read tool로 각 PNG 확인 → 정말 다른 내용인지 검증
- [ ] **각 crop의 핵심 콘텐츠 1줄 요약** — 예: "Phone 1: 로고 + 타이틀 / Phone 2: RSVP 폼 / Phone 3: 연락처". 같은 요약이 나오면 ❌
- [ ] **콘텐츠 영역 vs 캡처 영역 측정** — 캡처 PNG의 실제 콘텐츠가 어디까지인지 (다크 BG 영역이 어디부터 시작하는지) 확인. 콘텐츠 영역 밖 crop 금지
- [ ] **viewer가 distinct 섹션을 가지는지 사람이 직접 viewer URL 열어서 확인** — Welcome / RSVP / Contact 등 의미 섹션이 명확히 분리되는가? 만약 아니라면 Fallback이 아니라 **다른 viewer로 교체** 우선 시도

**📌 viewer별 대체 후보 (lazy-load 실패 시)**

| 1순위 후보 | 실패 시 2순위 | 실패 시 3순위 |
|----------|------------|------------|
| `invitation/personalized` (TRINTAS) | `invitation/seminar` (Heritage Summit) | `invitation/rsvp` (Olive Pattern) |
| `invitation/seminar` | `invitation/personalized` | `invitation/buttery_moment` |
| `catalog/oak_table` | `catalog/lookbook` | `catalog/newarrival` |

**📌 distinct 섹션이 끝까지 안 잡힐 때 — 최후 Fallback 결정 트리**

```
1. 다른 viewer 슬러그 시도 (위 표)
   ↓ 모두 실패
2. thum.io wait/30+ 으로 더 기다리기
   ↓ 실패
3. Playwright + 스크롤 트리거 캡처 (썸네일 §3.2)
   ↓ 인프라 없음
4. 같은 viewer를 zoom 다르게 — y=0~1000(타이틀만) / y=400~1400(중간) / y=900~1900(하단)
   각 zoom의 시각 임팩트가 다르도록 의도적으로 구성
5. 1개 폰 = full hero / 2~3개 폰 = 의미 없는 데코 fill (브랜드 컬러 BG만)
```

**✅ 좋은 사례 vs 나쁜 사례**

| | 좋음 ✅ | 나쁨 ❌ |
|---|---------|---------|
| **유저 여정** | Welcome → RSVP → Contact (3개 의미 섹션) | y=0/100/200 vertical scroll (다 똑같음) |
| **시각 변화** | 폰마다 다른 색·요소·UI | 모든 폰이 같은 타이틀·같은 텍스트 |
| **캡처 영역** | 콘텐츠 영역 안에서 분할 (y=0~1500) | 콘텐츠 영역 밖 빈 BG 포함 (y=2000~) |
| **인프라 한계** | lazy-load 미스 발견 → 다른 viewer 시도 | lazy-load 미스 무시 → 빈 화면 진행 |

#### 캡처 파이프라인

| 단계 | 작업 | 도구 |
|------|------|------|
| 1 | 본문 키워드 → 슬러그 매칭 (썸네일 §2 표) | 매칭 표 |
| 2 | viewer URL 풀페이지 캡처 | **thum.io fullpage** (1차) / Microlink (2차) / Playwright (3차) |

| 6 | 각 SCREEN 슬롯에 해당 hash fill | `use_figma` |

## 5. Claude 자동화 매뉴얼 (use_figma)

> 블로그 이미지 생성 시 따라야 할 컴포넌트 사용 순서.

### Step 1 — 캔버스 결정
1. 본문 메시지 → 출력 크기 (1920×1200 vs 1000×1000) → 비교형이면 `1920x1200-비교`
2. 해당 캔버스 컴포넌트(섹션 2) instance를 출력 페이지에 생성

### Step 2 — 모바일 목업 fill
1. 유형(A/C/F/G/H 등) → 적합한 모바일 목업 컴포넌트 선택 (§1 표)
2. instance 생성 → `rescale()`로 슬롯 크기에 맞춤 → 화면 영역에 viewer 캡처 fill
3. 기울임(`rotation`) / 글로우 effect 적용

### Step 3 — 에디터 컴포넌트 끼우기 (해당 유형만)
1. D·E·G·I·J 유형 → 본문 키워드 매칭 (§3 표)
2. 컴포넌트 instance 생성 → 위치·크기 조정

### Step 4 — 라벨 pill / sparkle 데코
1. 컨텍스트 라벨 (5~12자) → 상단 pill 텍스트 노드 채우기
2. K·D 유형 등에서 `sparkle2/3/4` 인스턴스 추가 ([[블로그/썸네일/1. 디자인 가이드/1-2. 레이아웃/1-2-1. 레이아웃 유형 — 합성 (A~K)]] §2.4 화이트리스트 동일)

### 절대 원칙

- ❌ **컴포넌트 노드를 직접 수정 금지** (master 파괴 위험)
- ❌ **컴포넌트 없이 그리지 말 것** — 매번 새로 그리면 시리즈 일관성 깨짐
- ✅ **항상 instance** — `createInstance()` 후 instance 위에서만 변형
- ✅ **rescale 우선** — 자식 vector 비율 보존 (`resize()` ❌)
