# CdBd 매거진 제작 디자인·포맷 규칙

> **목적**: 콘텐츠를 4:5 카드로 제작할 때의 **포맷·레이아웃·이미지·비주얼 공통 규칙**을 모은 문서. (특정 페이지 유형과 무관한 디자인 규칙)
> "무엇을 담을지"(카피·서사·보이스)는 [[2-2-1. 콘텐츠 가이드|콘텐츠 기획 가이드]], **페이지 유형 선택·슬롯**은 [[2-1-1. 공통|페이지 유형 가이드]]를 따른다.
>
> ※ 원문 기획서(카드뉴스 MVP)는 1:1 정사각·고정 8슬라이드 마스터 전제였으나 **전부 우리 규칙으로 대체**했다. 아래는 우리 규칙만 남긴 것.

## 1. 포맷·레이아웃 규칙

| 항목 | 우리 규칙 |
|------|-----------|
| 캔버스 비율·크기 | **4:5 (1080×1350)** |
| 페이지 유형 | **표지·본문·뒷표지 12유형** ([[2-1-1. 공통]]) |
| 폰트·크기 | 4:5 템플릿에 내장된 스타일 사용 (임의 크기 지정 ❌) |
| 로고 | 템플릿에 내장된 `CdBd mag.` 로고 위치 사용 |
| 페이지 번호 | **미사용** — 템플릿 원본에서 제거됨. `N/N` 페이지 번호는 넣지 않는다 |

## 2. 배경 타입 — 3가지 (모든 페이지 유형 공통)

- 배경 타입은 **3가지뿐**:
  - **① img + dim/blur** — 사진 + 가독성용 **dim(어두운 그라데이션) 또는 blur** 오버레이
  - **② solid** — 단색(검정 등)
  - **③ texture** — 종이/구김 등 텍스처
- **모든 페이지 유형(표지·본문·뒷표지)은 배경을 이 3가지 중 하나로 변경해 사용할 수 있다.** (유형별 기본 배경에 고정되지 않음 — 예: `Body-Illust`를 텍스처↔다크로, `Cover`/`BackCover`도 IMG↔Solid↔Texture로 교체 가능)
- **세트 내 통일**: 한 콘텐츠(세트)의 **본문(Body)은 셋 중 하나의 배경 타입으로 통일**한다 (본문 안에서 img+solid+texture 혼용 ❌). 표지·뒷표지는 본문과 별개로 톤만 맞춘다.

## 3. 포인트 컬러 일관성

- 본문에서 **포인트 컬러**(제목 하이라이트 박스, 강조 텍스트 등)를 쓰는 경우, **같은 콘텐츠(=같은 카드뉴스 세트) 안에서는 동일한 포인트 컬러**를 유지한다.
- 세트별로 포인트 컬러는 달라질 수 있지만, **한 세트 내에서는 통일**.

## 4. 이미지 처리 규칙

### 4-1. 여백 없이 프레임 가득
- **모든 이미지는 여백 없이 프레임을 가득 채운다.**
- 원본 비율을 유지한 채 **프레임보다 크게 두고 clip으로 오버플로를 잘라낸다** (이미지를 줄여 맞추는 scale-to-fit 크롭 ❌, 이미지 RECT < 프레임 = anti-pattern).
- 위치를 정할 때 **중요한 부분(피사체·텍스트 영역)이 잘리지 않도록** 사이즈/위치를 조정한다.

### 4-2. 이미지는 별도 레이어로 (부모 프레임 fill ❌)
- 이미지를 **부모 프레임의 fill로 넣지 않는다.**
- 프레임 **내부에 별도의 이미지 레이어(RECTANGLE)** 를 추가한다.
- 부모 프레임은 **clip content가 켜져 있으므로**, 이미지 레이어가 프레임을 완전히 덮도록 **사이즈/위치만 조정**하면 된다.

## 5. 인물 사진 배치 규칙

인물 사진은 위 **4. 이미지 처리 규칙(4-1·4-2)** 에 더해 **룩북 화보 배치 규칙**을 따른다.
> 📎 절차 문서: `cdbd-design-service/룩북/2. 디자인 가이드/2-4. 화보·상품.md` (및 「위치·사이즈 결정 트리」가 있는 `2-1. 공통.md`)

- **축소 크롭 금지 · 원본 비율 유지** — 프레임 clip으로만 잘라냄.
- **얼굴 등 중요한 부분이 잘리지 않게** 배치.
- 샷 타입별 배치 (결정 트리 요약):

| 샷 타입 | 배치 규칙 |
|---------|-----------|
| **풀샷** (머리~발끝) | 머리·발 모두 보이게 + **상단:하단 ≈ 3:2** 마진 + 모델 좌우 정중앙 (규칙 A) |
| 풀샷·한쪽 치우침 | 사이즈 키워 몸을 좌우 중앙으로 (크롭은 다리쪽만) (규칙 B) |
| **웨이스트~니샷** | 모델 정중앙 + 머리 상단 여백 ≈ 36~40 (규칙 C) |
| **바스트샷** (상하 여백 X) | 사이즈 키워 머리 보호 + 좌우 중앙 (규칙 D) |

- **비율이 안 맞아 여백이 생기면** 임의 크롭하지 말고 **Figma AI 배경 늘림**으로 채우거나 사용자에게 요청한다.

## 6. 이미지 소싱 규칙

| 상황 | 소싱 방식 |
|------|-----------|
| **`Body-Illust`의 3D 아이콘** | **Thiings** 활용 방식 그대로 따름 → 가이드 문서: `cdbd-templates/1. 작업 가이드/1-3. 이미지.md` 「📦 소스 ①: Thiings」 |
| **그 외 모든 이미지 슬롯** (표지·본문·뒷표지의 사진/그래픽) | **이미 보유한 이미지를 가공해서 사용** (신규 생성 X) |

> 즉, 새로 만드는 이미지는 Illust 유형의 Thiings 3D 아이콘뿐. 나머지는 기존 이미지를 크롭·보정·누끼 등으로 가공해 슬롯에 맞춘다.
> Thiings 추출·파일 관리(`~/Downloads/{slug}.png`, 1:1 기본 등) 세부 규칙은 위 `1-3. 이미지.md` 참조.

### 누끼(배경 제거) 가공이 필요할 때
콜라주 컷처럼 **배경을 제거(투명 PNG)** 해서 슬롯/셀에 얹어야 하는 경우, 별도 가공 규칙을 따른다.
> 📎 절차 문서: `cdbd-templates/1. 작업 가이드/1-3. 이미지.md` → 「✂️ 누끼(배경 제거) 이미지 처리 요청」

- **두 가지 모드**
  - 🅰️ **로컬 누끼** → `~/Downloads/{keyword}-cutout.png` (투명 PNG). Obsidian 임베드·임시 자산용
  - 🅱️ **Figma 누끼 + 프레임** → Figma 안에서 누끼 RECT + 배경색 프레임 분리. **CdBd 페이지에 들어가는 디자인 자산은 이 모드 필수** (배경색을 이미지에 굽지 말고 프레임에 분리 → 재사용·수정 용이)
- **핵심 단계**: 배경 제거(Figma AI Remove background 등) → **PIL `getbbox()` + `crop()`** 로 alpha 여백 제거 → 크롭본을 슬롯에 fill
- **검증**: PNG `RGBA` 모드 + 네 모서리 alpha=0 (투명) 확인

## 7. 비정형 이미지 카드 배치 — 균형 (masonry)

캡처본 크롭 크기가 제각각(비정형)이어도 배치는 **시각적 균형**을 맞춘다. **카드 크기(크롭)는 사용자 설정을 유지**하고 위치(x/y)만 조정한다.

- **2열 구성**: 외곽 여백 좌우 대칭(~80px), 열 간 간격 ~50–60px.
- **열 상단 정렬(top-align)**: 두 열의 첫 카드 상단 `y`를 맞춘다.
- **세로 간격 일정**: 같은 열 카드 사이 간격 일정(~25px). 단, 높이 차로 하단이 들쭉날쭉하면 **짧은 열의 카드를 아래로 내려 하단을 근접 정렬**(±40px)해 전체 블록이 사각형으로 보이게.
- **무게 대각 분산**: 큰 카드·작은 카드를 대각선으로 교차(예: 좌상 small·좌하 large / 우상 large·우하 small)해 시선 무게를 분산.
- 적용 예(06 해부): 룩북 440×297·참석 430×417·위치 430×445·일정 430×241 → 좌열 `(80,258)`·`(80,580)`, 우열 `(570,258)`·`(570,748)`.

## 8. 이미지 라벨(주석) 위치

이미지 카드의 라벨 탭은 **카드 좌상단 코너 기준 오프셋 `(−14, −20)`** 에 붙인다 (탭이 카드 위 모서리에 살짝 걸침).
- `label.x = card.x − 14` · `label.y = card.y − 20`.
- **카드 크기·위치가 바뀌면 라벨도 같은 오프셋으로 재배치**한다.
- ⚠️ 라벨은 **탭 프레임 + 텍스트가 별개 형제 노드**인 경우가 있다 → 둘 다 같은 델타로 이동(텍스트는 탭 기준 `+16/+7.5` 오프셋 유지).

## 9. 제목 하이라이트 박스 위치 계산

제목 텍스트가 바뀌면 하이라이트 박스를 **폰트 측정으로 재계산**한다. (제목 = Pretendard **Bold 68**, letterSpacing 0%, **중앙정렬** 가정)

- **세로(`y`·`height`)는 줄 위치이므로 유지** — 글자 내용과 무관(같은 폰트·줄 수면 그대로).
- **가로(`x`·`width`)는 단어 위치/폭에 따라 재계산**:
  - `lineCenter = 프레임.x + 프레임.w/2` (예: `60 + 960/2 = 540`)
  - 일반식: `box.x = (lineCenter − Wline/2) + W(줄시작~단어끝) − W(단어) − padX`
  - 단어가 **줄 시작**이면 → `box.x = (lineCenter − Wline/2) − padX`
  - `box.width = W(단어) + 2·padX` (`padX ≈ 10`)
- **측정**: 임시 텍스트 노드(동일 폰트·크기·ls, `textAutoResize='WIDTH_AND_HEIGHT'`)에 문자열을 넣고 `.width`를 읽는다. **trailing space 트림 주의** → 우측 기준(`W(줄시작~단어끝) − W(단어)`) 계산으로 회피.
- 적용 예(07 결과): "데이터를 미리"(369) / 줄2 "데이터를 미리 파악할 수 있어요"(827) → `box.x=117, w=389` (y197·h70 유지).
