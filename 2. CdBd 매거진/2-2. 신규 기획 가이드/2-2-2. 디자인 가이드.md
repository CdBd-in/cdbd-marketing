# CdBd 매거진 제작 디자인·포맷 규칙

> **목적**: 콘텐츠를 4:5 카드로 제작할 때의 **포맷·레이아웃·이미지·비주얼 공통 규칙**을 모은 문서. (특정 페이지 유형과 무관한 디자인 규칙)
> "무엇을 담을지"(카피·서사·보이스)는 [[2-2-1. 콘텐츠 가이드|콘텐츠 기획 가이드]], **페이지 유형 선택·슬롯**은 [[2-1-1. 공통|페이지 유형 가이드]]를 따른다.
>
> ※ 원문 기획서(카드뉴스 MVP)는 1:1 정사각·고정 8슬라이드 마스터 전제였으나 **전부 우리 규칙으로 대체**했다. 아래는 우리 규칙만 남긴 것.

## 1. 포맷·레이아웃 규칙

> 기본 규격(4:5 / 1080×1350, 페이지 유형 12종, Figma 페이지 `504-2`, `CdBd mag.` 로고, 페이지 번호 미사용)은 [[2-1-1. 공통#기본-규격|기본 규격]]이 정본이다.

- **폰트·크기**: 4:5 템플릿에 내장된 스타일 사용 (임의 크기 지정 ❌)

## 2. 배경 타입 — 3가지 (모든 페이지 유형 공통)

> 배경 타입 3종(img / solid / texture)과 "한 세트는 한 배경 타입으로 통일" 규칙은 [[2-1-1. 공통#배경-타입|배경 타입]]이 정본이다.

## 3. 포인트 컬러 일관성

- 본문에서 **포인트 컬러**(제목 하이라이트 박스, 강조 텍스트 등)를 쓰는 경우, **같은 콘텐츠(=같은 카드뉴스 세트) 안에서는 동일한 포인트 컬러**를 유지한다.
- 세트별로 포인트 컬러는 달라질 수 있지만, **한 세트 내에서는 통일**.

## 4. 이미지 처리 규칙

### 4-1. 여백 없이 프레임 가득
- **모든 이미지는 여백 없이 프레임을 가득 채운다.**
- 원본 비율을 유지한 채 **프레임보다 크게 두고 clip으로 오버플로를 잘라낸다** (이미지를 줄여 맞추는 scale-to-fit 크롭 ❌, 이미지 RECT < 프레임 = anti-pattern).
- 위치를 정할 때 **중요한 부분(피사체·텍스트 영역)이 잘리지 않도록** 사이즈/위치를 조정한다.

### 4-2. 이미지는 별도 레이어로 (부모 프레임 fill ❌)
- 이미지를 **부모 프레임의 fill로 넣지 않는다.**
- 프레임 **내부에 별도의 이미지 레이어(RECTANGLE)** 를 추가한다.
- 부모 프레임은 **clip content가 켜져 있으므로**, 이미지 레이어가 프레임을 완전히 덮도록 **사이즈/위치만 조정**하면 된다.

## 7. 비정형 이미지 카드 배치 — 균형 (masonry)

캡처본 크롭 크기가 제각각(비정형)이어도 배치는 **시각적 균형**을 맞춘다. **카드 크기(크롭)는 사용자 설정을 유지**하고 위치(x/y)만 조정한다.

- **2열 구성**: 외곽 여백 좌우 대칭(~80px), 열 간 간격 ~50–60px.
- **열 상단 정렬(top-align)**: 두 열의 첫 카드 상단 `y`를 맞춘다.
- **세로 간격 일정**: 같은 열 카드 사이 간격 일정(~25px). 단, 높이 차로 하단이 들쭉날쭉하면 **짧은 열의 카드를 아래로 내려 하단을 근접 정렬**(±40px)해 전체 블록이 사각형으로 보이게.
- **무게 대각 분산**: 큰 카드·작은 카드를 대각선으로 교차(예: 좌상 small·좌하 large / 우상 large·우하 small)해 시선 무게를 분산.
- 적용 예(06 해부): 룩북 440×297·참석 430×417·위치 430×445·일정 430×241 → 좌열 `(80,258)`·`(80,580)`, 우열 `(570,258)`·`(570,748)`.

## 8. 이미지 라벨(주석) 위치

이미지 카드의 라벨 탭은 **카드 좌상단 코너 기준 오프셋 `(−14, −20)`** 에 붙인다 (탭이 카드 위 모서리에 살짝 걸침).
- `label.x = card.x − 14` · `label.y = card.y − 20`.
- **카드 크기·위치가 바뀌면 라벨도 같은 오프셋으로 재배치**한다.
- ⚠️ 라벨은 **탭 프레임 + 텍스트가 별개 형제 노드**인 경우가 있다 → 둘 다 같은 델타로 이동(텍스트는 탭 기준 `+16/+7.5` 오프셋 유지).

## 9. 제목 하이라이트 박스 위치 계산

제목 텍스트가 바뀌면 하이라이트 박스를 **폰트 측정으로 재계산**한다. (제목 = Pretendard **Bold 68**, letterSpacing 0%, **중앙정렬** 가정)

- **하이라이트 범위 = 검정(`#000`) 글자 구간 전체**: 제목에서 `getStyledTextSegments(['fills'])`의 **검정(0,0,0) 세그먼트가 곧 하이라이트 대상**이다. 그 구간을 **처음~끝까지 모두** 덮는다(일부만 덮어 검정 글자가 박스 밖으로 삐져나오지 않게). 흰색 글자는 박스 밖.
- **세로(`y`·`height`)는 줄 위치이므로 유지** — 글자 내용과 무관(같은 폰트·줄 수면 그대로).
- **가로(`x`·`width`)는 단어 위치/폭에 따라 재계산**:
  - `lineCenter = 프레임.x + 프레임.w/2` (예: `60 + 960/2 = 540`)
  - 일반식: `box.x = (lineCenter − Wline/2) + W(줄시작~단어끝) − W(단어)`
  - 단어가 **줄 시작**이면 → `box.x = lineCenter − Wline/2`
  - **`box.width = W(단어)` — 박스 폭 = 강조 텍스트 폭 그대로(`padX=0`). 박스 끝점이 글자 끝과 일치**한다(advance width에 좌우 side bearing이 포함돼 패딩 없이도 미세 여유가 생김). **임의 패딩 추가 ❌** (넓어 보임).
- **측정**: 임시 텍스트 노드(동일 폰트·크기·ls, `textAutoResize='WIDTH_AND_HEIGHT'`)에 문자열을 넣고 `.width`를 읽는다. **trailing space 트림 주의** → 우측 기준(`W(줄시작~단어끝) − W(단어)`) 계산으로 회피.
- 적용 예(`padX=0`, 각 y·h 유지): 04 "CdBd 모바일 초대장"(560)→`x=201,w=560` · 06 "핵심 카드 네 장"(400)→`x=503,w=400` · 07 "데이터를 미리 파악"(502)→`x=127,w=502`.
