## 🧩 How — 3개 기둥

```
                  🌟 타이틀 → 자동 썸네일
                          │
   ┌──────────────────────┼────────────────────┐
   │                      │                    │
 [디자인 가이드]        [자동 캡처 인프라]      [Figma MCP]
 규칙 + 소재집            최신 자료 수집          제작 엔진
"어떻게 + 무엇을"         Playwright            생성 엔진
```

> **디자인 가이드**가 "어떻게 그릴까(규칙)"와 "무엇을 넣을까(소재집)"를 모두 포함.
> 소재집은 이미지 규칙이 정의한 슬롯에 넣을 실제 자산을 결정하므로 디자인 가이드 하위(`1-3. 이미지`)에 속함.

| 기둥 | 역할 | 위치 | 현재 상태 |
|------|------|------|----------|
| **디자인 가이드** | 어떻게 그릴까(규칙) + 무엇을 넣을까(소재집) | `1. 디자인 가이드/` — [[1-1. 스타일]] · [[1-2-1. 레이아웃 규칙]] · [[1-2-2. 레이아웃별 레퍼런스 노드]] · [[1-3-1. 이미지 규칙]] · [[1-3-2. 이미지 출처]] | 🟢 성숙 |
| **자동 캡처 인프라** | 최신 콘텐츠 자동 수집 (로그인 필요 화면 포함) | `자동화 도구/cdbd-capture/` | 🟡 구축됨 |
| **Figma MCP** | 실제 제작 엔진 (공식 목업 + 규칙 적용) | CdBd 블로그 템플릿 파일 | 🟢 검증됨 |

## ⚙️ 파이프라인 (타이틀 → 썸네일)

> **순서 원리 — 이미지 주도 + 베리에이션**: 타이틀 1개 → 이미지 유형 1개 → **자산 후보 1-2개 × 슬롯 변형 2 = 2-4안 자동 제작** → 사용자 선택. 단일 결정이 아니라 **다중 후보 + 변형 매트릭스**.

1. **입력 (intake)** — 사용자가 "썸네일 만들어줘"로 시작하면 Claude가 입력을 먼저 요청:
   > 썸네일 만들 정보를 알려주세요.
   > - 타이틀 (필수): 블로그 제목 한 문장 (줄바꿈 없이)
   > - 서브타이틀 (선택): 다음 중 하나
   >   1. **별도 입력** — 시리즈·연재 라벨 등 (예: "CdBd 프로필 링크 시리즈 #6")
   >   2. **타이틀 안 마커** — 타이틀 안에 `-` · `/` · 시리즈 명을 넣으면 자동 추출 (예: "프로필 링크 - 모바일 페이지 빌더 CdBd" → 서브: "프로필 링크")
   >   3. 단독 글이면 비워두세요.
   
   서브타이틀 판단은 [[1. 디자인 가이드/1-1. 스타일#서브타이틀 판단 기준 — 입력 타이틀 분석 (2026-06-12 추가)|서브타이틀 판단 기준]] 적용.
   강조 키워드·강조색·레이아웃·이미지는 이후 단계에서 Claude가 자동 결정 (사용자 지정 시 우선)
2. **이미지 유형 결정** — 타이틀에서 이미지 유형 1개 확정 (A·B·C·D·E) → [[1-2-1. 레이아웃 규칙]] §1.1
3. **자산 후보 1-2개 추출** — 1a 기능·1b 산업·1d 톤 다층 분석 → 1·2순위 자산 후보 → [[1-3-2. 이미지 출처]] §1 Step 2
4. **자산 수집** — Microlink 캡처 / Thiings 다운로드 / Playwright (후보별)
5. **N안 자동 제작** — 자산 후보 1-2 × 슬롯 변형(상/하) 2 = **2-4안** 자동 생성. 각 안: 슬롯 clone → 타이틀 의미 단위 줄 나누기·강조색([[1-1. 스타일]]) + 이미지 슬롯에 의미 영역 크롭 fill + 보조 동적 배치
6. **검수·선택** (휴먼) — 2-4안 중 1개 선택 → home.cdbd.in/blog 발행

> 2단계에서 이미지 유형이 정해지면 → 4단계에서 (위치·서브만 더해) 레이아웃 1칸이 확정되고 → 5단계에서 슬롯의 정해진 자리에 텍스트·이미지를 채운다.
> 위치 기준: 슬롯 템플릿([[1-2-1. 레이아웃 규칙]] §2) — 주 이미지는 슬롯이 자동 정의 / 보조 이미지는 [[1-3-1. 이미지 규칙]] §1.2.a 알고리즘으로 동적 배치.

## 🔧 현재 구조의 한계 — 왜 플러그인 단계가 끼어있나

> 현재 흐름은 **타이틀 입력 → Claude(variants JSON 작성) → 사용자(플러그인 실행) → Figma**. 마지막 "버튼 1클릭"이 남아있어 end-to-end 완전 자동은 아니다. 이유와 가능한 미래 경로 기록.

### 왜 Claude가 use_figma로 바로 안 만드나
`mcp__claude_ai_Figma__use_figma`로 **이론적·실증적으로 가능**(2026-06-01 실측)하지만, 4안 일괄 제작에는 비용 차이가 큼:

**실측 비교** (타이틀 "VIP 1:1 예약 관리, 고객도 지치는 전화 핑퐁 모바일 초대장으로 끝내기" / A·B 4안):

| 항목 | 플러그인 | Claude 직접 (단순 fill, 목업 ❌) | Claude 직접 (목업 포함) |
|------|---------|-------------------------------|----------------------|
| 호출 수 | 사용자 1클릭 | use_figma 4회 | use_figma 5회 (4안 + inspect) |
| 시간 (4안) | ~35~55초 (시동 포함) | **87초** (실측) | **~130초** (추정 — 안1 +33초 × 4) |
| 토큰 (대략) | ~550 | ~1,600 | ~2,500~3,000 |
| 정확도 | 100% (구현 그대로) | 70% (목업 X — 직사각형 fill) | ~95% (목업 instance + 내부 rect CROP fill) |
| 트랜잭션 | atomic 묶음 처리 | 안별 독립 (중간 실패 시 부분 잔존) | 안별 독립 |
| 재실행 | 버튼 1번 | 호출 시퀀스 4-5회 재현 | 호출 시퀀스 5+ 재현 |
| 좌표·transform 계산 | `code.js` 캡슐화 | 매 호출 Claude가 명시 | 매 호출 Claude가 명시 |
| 유지보수 | `code.js` 1곳 수정 → 모든 안 반영 | 매 호출 각각 검수 | 매 호출 각각 검수 |

> **핵심 인사이트** — 시간 차이가 "즉시 vs 분 단위"가 아니라 **30~80초 수준**. 1회는 무시할 수준이지만 누적되면 의미. 토큰은 약 **3~5배 차이**.

추가로 MCP 한계: 컴포넌트 변환·section 이동은 commit 안 되고, `throw new Error()` 시 변경 롤백 (변경/검증 분리 필요).
