# 🌟 목표 & 비전 — 블로그 썸네일 자동 생성

> 이 폴더(`1. 썸네일`)의 모든 작업이 향하는 **북극성(North Star)**.
> 새 세션은 항상 이 문서로 시작해 "지금 작업이 이 목표에 어떻게 기여하는가"를 점검한다.

---

## 한 문장으로

> **[home.cdbd.in/blog](https://home.cdbd.in/blog)에 발행되는 모든 블로그 글의 썸네일을, 타이틀만 주면 Claude가 디자인 시스템에 맞춰 자동 생성한다.**

---

## 🎯 Why — 왜 이걸 하는가

- 블로그는 CdBd의 핵심 **마케팅·SEO·리드 채널**
- **글 발행 속도 ≠ 썸네일 제작 속도** → 콘텐츠 파이프라인의 가장 느린 구간

---

## 🔄 As-is → To-be

| | As-is (지금) | To-be (목표) |
|---|---|---|
| **입력** | 디자이너에게 구두 요청 | 블로그 타이틀 텍스트 |
| **제작** | 사람이 매번 수작업 | Claude 자동 생성 |
| **시간** | 글 1개당 30분~1시간 | 분 단위 |
| **일관성** | 작업자마다 편차 | 디자인 시스템 100% 준수 |
| **사람 역할** | 제작자 | **검수·승인자** (80% 자동 / 20% 휴먼) |

---

## 🧩 How — 3개 기둥

```
                  🌟 타이틀 → 자동 썸네일
                          │
   ┌──────────────────────┼────────────────────┐
   │                      │                    │
 [디자인 시스템]        [자동 캡처 인프라]      [Figma MCP]
 규칙 + 소재집            최신 자료 수집          제작 엔진
"어떻게 + 무엇을"         Playwright            생성 엔진
```

> **디자인 시스템**이 "어떻게 그릴까(규칙)"와 "무엇을 넣을까(소재집)"를 모두 포함.
> 소재집은 비주얼 규칙이 정의한 슬롯에 넣을 실제 자산을 결정하므로 디자인 시스템 하위(`1-3. 비주얼`)에 속함.

| 기둥 | 역할 | 위치 | 현재 상태 |
|------|------|------|----------|
| **디자인 시스템** | 어떻게 그릴까(규칙) + 무엇을 넣을까(소재집) | `1. 디자인 시스템/` — [[1-1. 스타일]] · [[1-2-1. 템플릿 규칙]] · [[1-2-2. 템플릿별 레퍼런스 노드]] · [[1-3-1. 비주얼 규칙]] · [[1-3-2. 비주얼 아카이브]] · [[1-4. 프롬프트]] | 🟢 성숙 |
| **자동 캡처 인프라** | 최신 콘텐츠 자동 수집 (로그인 필요 화면 포함) | `scripts/cdbd-capture/` | 🟡 구축됨 |
| **Figma MCP** | 실제 제작 엔진 (공식 목업 + 규칙 적용) | CdBd 블로그 템플릿 파일 | 🟢 검증됨 |

## ⚙️ 파이프라인 (타이틀 → 썸네일)

> **★ 텍스트 우선 (Text-First)** — 타이틀의 **위치·줄 나누기가 썸네일 인상을 좌우하는 가장 중요한 요소**.
> 그래서 자산·이미지보다 **먼저** 스타일 규칙을 읽고 타이틀을 확정한 뒤, 남은 공간에 비주얼을 맞춘다.

```
블로그 타이틀 (줄바꿈 없는 한 문장)
   │
   ▼
① 타이틀 스타일링 ([[1-1. 스타일]])      ──→ ★ 의미 단위 줄 나누기 + 템플릿/위치 선정 + 강조색 결정
   │                                       (서브타이틀 유무로 강조색 자동 / 줄 수 2~4)
   ▼
② 다층 분석 ([[1-3-2. 비주얼 아카이브]] §1) ──→ 기능명 / 산업 / 형식 / 톤 추출
   │
   ▼
③ 자산 선택 (비주얼 아카이브 §2·§3)       ──→ 템플릿 · 카드 · 데코 결정
   │
   ▼
④ 자산 수집                              ──→ Microlink 캡처 / Thiings 다운로드 / Playwright
   │
   ▼
⑤ Figma 생성 ([[1-2-1. 템플릿 규칙]] §1)  ──→ ★ 슬롯 템플릿 있으면 clone / 없으면 레이아웃 직접 (텍스트 우선 → 남은 공간에 비주얼, 의미 영역 크롭)
   │
   ▼
⑥ 검수·승인 (휴먼)                        ──→ home.cdbd.in/blog 발행
```

> ①에서 타이틀 위치·줄바꿈을 먼저 확정 → ⑤에서 그 타이틀이 차지하고 **남은 공간**에 비주얼을 끼운다.
> 비주얼부터 키워 놓고 텍스트를 욱여넣지 않는다 (→ [[1-3-1. 비주얼 규칙]] §0 작업 순서).

## ✅ 성공 기준 (이게 되면 목표 달성)

1. **병목 제거** — 새 블로그 글 발행 시 썸네일이 즉시 따라옴
2. **일관성** — 100개 썸네일을 모아 봐도 하나의 룩앤필
3. **역할 전환** — 디자이너는 "검수·승인"만, "제작"은 Claude가
4. **자가 갱신** — CdBd에 신규 템플릿/기능 추가되면 소재집도 자동 동기화

## 🚧 목표까지 남은 큰 과제

1. **콘텐츠 완성** — 에디터 기능(팀공유·QR·AI 디자인) 캡처 + 매핑
2. **자동 매핑 정확도** — 타이틀 10~20개로 매핑 정확도 측정·튜닝
3. **공식 목업 자동 활용** — clone + fill 워크플로우 스크립트화
4. **휴먼 개입 최소화** — 현재 매 단계 확인 → 명백한 케이스는 무확인 자동 진행
5. **CdBd 자동 동기화** — 신규 템플릿/기능 주기적 크롤링 → 소재집 갱신
