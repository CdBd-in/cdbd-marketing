## 0. 작업 순서 — 이미지 주도 (Image-First) 🔴

> **핵심 원칙**: 타이틀에서 **이미지부터** 풀어간다. 타이틀이 어떤 이미지를 부르는지 먼저 정하고 → 이미지를 모으고 → 레이아웃(슬롯)을 확정한 뒤 → **마지막에 타이틀을 슬롯의 정해진 자리에 채운다**.
> 슬롯 16종(`1:1245`)이 텍스트 자리·이미지 자리·여백·정렬을 **모두 미리 정해놨기 때문에** "남은 공간 계산"이 필요 없다. **슬롯이 곧 정답**.
> 전체 파이프라인(intake → 검수) → [[0. 목표와 비전]] §⚙️

| 순서  | 단계                     | 내용                                                                                      | 출처                                   |
| --- | ---------------------- | --------------------------------------------------------------------------------------- | ------------------------------------ |
| 1   | **이미지 유형 결정 (A~E)**    | 타이틀에서 "보여줄 CdBd 화면이 있는가/하나/여럿/없는가" 판단 → A·B·C·D·E                                       | [[1-2-1. 레이아웃 규칙]] §1.1              |
| 2   | **이미지 자산 수집**          | 유형별 자산 결정 + 캡처·다운로드 (viewer/에디터/Thiings/외부 자료)                                          | §1.1 + [[1-3-2. 이미지 리소스 북]] §2·§3·§4 |
| 3   | **레이아웃 확정 → 슬롯 clone** | 유형 × 타이틀 위치(상/하/중앙) × 서브 유무 → 슬롯 16종 중 1칸 복제                                            | [[1-2-1. 레이아웃 규칙]] §2                |
| 4   | **슬롯에 텍스트 + 이미지 fill** | 타이틀 의미 단위 줄 나누기·강조색 → 슬롯의 `TITLE`/`SUBTITLE`에 입력 / 이미지 → `VISUAL_SLOT` 등에 의미 영역 크롭 fill | 타이틀 → [[1-1. 스타일]] / 이미지 → §1.1.b    |
| 5   | **검수·승인**              | 의미 영역이 잘 보이는가 / 시각 균형(대각선) / 텍스트 가림 없는가                                                 | §2.3 + 휴먼 검수                         |

> ✅ **슬롯 시스템 효과**: 좌표·크기·여백·정렬·줄 수 위치 보정이 자동 → "이미지가 텍스트를 가리지 않을까" 걱정할 필요 없음.
> 📐 줄나누기·강조색 규칙 → [[1-1. 스타일]] "텍스트 작성 규칙"
> 🎯 "왜 이미지부터?": 이미지 유형이 정해지면 슬롯이 결정되고, 슬롯이 결정되면 타이틀 자리도 결정됨. 반대 순서는 슬롯 시스템에서 불가능.

## 1. 이미지 요소 유형 — 무엇을 준비하나

이미지는 **역할**에 따라 두 가지로 나뉜다.

#### 1.1.a. 공식 목업 컴포넌트 (3종류) — A·B·C에서 반드시 사용

> **컴포넌트 페이지**: ✨ [컴포넌트](https://www.figma.com/design/3LPfZ6a6vlJrZ4TXorVWJL/CdBd-블로그-썸네일?node-id=1-1343) (`1:1343`) 안의 **`모바일 목업` section** (`1:1344`) — 3개 symbol. **반드시 이 컴포넌트를 인스턴스로 생성/clone해서 사용** (직접 Rectangle 그리기 ❌).

| # | 목업 종류 | 컴포넌트 ID (symbol) | 원본 크기 | 화면 영역 (캡처 fill 위치) | 사용처 |
|---|----------|---------------------|----------|---------------------------|--------|
| 1 | **원페이지 목업-1** | `1:1368` | 197.36×415.49 | 컴포넌트 안 **`#FFFFFF` rect** | 일반 단일 페이지 (명함·프로필 등) |
| 2 | **원페이지 목업-2 (iPhone-16-Pro)** | `1:1369` | 187×444 | 컴포넌트 안 **`#FFFFFF` rect** | 진짜 폰 느낌 강조 — 프리미엄 컨셉 |
| 3 | **멀티페이지 목업** | `1:1370` | 150×341.51 | 컴포넌트 안 **`#FFFFFF` rect** (중앙 띠) | 다중 페이지 시리즈·스크롤형 콘텐츠 |

> 💡 **공통 규칙**: 3종 목업 모두 **#FFFFFF (흰색) rect 자식 노드**가 화면 영역. viewer 캡처는 이 #FFFFFF 영역에 fill한다.
> **자동화**: 컴포넌트 인스턴스 생성 → 자식 중 `fills`가 `#FFFFFF`(R=1, G=1, B=1)인 rect 노드를 찾아 imageHash로 교체. 내부 자식 ID는 인스턴스마다 달라질 수 있으므로 **색상 기준 탐색**이 안전.

> **선택 가이드**:
> - **명함·프로필·일반 페이지** → 원페이지 목업-1
> - **고급·프리미엄·인물 강조** → 원페이지 목업-2 (iPhone-16-Pro)
> - **카탈로그·룩북·매거진** (페이지 시리즈) → 멀티페이지 목업
>
> **소재집 § 2.2 카탈로그 매핑 (2026-05-26 확정)**:
> - `oak_table` (1) → 원페이지 목업
> - `lookbook` (2) / `newarrival` (3) / `online_lookbook` (4) → **멀티페이지 목업**

**사용 방법** (Figma Plugin API):
1. 공식 컴포넌트(`1:1368`/`1:1369`/`1:1370`)를 `createInstance()` 또는 `clone()`해서 새 썸네일 프레임에 `appendChild`
2. 인스턴스 내부에서 **`fills`가 `#FFFFFF`(R=1, G=1, B=1)인 rect**를 `findOne`으로 찾아 imageHash fill 적용 (scaleMode·imageTransform → §1.1.b)
3. 위치를 `x=353, y=68` (하단형) 또는 우측 정렬 (상단형)로 이동
4. cut-off 패턴 시 부모 프레임에 `clipsContent = true` 보장

```js
// 예시
const mockup = figma.getNodeById("1:1368").createInstance()
const screen = mockup.findOne(n =>
  n.type === "RECTANGLE" &&
  n.fills?.[0]?.type === "SOLID" &&
  n.fills[0].color.r === 1 && n.fills[0].color.g === 1 && n.fills[0].color.b === 1
)
screen.fills = [{type: "IMAGE", imageHash, scaleMode: "CROP", imageTransform: [[1,0,0],[0,1,offsetY]]}]
```

#### 1.1.b. 의미 영역 크롭 원칙 — viewer 전체 ❌ / 타이틀이 말하는 그 섹션 ⭕ 🔴

> **핵심**: 목업·배경 이미지의 캡처를 **viewer 페이지 통째로 넣지 않는다.**
> 타이틀이 말하는 **바로 그 기능·섹션**이 화면에 보이도록 **크롭**한다.
> (CdBd viewer는 세로로 매우 길어, 전체를 fill하면 정작 핵심 섹션이 안 보이고 상단 프로필만 노출됨)

| 순서 | 단계 | 내용 |
|------|------|------|
| 1 | **의미 영역 식별** | 타이틀이 가리키는 기능·섹션이 viewer의 어느 위치(상/중/하단)인지 결정 → [[1-3-2. 이미지 리소스 북]] §3.1 "영역 위치" 표 참조 |
| 2 | **CROP fill** | `scaleMode: 'CROP'` + `imageTransform`(Y offset)으로 그 섹션이 목업 화면에 오도록 이동 |
| 3 | **확인** | 목업 화면 안에 "타이틀이 말하는 그 UI"가 실제로 보이는가 점검 |

> 예: 타이틀이 "**상담 신청 폼**"이면 → `promotion` viewer의 **하단 폼 영역**을 CROP. 프로필·카드가 보이는 상단을 넣으면 ❌
> 영역 좌표·`scaleMode`·`imageTransform` 코드 → [[1-3-2. 이미지 리소스 북]] §3.1
> 프롬프트에 크롭 영역 명시하는 법 → [[1-4. 프롬프트]]

### 1.2. 보조 이미지 (Sub)

| 유형            | 용도         | 예시                      | 크기                       | 라이브러리·출처 |

| **이모지/캐릭터**   | 정서·감정 강화   | Memoji 사람 1명·그룹·손 | 100~150px | ✨ 라이브러리 (TBD) ← Apple Memoji 추출 / [[1-3-2. 이미지 리소스 북]] §4.2 |
| **앱/서비스 아이콘** | 비교 대상 명시   | 링크트리, Jasper, Lexica 로고 | 60×60px 이하 | 각 서비스 공식 로고 (구글링) → 필요 시 라이브러리에 추가 |
| **UI 요소**     | 맥락 추가      | 채팅 말풍선, 카드, 폼           | 주 이미지의 1/3 이하 | 직접 디자인 또는 [Figma Community](https://www.figma.com/community) |

> **위치 규칙**: 유형별 동적 배치 알고리즘 → §2.3 "보조 이미지 위치"
> **공통 원칙**: 보조 < 주 (시각 무게). 개수 0~3개 ([[#2.1 개수 규칙|§2.1]])
> **자산 선택**: 타이틀의 **1d 톤·키워드**에 따라 추천 → [[1-3-2. 이미지 리소스 북]] §1d + §5.1
> **자동화**: 슬롯 clone 완료 후 → 라이브러리 인스턴스 생성 (`createInstance()`) → §2.3 알고리즘으로 좌표 계산 → 슬롯 프레임에 `appendChild`

## 2. 이미지 조합 규칙 — 몇 개, 어떻게

### 2.1. 개수 규칙

| 역할         | 개수                        |
| ---------- | ------------------------- |
| **주 이미지**  | **반드시 1개** (시각적 초점 분산 금지) |
| **보조 이미지** | **0~3개** (그 이상이면 산만)      |

> 목업 여러 개(2~3개 겹침)는 "한 덩어리" = **주 이미지 1개**로 취급
> **에디터 기능 UI + 결과 목업** 결합형도 마찬가지로 한 덩어리 = 주 이미지 1개 (→ [[1-2-1. 레이아웃 규칙]] §1.1 결합형 / 캡처 [[1-3-2. 이미지 리소스 북]] §3.2)

---

### 2.2. 조합 원칙

1. **역할이 명확해야 함** — 주/보조 중 어느 것이 핵심인지 한눈에 보여야 함
2. **텍스트와 겹치지 않기** — 이미지가 글자를 가리면 안 됨
3. **여백 확보** — 이미지끼리, 그리고 텍스트와의 여백을 충분히

---

### 2.3. 이미지 배치 기준 — 어디에 놓나 (실측 기반)

> "자유 배치"가 아니라 **3개 레이어로 위치를 결정**한다.
> 기준은 블로그 썸네일 페이지(Figma `0:1` "블로그 썸네일")의 **실제 예시 60개를 측정**해 도출 (2026-05-29).
> 핵심: **타이틀(좌측)과 주 이미지(우측)이 대각선 균형**을 이룬다. → 작업 순서는 §0(텍스트 우선) 참조.

#### Layer 1 — 좌우 분할 (골격)
- 타이틀 = **좌측** (`x = 40` 고정)
- 주 이미지 = **우측** 정렬 (x 시작 대략 **250~360px**)
- 60개 예시 거의 전부가 이 좌(텍스트)–우(이미지) 대비를 따름

#### Layer 2 — 세로 위치 = 타이틀의 대각선 반대편
| 타이틀 위치 (레이아웃) | 주 이미지 세로 위치 |
|---|---|
| **상단형** | 우측 **중앙~하단** |
| **하단형** | 우측 **상단** (`y ≈ 68`에서 시작) |
| **중앙형(배경)** | 우측 **세로 중앙** |

> 타이틀과 이미지가 **대각선**을 이뤄 시각 무게가 균형을 잡는다.

#### Layer 3 — 5유형(A~E)별 앵커 레시피 (실측값)
| 유형 | 위치·크기 (실측) | 블리드(cut-off) |
|---|---|---|
| **A. 목업** (세로 1개) | `x ≈ 353 / y ≈ 68 / w ≈ 217` (h 자동) | **하단으로 블리드** — 60개 중 8개+ 동일 반복 (확정 상수) |
| **B. 목업+에디터** | 목업: `x ≈ 395 / w ≈ 176 / h ≈ 360` (우측 축소) + 에디터 UI: `260×154` contain (좌중앙·상단) | 목업만 하단 블리드, 에디터는 contain |
| **C. 멀티 목업** (2~3개) | 우측·중앙 하단에 나란히, 각 `w ≈ 143 / h ≈ 340` (엇갈림 — 중앙은 y=175, 양옆 y=215) | 하단으로 블리드 |
| **D. 3D 아이콘** | `w ≈ h ≈ 260`, 우측, 세로 중앙(상단형 `y ≈ 160` / 하단형 `y ≈ 50`) | contain (블리드 X) |
| **E. 배경** | BG: 캔버스 전체 `600×450` opacity 20% / 보조: `230×230` 우측(`x=320 / y=110`, 옵션) | BG 풀 블리드 |

#### Layer 4 — 보조 이미지 위치 알고리즘 (주 이미지 기준 상대 좌표)

> 보조 이미지는 슬롯에 미리 박혀있지 않음 → ✨ 라이브러리에서 인스턴스 생성 후 **주 이미지 좌표를 기준으로 상대 배치**.

| 보조 유형 | 크기 | 배치 규칙 (주 이미지 기준) | 좌표 예시 |
|---|---|---|---|
| **데코** (sparkle 등) | 50×50 이하 | **주 이미지의 모서리에 겹침** (우상단·좌상단·하단). 시선 끌기 포인트. | 우상단 겹침: `x = 주.x + 주.w - 25 / y = 주.y - 25` |
| **이모지/Memoji** | 100~150 | **주 이미지의 대각선 반대편 빈 자리** (균형). 단독은 좌하단, 그룹은 좌측 중앙. | 좌하단: `x = 60 / y = 280` (캔버스 좌표) |
| **앱 아이콘** | 60×60 이하 | **주 이미지 주변 산포** (좌측 빈 공간에 1~3개 세로·가로 배치, 간격 ≈ 20px) | 좌측 가로 산포: `x = 50/120/190 / y = 360` |
| **UI 요소** (말풍선·카드) | 주의 1/3 이하 | **주 이미지 근처** (옆 또는 위, 살짝 겹침 가능). 의미 연결. | 우측 옆: `x = 주.x - 80 / y = 주.y + 100` |

**일반 원칙 (모든 유형 공통):**
1. **시각 무게**: 보조 < 주 항상 유지
2. **대각선 균형**: 타이틀 ↔ 주 이미지 ↔ 보조 이미지가 한쪽으로 쏠리지 않게
3. **텍스트 회피**: `x ≥ 280` 영역에만 배치 (좌측 텍스트 영역 침범 ❌). 단, **Memoji 그룹**은 예외적으로 좌측 가능 (단, 텍스트와 ≥ 30px 간격)
4. **겹침 허용**: 데코는 주 이미지와 **의도적으로 겹침** (포인트 강조). 다른 유형은 살짝만.

> **자동화 의사코드**:
> ```js
> // 1. 주 이미지 좌표
> const main = slot.findOne(n => n.name === "VISUAL_SLOT")
> // 2. 보조 인스턴스 생성
> const deco = decoLibrary[type].createInstance()  // ✨ 라이브러리에서
> // 3. 위치 계산
> deco.x = main.x + main.width - 25  // 우상단 겹침 (sparkle)
> deco.y = main.y - 25
> // 4. 슬롯 프레임에 추가
> slot.appendChild(deco)
> ```

#### 공통 규칙
- 텍스트와 간격 **≥ 30px** (§1.1 목업 규칙과 동일)
- 이미지 **무게중심**은 타이틀의 **대각선 반대편**에 오도록 → 한쪽 쏠림 방지
