# CdBd 이미지 리소스 북

> **목적**: 블로그 썸네일 자동 생성 시 Claude가 타이틀에 맞는 적절한 시각 자산을 *자동 선택*할 수 있도록 한 카탈로그.
> **역할**: [[1-3-1. 이미지 규칙]]이 정의한 이미지 슬롯(주/보조)에 **실제로 넣을 자산**을 결정. (규칙=어떻게 / 이미지 리소스 북=무엇을)
> **사용처**: [[1-4. 프롬프트]]의 프롬프트 템플릿과 함께 컨텍스트로 전달.
> **운영 원칙**: 80% 자동 / 20% 사용자 선택권 — 후보 1~3개를 Claude가 추천하고, 명백한 케이스는 바로 진행.

### Step 2. 종합 우선순위 (5유형 흐름)

1. **1c 유형 결정 먼저** ([[1-2-1. 레이아웃 규칙]] §1.1) → A·B·C·D·E 중 하나로 확정
2. **1a (기능명) 매칭 있으면** → §3에서 캡처 소스 결정 (A는 §3.1 / B는 §3.2)
3. **1b (산업) 매칭 있으면** → §2에서 산업 일치 슬러그 선택 (A·B·C에 활용)
4. **D 유형** → §4 3D·데코에서 개념 매칭 오브젝트 선택
5. **E 유형** → 외부 자료 + 선택적 보조 (CdBd 화면이 아닌 주제 관련)
6. **1d (톤)은 항상 추출** → 보조 데코·이모지 선택에 사용

### Step 3. 다중 매칭 시 선택 기준
- 시각적 임팩트가 큰 자산 우선 (#프리미엄 > #일반)
- 최근 사용 이력이 적은 자산 우선 (다양성 확보)
- 타이틀의 산업·고객층과 일치하는 태그 우선

### Step 4. Fallback
1a~1d 모두 매칭 없음 → 사용자에게 확인 ("X 또는 Y 중 어떤 화면이 적합?")

### 🧪 다층 분석 적용 예시 (5유형 기준)

**예시 1**: "마케터야 **프로필 링크** 좀 만들어봐?"
- 1c **유형**: 프로필 링크는 viewer 기능 → **A. 목업**
- 1a: "프로필 링크" → §3.1 프로필 링크 (캡처 소스: `profilelink/promotion` 상단)
- 1b: 매칭 없음 (마케터는 일반 직군)
- 1d: 매칭 없음 → 기본 sparkle
- **결정**: A 슬롯 + `profilelink/promotion` viewer 목업 (의미 영역 크롭) + sparkle

**예시 2**: "**VIP 1:1 예약 관리**, 전화 핑퐁 모바일 초대장으로 끝내기"
- 1c **유형**: 예약 관리는 viewer 기능 (방문자가 예약 캘린더를 봄) → **A. 목업**
- 1a: "예약 관리" → §3.1 예약 캘린더 (`invitation/reservation` 중단)
- 1b: "VIP" → §2 `invitation/seminar` 후보 (VIP 톤)
- 1d: "VIP" → crown
- **결정**: A 슬롯 + `invitation/reservation` 예약 캘린더 (의미 영역 크롭) + crown 데코

**예시 3**: "**레이어 추가하기** 기능 업데이트"
- 1c **유형**: 레이어는 에디터에서 다루는 작업 → **B. 목업 + 에디터**
- 1a: "레이어" → §3.2 에디터 카드 빌더 UI + 결과 목업
- 1b: 매칭 없음
- 1d: 매칭 없음 → sparkle ("New" 톤)
- **결정**: B 슬롯 + 에디터 카드 빌더 UI(`EDITOR_SLOT`) + 결과 목업(`VISUAL_SLOT`) + sparkle

**예시 4**: "모바일 **명함과 브로셔** 만들고 팀 전체에 공유하는 방법"
- 1c **유형**: 명함 + 브로셔 (둘 이상) → **C. 멀티 목업**
- 1a: 매칭 없음 (명함·브로셔는 카테고리명)
- 1b: 매칭 없음
- 1d: "팀 전체" → Memoji 그룹
- **결정**: C 슬롯 + `profilelink` 목업 1개 + `catalog` 목업 1개 (멀티 슬롯에 배치) + Memoji 그룹

## 3. 기능 라이브러리

> **핵심 인사이트**: CdBd 자체가 "기능 조합으로 만든 페이지". 따라서 **viewer 페이지의 한 섹션 = 해당 기능의 라이브 데모**.
> 기능 캡처 소스를 두 그룹으로 분류:
> - **3.1 viewer 유래 기능** — Microlink로 자동 캡처 가능 (15개)
> - **3.2 에디터 유래 기능** — 로그인 필요, 미리 수동 캡처 후 attachments 저장 (8개 우선 후보)

```bash
# 모바일 뷰포트 (썸네일 목업용 — 권장)

  | python3 -c "import sys, json; print(json.load(sys.stdin)['data']['screenshot']['url'])"

# 데스크탑 뷰포트 (필요시)

```

## 7. Figma 이미지 적용 시 주의사항 (2026-05-26 발견)

> `upload_assets` MCP에 `nodeId`를 지정해도 fill이 **자동 적용되지 않음**.
> 업로드 후 받은 `imageHash`를 `use_figma`로 노드의 `fills`에 명시적으로 설정해야 함.

```js
// 정상 패턴
node.fills = [{
  type: 'IMAGE',
  scaleMode: 'FILL',  // 또는 'FIT', 'CROP', 'TILE'
  imageHash: '<업로드 후 받은 hash>'
}];
```
