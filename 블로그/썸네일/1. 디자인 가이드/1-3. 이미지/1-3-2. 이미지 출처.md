# CdBd 이미지 출처

> **목적**: 블로그 썸네일 자동 생성 시 Claude가 타이틀에 맞는 적절한 시각 자산을 *자동 선택*할 수 있도록 한 카탈로그.
> **역할**: [[1-3-1. 이미지 규칙]]이 정의한 이미지 슬롯(주/보조)에 **실제로 넣을 자산**을 결정. (규칙=어떻게 / 이미지 출처=무엇을)
> **사용처**: 자동화 파이프라인의 자산 결정 단계 ([[0. 목표와 비전]] §파이프라인 3-4단계)에서 컨텍스트로 사용.
> **운영 원칙**: 80% 자동 / 20% 사용자 선택권 — 후보 1~3개를 Claude가 추천하고, 명백한 케이스는 바로 진행.

## 1. Claude 사용 가이드 — 타이틀 → 자산 후보 추출 알고리즘

> **목표**: 타이틀 1개 → **자산 후보 1-2개 × 슬롯 변형(상단/하단) 2 = 2-4안 자동 제작** → 사용자 선택
> **베리에이션 메인 축**: 이미지 자산 (다른 viewer 캡처·다른 템플릿). 슬롯 위치는 보조 축.
> **단일 결정 안 함**: 가능한 자산을 **여러 후보**로 추출 → Claude가 우선순위만 정렬 → N안 자동 생성

### Step 2. 자산 후보 1-2개 추출 (5유형 흐름)

> **단일 결정 ❌ / 후보 추출 ⭕**: 우선순위 1·2위 자산을 둘 다 후보로 추출 → 슬롯 변형과 조합해 N안 생성.

1. **1c 유형 결정 먼저** ([[1-2-1. 레이아웃 규칙]] §1.1) → A·B·C·D·E 중 하나로 확정 (**유형은 1개**)
2. **자산 후보 추출** (유형에 따라 다름):
   - **A. 목업** → §3.1(viewer 기능) + §2(템플릿) 교집합 → **1순위·2순위 후보 2개**
   - **B. 목업+에디터** → §3.2(에디터 기능) → **에디터 캡처 + 결과 목업 1-2개**
   - **C. 멀티 목업** → §2 템플릿에서 **2-3개 카테고리 조합** (1안 = 한 조합)
   - **D. 3D 아이콘** → §4.1 데코·3D에서 **개념 일치 1-2개**
   - **E. 배경** → 외부 자료 1-2 후보 + (옵션) 보조 3D
3. **1d (톤)은 항상 추출** → 보조 데코·이모지 선택 (모든 안에 공통 적용 또는 안별 다른 데코)
4. **출력**: 자산 후보 1-2개 + 슬롯 변형(상단/하단) 2 = **2-4안**

### Step 3. 후보 우선순위 정렬 기준 ⭐ (5유형 공통 — 2026-05-31 강화)

같은 유형 안에서 여러 자산 후보가 있을 때 정렬 순서. **[[1-1. 스타일]] §3 강조어 선택 원칙과 동일한 우선순위** (제품·기능명 최우선).

1. **1a (제품·기능명 명시) ⭐⭐⭐ 최우선** — 타이틀에 CdBd 기능명이 있으면 그 기능의 자산이 반드시 1순위
   - **A 유형**: 해당 기능의 viewer 캡쳐 → §3.1
   - **D 유형**: 해당 기능을 상징하는 3D 오브젝트 → §5.4 (envelope=초대장 / card=명함 / calendar=예약 / 등)
   - **혼동 주의**: "비공개 초대장" → "비공개"(보안 톤)로 매칭하면 안 됨. **"초대장"(기능명)이 우선** → invitation 계열 자산
2. **1b (산업·고객층 일치)** — 타이틀의 산업과 자산 태그 일치
3. **1d (톤 매칭)** — 1a·1b 매칭 없을 때만 톤·정서로 선택 (보안→shield, VIP→crown 등)
4. **시각적 임팩트** — #프리미엄 > #일반
5. **다양성** — 최근 사용 이력이 적은 자산 우선

### Step 4. Fallback
1a~1d 모두 매칭 없음 → 사용자에게 확인 ("**X / Y / Z** 중 어느 화면이 적합한지 골라주세요" — 3개 후보 보여주고 선택)

### 🧪 다층 분석 적용 예시 (5유형 + 2-4안 출력)

**예시 1**: "마케터야 **프로필 링크** 좀 만들어봐?"
- 1c **유형**: 프로필 링크는 viewer 기능 → **A. 목업**
- 1a: "프로필 링크" → §3.1 프로필 링크
- 1b: 매칭 없음 (마케터는 일반 직군)
- 1d: 매칭 없음 → 기본 sparkle
- **자산 후보 2개**:
  - 후보 1: `profilelink/promotion` (영업·프로모션 톤)
  - 후보 2: `profilelink/portfolio` (마케터 직군과 더 어울림)
- **출력 4안**: 각 후보 × 슬롯 변형(상단/하단)
  - 안 1: `promotion` × 목업·상단 (`1:1266`)
  - 안 2: `promotion` × 목업·하단 (`1:1251`)
  - 안 3: `portfolio` × 목업·상단
  - 안 4: `portfolio` × 목업·하단
  - 공통 데코: sparkle 1개 (우상단 겹침)

**예시 2**: "**VIP 1:1 예약 관리**, 전화 핑퐁 모바일 초대장으로 끝내기"
- 1c **유형**: 예약 관리는 viewer 기능 → **A. 목업**
- 1a: "예약 관리" → §3.1 예약 캘린더
- 1b: "VIP" → `invitation/seminar` 후보
- 1d: "VIP" → crown
- **자산 후보 2개**:
  - 후보 1: `invitation/reservation` 예약 캘린더 (의미 영역 크롭)
  - 후보 2: `invitation/seminar` (VIP 톤 일치)
- **출력 4안**: 각 후보 × 상단/하단
- 공통 데코: crown 1개

**예시 3**: "**레이어 추가하기** 기능 업데이트"
- 1c **유형**: 레이어는 에디터 작업 → **B. 목업 + 에디터**
- 1a: "레이어" → §3.2 에디터 카드 빌더 UI
- 1b: 매칭 없음
- 1d: "업데이트" → sparkle ("New" 톤)
- **자산 후보 1-2개**:
  - 후보 1: 에디터 카드 빌더 UI + `profilelink/promotion` 결과 목업
  - 후보 2: 같은 UI + `catalog/oak_table` 결과 목업 (다양성)
- **출력 2-4안**: 각 후보 × 슬롯 변형(상단/하단, B 슬롯)
- 공통 데코: sparkle 1개

**예시 4**: "모바일 **명함과 브로셔** 만들고 팀 전체에 공유하는 방법"
- 1c **유형**: 명함 + 브로셔 (둘 이상) → **C. 멀티 목업** (타이틀 상단 고정)
- 1a: 매칭 없음
- 1b: 매칭 없음
- 1d: "팀 전체" → Memoji 그룹
- **자산 후보 1-2개** (C는 카테고리 조합):
  - 후보 1: `profilelink/corporate` + `catalog/oak_table`
  - 후보 2: `profilelink/promotion` + `catalog/lookbook`
- **출력 2안**: 각 후보 (C는 상단 고정 → 위치 변형 없음)
  - 안 1: 조합 1 × 멀티·상단 (`1:1257`)
  - 안 2: 조합 2 × 멀티·상단·서브 (`1:1287`) — 서브 가능 시
- 공통 보조: Memoji 그룹 1개

## 3. 기능 라이브러리

> **핵심 인사이트**: CdBd 자체가 "기능 조합으로 만든 페이지". 따라서 **viewer 페이지의 한 섹션 = 해당 기능의 라이브 데모**.
> 5유형 매핑:
> - **§3.1 viewer 기능** = **A. 목업 전용** (발행 페이지에 보이는 기능) — Microlink 자동 캡처 가능 (15개)
> - **§3.2 에디터 기능** = **B. 목업+에디터 전용** (편집·관리 화면 기능) — Playwright 캡처 (8개 우선 후보)
> - **§2 템플릿 카탈로그** = **A·B·C 공용** (모든 목업 종류 출처)

### 7.2. Microlink viewer 캡쳐 표준 패턴 ⭐ (2026-05-31 확정)

> **문제**: Microlink 모바일 뷰포트(375×812) full-page 캡쳐 시 viewer 페이지 외곽에 **검정 padding이 4면에 추가됨** (위·아래 ~250px, 좌·우 ~60px @1320×3034 기준).
> **잘못된 해결**: Python으로 검정 영역 잘라내기 → viewer 자연 여백까지 손실 (v10). 흰색 치환 → viewer 배경색과 불일치 가능 (v11).
> **올바른 해결**: **원본 캡쳐를 그대로** Figma 업로드 + **scaleMode CROP + imageTransform**으로 viewport 시각적으로 안쪽 영역만 표시.

```js
// 자동화 표준 (code.js의 applyMockup 함수)
screen.fills = [{
  type: 'IMAGE',
  imageHash: '<원본 v8 hash, 픽셀 처리 X>',
  scaleMode: 'CROP',
  imageTransform: [
    [0.9078, 0, 0.0461],  // 좌우 4.61%씩 crop (가로 90.78% 영역만 사용)
    [0, 0.8907, 0.0859],  // 위 8.59% (status bar 영역) + 아래 2.34% crop
  ],
}];
```

**imageTransform 매트릭스 해석**:
- `[[sx, 0, tx], [0, sy, ty]]` — 표시할 영역의 비율(sx·sy)과 시작 offset(tx·ty)
- 원본 1320×3034 캡쳐 → x=60.85~1259.15, y=260.62~2962.61 영역만 화면에 표시
- 검정 padding은 viewport 밖으로 밀려나 자동으로 안 보임

**장점**:
- 픽셀 처리 단계 제거 → Python `Image.crop()` 불필요
- 단일 원본 hash 재활용 (동일 viewer 여러 슬롯에 적용 시 hash 1개만)
- 캡쳐 도구 차이(Microlink padding 변경 등)는 매트릭스 값만 조정

**모든 viewer 캡쳐가 동일 매트릭스 사용 가능한지**: Microlink가 viewport 비율과 캡쳐 페이지 비율 차이로 padding을 생성하므로, 같은 모바일 뷰포트(375×812)면 모든 viewer가 비슷한 padding 비율을 가짐. 다른 viewport 또는 다른 캡쳐 도구 사용 시에는 매트릭스 재측정 필요 (참조 frame의 imageTransform 추출 → 그 값으로 갱신).

**참조 frame**: `83:186` "원페이지 목업-1" (사용자 작성, 슬롯 페이지) — 매트릭스 값의 원본 출처.
