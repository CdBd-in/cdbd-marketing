# 🚨🚨🚨 텍스트 삽입 절대 원칙 (사고 최다 발생 지점)

> **여기서 사고가 가장 많이 난다.** 다른 모든 항목보다 먼저, 매 작업마다 이 3가지부터.

## ① 줄 나누기 → **무조건 의미 단위로**
- 어절·구문 단위로 끊기. 의미가 흐트러지는 위치에서 줄바꿈 ❌
- 강조어는 한 줄 안에 통째로. 두 줄에 걸치지 않기.

## ② 어절이 중간에 잘리면 안 됨 ⛔
- "고객도 / 지치는 전화" ✅ / "고객도 지치는 / 전화" ✅
- "고객도 지치는 전 / 화 핑퐁" ❌ ← 자동 줄바꿈에 맡기면 이 사고 남
- 방어: `\n` 명시 + 각 줄 폭 ≤350px 실측 검수 + `textAutoResize=HEIGHT` + `node.resize(350)`

## ③ 최대한 **2-3줄 안에** 정렬
- 기본: **2-3줄**. 
- **예외 — 4줄로 늘리는 유일한 조건**: 2-3줄로 정렬했는데 이미지(VISUAL_SLOT / EDITOR_SLOT / 보조 데코)와 겹칠 것 같을 때.
  - 충돌 검증식: `줄수 × 46 + y_start ≤ 다음 슬롯 y_start`
  - 충돌 시 → 4줄로 분산 (5줄 이상은 ❌)

## ⚙️ 작업 중 체크 (이미지 제작 중)

### Step 7. 줄 나누기 ([[1-1. 스타일]] §3) ⭐⭐⭐ 자주 놓침
- [ ] **의미 단위(어절·구문)로 끊기** — 어절 중간에서 자르지 않기
- [ ] **한 줄 한글 10~12자 이내** (폭 ≤350px / 폰트 Bold 36px) — TITLE 모든 유형 350 통일 (2026-06-01)
- [ ] **각 줄 폭 ≤350px 실측 검수** ⚠️ — 의미만 보고 박지 말고 글자 수·폭 둘 다 확인 (06-01 사고)
- [ ] **강조 키워드는 한 줄 안에 통째로** — 줄바꿈으로 쪼개지 않음
- [ ] **각 줄 길이 비슷하게** — 시각적 균형
- [ ] **가장 적은 줄 수** (보통 2-4줄)
- [ ] **`\n` 명시** — 자동 줄바꿈 fallback에 의존 ❌
- [ ] **줄 수 × 46 + y_start ≤ 다음 슬롯 y_start** — EDITOR_SLOT/VISUAL_SLOT 충돌 검증
- [ ] **fillText 동작**: `textAutoResize = HEIGHT` + `node.resize(350, h)` (폭 강제 고정, 높이 자동) — 이전 `WIDTH_AND_HEIGHT` 폐기

### Step 8. 색상 적용 ([[1-1. 스타일]] §2)
- [ ] 타이틀 기본 = #FFFFFF (흰색)
- [ ] 강조어 = #8F80FF (Purple) — A·B·C·D 유형
- [ ] 서브타이틀 = #4DE98B (Green) — 있을 때 전체
- [ ] **E 유형 = 전부 흰색** (강조색 ❌)
- [ ] 한 썸네일에 강조어 1개

### Step 9. 자산 fill ([[1-3-1]] §1.1.b 의미 영역 크롭)
- [ ] **A·B·C**: 공식 목업 컴포넌트 인스턴스 → 내부 흰색/회색 rect에 fill (CROP + imageTransform)
- [ ] **D**: VISUAL_SLOT에 Thiings PNG 직접 fill (FIT)
- [ ] **E**: BG_SLOT에 외부 사진 fill (FILL, opacity 20%) + 보조 VISUAL_SLOT에 Thiings 3D
- [ ] **의미 영역 크롭** — viewer 캡처 시 타이틀이 말하는 그 섹션이 보이도록

### Step 10. 텍스트 위치 보정
- [ ] **하단형 슬롯** (1:1251/1246, 1:1304/1314, 1:1274/1277): `y = 410 - height`
- [ ] **E 유형 중앙**: `y = (450 - height) / 2`
- [ ] TEXT_BLOCK 있으면 그것, 없으면 TITLE 단독

3. **시각적 균형이 맞나? 한쪽으로 쏠리지 않았나?**
4. **2-4안 중 어느 게 가장 적합한가?**

## 📋 자동화 지원 현황 (2026-06-04)

자동화는 두 단계로 나뉩니다:
- **슬롯 fill 자동화**: 슬롯 clone → 텍스트/이미지/색상 자동 적용
- **이미지 자동 소싱**: 어디서 이미지를 가져올지 (자동 vs 수동 imageHash 입력)

| 유형 | 슬롯 fill | 이미지 자동 소싱 | 비고 |
|------|----------|-----------------|------|
| **A. 목업** | ✅ `applyMockup()` (목업 인스턴스 + CROP+imageTransform) | ✅ 완전 자동 | **Microlink + cdbd.in viewer 캡처 자동** (가이드 §3.1·§2 17개 매핑) — 무료 50 req/day |
| **B. 목업+에디터** | ✅ `applyEditor()` (EDITOR_SLOT FIT fill) + `applyMockup()` | ❌ 수동 입력 | 슬롯 fill 완성 (2026-06-01). 에디터 캡처 (Playwright) 자동 호출 미구현 |
| **C. 멀티 목업** | ⚠️ VISUAL_SLOT_1/2/3 처리 별도 필요 | ❌ 수동 입력 | viewer 2-3개 자동 캡처 미구현 |
| **D. 3D 아이콘** | ✅ `apply3DIcon()` (VISUAL_SLOT FIT fill) | ⚠️ 부분 자동 | envelope·calendar·crown·shield·globe·magic-wand 자동 / card·book·chat-bubble·pen·chart-up 미등록 |
| **E. 배경** | ✅ `applyBackground()` (BG_SLOT opacity 20%) + 보조 VISUAL_SLOT | ✅ 완전 자동 | Lexica AI 생성 배경 + Thiings 3D 자동 다운로드 |

> 💡 **수동 imageHash 입력 방식**: 플러그인 UI의 "변형 매트릭스 (JSON 배열)"에 `{"slotId": "...", "imageHash": "...", "name": "..."}` 형식으로 입력하면 모든 유형이 작동.
> 📌 **외부 인프라 요구사항**: A/B/C 유형의 완전 자동화는 Microlink/Playwright API 호출 코드 추가 필요 (외부 서비스 호출은 가능하나 plugin code에 미구현).
