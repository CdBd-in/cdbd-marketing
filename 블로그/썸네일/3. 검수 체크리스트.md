## 🚨 P0 — 즉시 재작업 사유 (사용자에게 절대 보고 금지)

> 이 5개 중 하나라도 걸리면 **무조건 다시**. 보고 → 사용자 검수 → 재요청의 손실이 가장 큰 항목들.

### ☐ ① 원본 텍스트 무결성 — 글자·구두점·띄어쓰기 100% 일치
- **체크 방법**: 입력받은 타이틀 원문과 각 안 `TITLE.characters`를 **`\n`만 제거한 상태**로 문자열 비교 (`title.replace(/\n/g, '') === input.replace(/\s+/g, ' ')` 같은 식).
- **자동 실패 조건**:
  - 쉼표·마침표·느낌표·물음표 **추가** 1개라도 있음
  - 띄어쓰기 추가·삭제 1곳이라도 있음
  - 글자 변경·삭제 1자라도 있음
- 📌 **참고**: [[블로그/썸네일/2. 자동화 체크리스트.md|2. 자동화 체크리스트]] §텍스트 절대원칙 ① / [[1-1. 스타일]] §3 텍스트 작성 규칙. 과거 사고 — 06-04 "고객도 지치는," 임의 쉼표 추가.

### ☐ ② 어절 중간 잘림 없음
- **체크 방법**: 각 줄 끝과 다음 줄 첫 글자가 **한 어절을 이루지 않는지** 육안 검증. 한국어는 띄어쓰기 단위(어절)가 의미 단위.
- **자동 실패 조건**:
  - 한 어절이 두 줄에 걸쳐 잘림 (예: `전 / 화`, `명함 / 과`)
  - 조사가 앞 어절과 분리됨 (예: `프로필 / 링크로` 자체는 OK / `프로필링크 / 로`는 ❌)
- **추가 검증**: `TITLE` 노드 `width = 350` 강제 + `textAutoResize = HEIGHT` 적용됐는지 (Figma 자동 줄바꿈 fallback 차단). → [[1-1. 스타일]] §3 TEXT 노드 폭 규칙.

### ☐ ③ 줄 수 2–4줄 이내, 강조어 한 줄 통째
- **체크 방법**: 각 안의 `TITLE` 줄 수 count + 강조 키워드 문자열이 단일 line에 통째로 들어있는지.
- **자동 실패 조건**:
  - 5줄 이상
  - 강조 키워드가 두 줄에 걸쳐 쪼개짐
  - 4줄인데 슬롯 충돌 검증식(`줄수 × 46 + y_start ≤ 다음 슬롯 y_start`) 미통과 → 다른 슬롯 위치(상↔하)로 변경 또는 줄 재배치
- 📌 [[블로그/썸네일/2. 자동화 체크리스트.md|2. 자동화 체크리스트]] §텍스트 절대원칙 ③.

### ☐ ④ 의미 영역 크롭 — viewer 상단만 보이는 사고 없음
- **체크 방법**: A/B/C 유형의 `VISUAL_SLOT`을 화면에서 확인. 타이틀이 가리키는 그 기능·섹션이 **실제로 보이는지**.
- **자동 실패 조건**:
  - viewer 통째 fill (`scaleMode: 'FILL'`만 적용, `imageTransform` y-offset 누락) → 프로필·헤더만 보이고 핵심 기능 없음
  - 타이틀이 "예약 관리"인데 목업 화면에 viewer 상단 명함 부분만 보임
  - E 유형 `BG_SLOT`에 opacity 20% 미적용 (텍스트 가독성 깨짐)
- 📌 [[1-3-1. 이미지 규칙]] §1.1.b / [[1-3-2. 이미지 출처]] §3.1.

### ☐ ⑤ 슬롯 placeholder 잔존 없음
- **체크 방법**: 각 안 슬롯 안에 **점선 stroke**(`strokes`) 또는 회색 임시 fill 남아있는지 노드 순회.
- **자동 실패 조건**: 임의의 노드에서 `strokes.length > 0` (DashPattern 포함) 또는 빈 fills 빈 슬롯 그대로 출력됨.
- **수정**: `strokes = []` / `fills = []` (이미지 채운 슬롯은 fills 유지, placeholder만 제거).

## 🟡 P1 — 가이드 준수 검증 (사용자 만나기 전 정리)

### ☐ ⑥ 강조색·서브색 규칙
- **TITLE 강조 키워드**: Purple `#8F80FF` 인라인 (`setRangeFills`). 강조 키워드 **1개만**, 서브 유무 무관.
- **SUBTITLE 전체**: Green `#4DE98B` (서브 있을 때).
- **E 유형(배경)만 예외**: 텍스트 전부 흰색, 강조색 ❌.
- **자동 실패**: 강조어 0개 또는 2개 이상 / 색이 흰색 그대로 / E인데 강조색 적용됨.
- 📌 [[1-1. 스타일]] §2.

### ☐ ⑦ TEXT 노드 폭·정렬
| 유형 | TITLE width | SUBTITLE width | 정렬 |
|------|------------|----------------|------|
| A·B·C | 350 | 285 | 좌측 |
| D | 350 | 350 | 좌측 |
| E | 자유 (텍스트 자동 폭) | 자유 | **중앙** (텍스트 자체) |
- **체크**: `node.width` 실측 + `textAlignHorizontal` 확인.
- **하단형 슬롯 y 자동 보정 확인**: A 하단(1:1251/1:1246), B 하단(1:1304/1:1314), D 하단(1:1274/1:1277) — `y = 410 - height` 재계산 됐는지. E는 `(450 - height) / 2`.

### ☐ ⑧ 슬롯 ID 매칭 (유형 ↔ 변형 ↔ 서브 유무)
- 자동 생성된 안의 frame ID가 [[1-2-1. 레이아웃 규칙]] §2.1 표의 정확한 ID를 clone한 것인지.
- **E 유형 특수 규칙**: 서브 없음 → `1:1262`만 / 서브 있음 → `1:1294`만. 두 슬롯 섞지 않음.
- **C 유형**: 상단 고정 (하단형 ❌).

### ☐ ⑨ 공식 목업 컴포넌트 사용 (A/B/C)
- **체크**: `VISUAL_SLOT` 안에 `1:1368` / `1:1369` / `1:1370` 인스턴스가 들어가 있는지 (직접 Rectangle 그리기 ❌).
- viewer 캡처는 **회색톤·밝기 ≥ 0.9 rect 자식 노드**에 fill (단순 imageHash 슬롯에 직접 fill ❌).
- 카탈로그·룩북 키워드 → **멀티페이지 목업(`1:1370`)** 사용했는지.
- 📌 [[1-3-1. 이미지 규칙]] §1.1.a.

### ☐ ⑩ 기능 캡처 이미지 cornerRadius=16 + fit-by-height
- **적용 대상**: B `EDITOR_SLOT` / D 직접 fill(스크린샷 자산) / E 보조 `VISUAL_SLOT`(기능 캡처).
- **제외**: 모바일 목업 컴포넌트 / 3D 아이콘 / `BG_SLOT`.
- **체크**: 해당 슬롯 `cornerRadius === 16` + fit-by-height 알고리즘(`scaledW = imgW × slotH / imgH` → CROP 또는 슬롯 resize+우측 정렬) 적용됐는지.
- 📌 [[1-3-1. 이미지 규칙]] §1.1 (2026-06-04 추가 항목).

### ☐ ⑪ 보조 이미지 위치·개수
- **개수 (유형별 권장)**: A 0–1, B 1, C 0–1, D 0–1, E 1.
- **위치**: `x ≥ 280` (텍스트 영역 침범 ❌). Memoji 그룹만 좌측 예외 (텍스트 ≥ 30px 간격).
- **크기**: 데코 ≤ 50×50, 이모지 100–150, 앱 아이콘 ≤ 60×60.
- **출처**: Thiings 카탈로그 또는 ✨ 컴포넌트 페이지의 데코 라이브러리. **AI 생성 ❌**.
- 📌 [[1-3-1. 이미지 규칙]] §1.2.a / [[블로그/썸네일/2. 자동화 체크리스트.md|2. 자동화 체크리스트]] §자주 놓치는 핵심항목 #3.

## 🟢 P2 — 시각적 균형 (놓치면 사용자 검수에서 걸림)

### ☐ ⑫ 한쪽 쏠림 없음
- 텍스트 ↔ 주 이미지 ↔ 보조 이미지의 시각 무게가 한쪽으로 쏠리지 않음.
- 상단형: 텍스트 상단 + 이미지 우측 하단 → 대각선 균형.
- 하단형: 텍스트 하단 + 이미지 우측 상단 → 대각선 균형.

### ☐ ⑬ 이미지가 텍스트 가리지 않음
- 보조 이미지·데코가 `TITLE` `SUBTITLE` 영역 침범하지 않음.
- A 유형 TITLE 350 ↔ VISUAL_SLOT x=353 미세 겹침은 **y로 분리됨**을 확인.

### ☐ ⑭ 베리에이션 수 (2–4안)
- A·B·D: 자산 후보 1–2 × 상/하 변형 2 = **2–4안**
- C: 상단 고정 → 자산 1–2 × 1 = **2안**
- E: 중앙 고정 → 자산 1–2 × 1 = **2안**
- **자동 실패**: 1안만 생성됨 / 5안 이상

### ☐ ⑮ 출력 위치 확인
- 생성된 안이 **💻 AI 블로그 썸네일 제작 (`26:2`)** 페이지에 있는지.
- 슬롯 원본 페이지 (🧩 `1:1245`) · 발행본 페이지 (🎨 `0:1`) · 컴포넌트 페이지 (✨ `1:1343`)에 부착되면 ❌.

```

각 안 요약:
  - 1안: [유형·위치·자산명] (예: A 상단·oak_table viewer)
  - 2안: ...
  - 3안: ...
  - 4안: ...

내부 검수 결과: 텍스트 무결성 ✅ / 의미 영역 ✅ / placeholder 정리 ✅ / 강조색 ✅
사용자 검수 항목 (휴먼 판단): 의미 적합도 · 시각 균형 · 어느 안 채택
```

> 통과 못한 항목이 있는데 보고하면 사용자가 다시 짚어주는 손실 발생. **반드시 ①~⑮ 전부 ✅ 확인 후 보고**.

## 🔁 검수 실패 시 액션

| 실패 항목 | 액션 |
|---------|------|
| ① 원본 텍스트 | 원본 그대로 다시 set + `\n`만 재삽입. 다른 글자 절대 손대지 말 것. |
| ② 어절 잘림 | `\n` 위치 의미 단위로 재조정 + width 350 강제 재확인. |
| ③ 5줄 이상 / 강조어 분리 | 강조어 위치 기준으로 줄 재분할. 충돌 검증식 통과까지 반복. |
| ④ 의미 영역 | `imageTransform` y-offset 재계산 ([[1-3-2. 이미지 출처]] §3.1 영역 좌표 표 인용). |
| ⑤ placeholder | 슬롯 전체 순회 `strokes=[]`. |
| ⑥–⑮ | 해당 가이드 절 재확인 후 fill 단계 부분 재실행. |

> 재작업 후 **반드시 P0(①~⑤)부터 다시 점검**. 부분 수정이 다른 항목을 깨뜨릴 수 있음.
