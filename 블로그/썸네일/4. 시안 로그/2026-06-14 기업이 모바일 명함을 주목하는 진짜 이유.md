## 5. 발견·수정 사항 (사고 기록)

### 사고 #1 — A3 텍스트 줄 깨짐 (해결)

**증상**: A3(slot `1:1266` A 상단) TITLE이 "기업이 모바일 명함 / 을 / 주목하는 진짜 이유" **3줄로 깨짐**. 같은 텍스트로 D1·D2·A4·C5·C6는 정상 2줄.

**원인 진단**:

| 슬롯 | 디폴트 TITLE width | textAutoResize | 결과 |
|---|---|---|---|
| `1:1254` D 상단 | 297 | `WIDTH_AND_HEIGHT` | ✅ 2줄 (auto-hug with `\n`) |
| `1:1274` D 하단 | 297 | `WIDTH_AND_HEIGHT` | ✅ 2줄 |
| **`1:1266` A 상단** | **285** | **`HEIGHT`** | ❌ 첫 줄 "기업이 모바일 명함을" 10자 > 285px → "을" 다음 줄 강제 wrap |
| `1:1251` A 하단 | 297 | `WIDTH_AND_HEIGHT` | ✅ 2줄 |
| `1:1257` C 상단 | 484 | `HEIGHT` | ✅ 2줄 |

→ 슬롯 원본 `1:1266`의 TITLE width 디폴트가 285(서브 변형 기준) — A 상단·서브(`1:1269`)와 혼동된 것 같음. 가이드 §3 "A·B·D·E TITLE 350px"와 불일치.

**해결**: 모든 안에 명시적 `textAutoResize = "HEIGHT"` + `resize(targetW, height)` (D/A=350, C=484) 강제 후 characters 재반영.

**룰 갱신 후보**:
- [[1-2-1. 레이아웃 규칙]] §3.1 슬롯 좌표 표에 TITLE width 명시 (각 슬롯 디폴트 일치 검증)
- 자동화 코드: **TITLE width 항상 강제** (`textAutoResize=HEIGHT` + `resize(targetW, h)` + characters 순서)
- [[2. 자동화 체크리스트]] §자주 놓치는: "TITLE width — 슬롯 원본 디폴트 신뢰 ❌ / 항상 명시 강제 ⭕" 추가

### 사고 #2 — C 멀티 mockup에 보라 글로우 잘못 적용 (해결)

**증상**: C 안 5·6의 3 mockup INSTANCE에 보라 `#6C4CFF` glow가 입혀짐. 가이드 §3.1는 **A 유형 슬롯 한정** (`1:1267`/`240:236`/`240:240`/`240:238`)으로 명시.

**원인**: A 유형 빌드 코드에서 사용한 fallback 패턴
```js
const vEffects = visual.effects && visual.effects.length ? [...visual.effects] : [GLOW];
inst.effects = vEffects;
```
를 C 유형 빌드에 그대로 복붙. C 슬롯 VISUAL_SLOT_n은 effects 없음 → fallback이 GLOW 강제.

**해결**: C 5·6의 mockup INSTANCE 6개에 `inst.effects = []` 명시.

**룰 갱신 후보**:
- 자동화 코드: GLOW fallback **금지**. `inst.effects = visual.effects || []` (슬롯 effects만 그대로 복사).
- [[2. 자동화 체크리스트]] §자주 놓치는: "글로우 effect — 슬롯에 박힌 것만 복사, fallback ❌. A 한정 룰 ([[1-2-1. 레이아웃 규칙]] §3.1)" 추가
- 더 깊은 룰: 인스턴스 effect 적용은 "타입 화이트리스트" 추가 — A 유형일 때만 GLOW 허용.

### 부수 관찰

- **C mockup 높이 모자람**: rescale 0.7245 → h=301 vs slot h=340 (39px 빈공간 하단). 슬롯 정의는 "하단 블리드" 의도였지만 원페이지 75:34는 비율 2.105로 슬롯 비율 2.378보다 짧음. 시각적으로 큰 문제는 아니지만 멀티페이지 mockup `1:1370` (비율 2.277) 사용이 더 자연. 단, 본 사례는 단일 페이지 viewer hero라 75:34 적합.
- **upload_assets 부산물 frame**: 매번 7개 frame이 첫 페이지(슬롯 페이지)에 생성됨 → 빌드 첫 호출에서 정리 (`getNodeByIdAsync` + `.remove()`).
