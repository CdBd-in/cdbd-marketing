## 4. 발견·해결한 사고

### 사고 #1 — TITLE 어절 중간 wrap (해결)

**증상**: A1·D1·D2 초기 빌드에서 TITLE "1:1 개인화 초대\n장\n운영 가이드" 3줄로 강제 분리 — "초대장" 어절 중간 잘림 ⛔ (§텍스트 절대원칙 ② 위반)

**원인**: 강조어 "1:1 개인화 초대장" 9자 × 30 = 270px > 슬롯 TITLE width 285? 실측은 슬롯에 따라 다름 (1:1269 `TITLE` width 285 미만일 가능성). 한글 자모 조합 폭이 30px보다 클 수도. 결론: **285도 부족했음**.

**해결**: A·D 4안 모두 TITLE width 285 → **350 확장** + characters 재set + setRangeFills 보라 재적용 + A2 하단 변형은 TEXT_BLOCK y = 410 - height 재계산.

**룰 갱신 필요**: [[1-1. 스타일]] §3 TEXT 노드 폭 표에 "강조어 9자(+) 한 줄 fit 요구 시 A·D 350 확장 권장" 추가. PDF·플립북 사고 #1과 동일 패턴 — width 285 한계는 한글 8자 이내. ([[블로그/썸네일/2. 자동화 체크리스트.md]] §0 ⑤ + §자주 놓치는 #11과 일치)

### 사고 #2 — A2 슬롯 1:1246 텍스트 fill 실패 (해결, 룰 정착 필요) ⭐

**증상**: A2 초기 빌드에서 placeholder 텍스트 "서브타이틀 · 시리즈 #N" / "여기에 타이틀이 두세 줄로 들어갑니다" 그대로 노출 — 텍스트 fill 자체가 작동 안 함.

**원인**: 슬롯 `1:1246` 안 텍스트 노드 이름이 **`SUBTITLE`/`TITLE`이 아니라 placeholder 텍스트 자체**:
- `<text id="1:1249" name="서브타이틀 · 시리즈 #N">` (실제 노드 name이 placeholder text)
- `<text id="1:1250" name="여기에 타이틀이 두세 줄로 들어갑니다">`

→ `findOne(n => n.name === "SUBTITLE")`이 null 반환 → 텍스트 set 안 됨.

**해결** (위치 기반 fallback):
```js
const tb = f.findOne(n => n.name === "TEXT_BLOCK");
const texts = tb.children.filter(c => c.type === "TEXT").sort((a,b) => a.y - b.y);
const sub = texts[0];  // y 가장 작은 게 SUBTITLE
const ttl = texts[1];
// 노드 이름도 정상화
sub.name = "SUBTITLE"; ttl.name = "TITLE";
```

**룰 정착 후보** (P1 — 다음 세션 작업):
- [[블로그/썸네일/1. 디자인 가이드/1-2. 레이아웃/1-2-2. 레이아웃별 레퍼런스 노드.md]] 또는 §2.2 사용 절차에 **"슬롯 마스터 1:1246 노드 이름 정상화 필요"** 노트 추가 — 직접 슬롯 마스터에서 노드명을 `SUBTITLE`/`TITLE`로 rename
- [[블로그/썸네일/2. 자동화 체크리스트.md]] §자주 놓치는 추가 — "텍스트 노드 findOne 매칭은 name 기반 우선 + 위치 fallback (TEXT_BLOCK 자식 중 y 정렬)"

### 사고 #3 (없음) — C 슬롯 width 460 확장 정상 작동 ✅

C5·C6 초기 빌드에 TITLE width 460 확장 적용 → "1:1 개인화 초대장\n운영 가이드" 2줄 정상. 사고 없음.

## 7. 작업 흐름 인사이트 (2 사례째 회고)

### 7.1. 입력 분석 §0 룰 재검증

직전 PDF·플립북 사례에서 정착시킨 §0 5단계가 두 번째 사례에서도 그대로 작동:
- ③ 본문 구조 분석 → 다중 유형 격상 (A·D·C 3 유형, 4안 → 6안)
- ④ 자산 직접 매칭 → 추측 단계 사라짐 (`invitation/personalized` 본문 §정의 1:1 매칭)
- ⑤ 강조어 길이 사전 측정 → C 슬롯 460 확장 사전 적용 (C5·C6 사고 미발생 ✅)

다만 사고 #1이 A·D에서 재발 — §0 ⑤에서 "D/A 285 + 확장 시 350" 룰 명시했는데, 강조어 9자가 정확히 270px 예측이라 fit인 줄 알았다. 실제는 안 들어감. **285 한계가 한글 8자 정도**라는 추가 정보로 룰 정밀화 필요.

### 7.2. 사고 #2 — 슬롯 마스터 노드명 불일치 발견

A2 슬롯 `1:1246`만 노드명이 한국어 placeholder. 다른 슬롯(1:1269/1:1282/1:1277)은 SUBTITLE/TITLE 정상. 슬롯 마스터별 일관성 결여 — 가이드 [[1-2-1. 레이아웃 규칙]] §2.3 "슬롯 이름 규칙"의 "이름을 바꾸지 말 것" 룰을 슬롯 마스터 자체가 위반.

**자동화 대응책**: 위치 기반 fallback (TEXT_BLOCK 자식 y 정렬)로 우회. 그러나 근본 해결은 슬롯 마스터 자체 rename.

### 7.3. PIL crop 패턴 정착 — 비율 0.4535 일관 사용

이번 사례는 A 유형도 PIL crop 사용 (full-page 캡처 + 비율 보존 매트릭스 대신 PIL crop으로 단순화):
- 750/0.4535 = 1654 → mockup 비율 정확 매칭
- FILL center crop 시 잘림 0
- 비율 보존 매트릭스 (yScale 계산) 불필요 → 코드 단순

C5도 같은 PIL crop 패턴으로 3 의미 섹션 분할 → C5·C6·A1·A2 모두 동일 패턴 → 통일성 ✅.

### 7.4. 데코 통일성

가이드 §자주 놓치는 #7 — 톤 매칭 우선 / sparkle fallback. 이번 시안은 sparkle 0회 사용 ✅. crown(VIP 톤) + envelope(초대장 기능명) 매칭 — 본문 어휘 직접 매칭이라 톤 매칭보다 강한 근거.
