# 0. 목표와 비전

## 목표

디자이너가 아닌 사람도 블로그 이미지를 손쉽게 만들 수 있도록, **Claude에 내용을 던져주면 Figma에 자동으로 이미지를 생성**하는 워크플로우를 구축한다.

## 비전

- **누구나 디자이너처럼**: 디자인 지식이 없어도 텍스트만 입력하면 완성도 있는 블로그 이미지가 나온다.
- **Claude → Figma 자동화**: 사용자가 Claude에게 블로그 내용(제목, 본문, 키워드 등)을 전달하면, Claude가 Figma MCP를 통해 자동으로 이미지를 생성한다.
- **일관된 브랜드 톤**: 자동 생성이지만 CDBD 브랜드 가이드와 일관된 스타일을 유지한다.

## 핵심 원칙

1. **입력 최소화**: 사용자는 "내용"만 던지면 된다. 레이아웃, 색상, 폰트 등은 Claude가 가이드에 따라 자동 결정.
2. **Figma 네이티브 결과물**: 결과물은 편집 가능한 Figma 파일로 산출되어, 필요 시 미세 조정이 가능하다.
3. **재현 가능성**: 같은 내용이면 같은 품질의 결과가 일관되게 나와야 한다.

## 사용자 시나리오

> "이번 블로그 글 '모바일 명함이 주목받는 이유'에 들어갈 본문 이미지 만들어줘"
> 
> → Claude가 본문 핵심 키워드와 메시지를 추출
> → 디자인 가이드(레이아웃·스타일·이미지 규칙)에 맞춰 Figma에 자동 생성
> → 사용자는 완성된 Figma 링크를 받음

## 자동화 파이프라인 (7 단계)

> 본문을 받았을 때 Claude가 따르는 표준 흐름. 각 단계는 디자인 가이드의 특정 섹션과 1:1 매핑.

```
[1] 입력 + 사이즈   →  [2] 유형 결정   →  [3] 자산 결정   →  [4] 캡처·업로드
                                                                  ↓
[7] 검수·전달  ←  [6] 마무리 정리  ←  [5] 슬롯 fill  ←────────────┘
```

### 1단계 — 입력 + 사이즈 ⭐ (2026-06-19 압축)

> 옛 1·2단계(입력 분석 + 출력 크기 결정)를 1개로 압축. **사이즈는 사용자가 컨트롤**.

- **입력**: 본문 한 단락 + (선택) 이 자리에 들어갈 메시지 의도
- **사이즈 결정 방식 — 둘 중 하나**:
  - **(a) 사용자 직접 지정** — "1920×1200으로 만들어줘" / "스퀘어로" 등 명시 → 그대로 사용
  - **(b) Claude가 한 번 묻기** — 본문 받을 때 사이즈가 명시되지 않으면:
    > "이미지 사이즈는 **1920×1200(Landscape)** vs **1000×1000(Square)** 중 어느 쪽으로 할까요?"
    >
    > 간단 가이드: 메인 시각·비교·시연 → Landscape / 본문 흐름 중간 강조·디테일·모달 → Square
- **출력**: 본문 핵심 메시지 1줄 + 톤·산업 키워드 + **확정된 사이즈**
- **원칙**: Claude가 본문 분석으로 사이즈를 추측하지 않는다 — 사용자 통제권 우선
- **참조**: [[1. 디자인 가이드/1-2. 레이아웃/1-2-1. 레이아웃 규칙]] §1 Step 1 (참고용 가이드)

### 2단계 — 구성 패턴 결정 (11유형 중 1개)
- 1단계에서 확정된 사이즈에 맞는 유형만 후보:
  - Landscape (1920×1200) → A·B·C·D·E·F 중 1개
  - Square (1000×1000) → G·H·I·J·K 중 1개
- 본문 신호 → 유형 매칭
- **참조**: §1 Step 2 표 + §3 유형별 상세 룰

### 3단계 — 자산 결정
- **viewer 슬러그** (A·C·F·G 등 폰 유형) — 본문 키워드 → 17개 viewer 중 매칭
- **에디터 컴포넌트** (D·E·H·I·J) — 기능 키워드 → 6개 에디터 캡처 중 매칭
- **Thiings 3D 슬러그** (K 데코, 부분 강조 등) — 톤 키워드 → 9종 매핑
- **참조**: [[1. 디자인 가이드/1-3. 이미지 규칙]] §4 자산 출처

### 4단계 — 캡처·업로드 ⭐ 핵심
- viewer 풀페이지 캡처 (thum.io `fullpage` 1차 / Microlink 2차 / Playwright 3차)
- 🔴 **사람처럼 viewer 구조 분석** → N개 의미 섹션 선정 (슬롯 개수에 맞춰)
- 각 섹션 PIL crop → mockup 비율 매칭 (0.4642 등)
- `upload_assets count=N` → N개 imageHash 확보
- **참조**: [[1. 디자인 가이드/1-3. 이미지 규칙]] §4.1 절대 원칙

### 5단계 — 슬롯 fill (use_figma)
- 슬롯 템플릿 clone (`15:25` ~ `15:464` 11개 중 1개) → 출력 페이지 `1:20182`에 append
- `BG_CANVAS`는 건들지 않음 (locked, 캔버스 컴포넌트가 BG 제공)
- 각 `SCREEN_*` / `EDITOR_*` 슬롯에 imageHash fill + 점선 stroke 제거
- 라벨 슬롯 처리:
  - 본문 컨텍스트가 자연 라벨 도출 → 텍스트 추가
  - 안 도출 → `pill.remove()` (선택적)
- **참조**: §2.3 자동화 사용 패턴

### 6단계 — 마무리 정리
- 슬롯 placeholder stroke 제거 (이미 fill된 것은 모두)
- 줄 수 변동 시 y 자동 보정 (해당 유형만)
- 데코(✨) 필요 시 sparkle 컴포넌트 instance 추가

### 7단계 — 검수·전달
- 결과 frame 스크린샷 확인 + vault assets 폴더에 저장
- 사용자에게 Figma 노드 링크 전달
- 추후 manual 조정 흔적이 디자인 가이드에 피드백되도록 ([[1. 디자인 가이드/1-2. 레이아웃/1-2-1. 레이아웃 규칙]] 갱신 로그)
