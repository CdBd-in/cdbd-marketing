# 장르 → 이미지 세트 결정 (자동화 1단계)

> **자동화의 최상위 라우팅 계층.** 본문 한 단락이 아니라 **글 전체**를 먼저 읽고 "이 글은 어떤 장르인가 → 이미지를 몇 장, 어떤 유형으로, 어디에 배치할 것인가"를 결정한다.
> 각 이미지의 **출력 크기·구성 패턴**은 그다음 [[1-2-1. 레이아웃 유형 — 합성 (A~K)]]에서, **기초 토큰**은 [[1-1. 스타일]], **공식 컴포넌트**는 [[1-3. 이미지 규칙]]에서 결정.
> 기존 11유형(A~K)으로 안 잡히는 **외부·실사 유형(L~R)** → [[1-2. 레이아웃/1-2-2. 외부·실사 유형 (L~R)]]

> 📊 **근거**: 블로그 15페이지 / 게시물 약 90개 / 이미지 390장 직접 분석 (분석 원본 문서·스크랩 이미지는 정리됨 — 결론은 본 가이드에 모두 반영).

---

## 0. 왜 장르가 먼저인가

390장을 분석해 보니 **글의 "장르"가 이미지 세트를 거의 결정**한다. 단락별로 유형을 고르기 전에, 글 전체 장르를 맞히면 어떤 유형을 몇 장 쓸지가 80% 정해진다.
→ **장르 분류 정확도 = 자동화율.** 이 문서가 자동화의 첫 관문이다.

핵심 발견: 기존 11유형(A~K)은 전부 **CdBd viewer 목업·에디터 캡처** 중심이다. 하지만 사례·소트리더십·라운드업·프로필링크 글은 **CdBd 화면이 아닌 것**(실사진·경쟁사 화면·인포그래픽·문제신)을 많이 쓴다. → 신규 유형 L~R 필요 ([[1-2. 레이아웃/1-2-2. 외부·실사 유형 (L~R)]]).

## 1. 장르 분류기 — 제목·본문 신호 → 장르 1개

> 입력: **글 제목 + 도입부 + 소제목 목록** → 출력: **장르 1개** (+ 시리즈 여부)

| 장르                           | 판별 신호 (제목/내용)                                        | 예시 글                                             |
| ---------------------------- | ---------------------------------------------------- | ------------------------------------------------ |
| **① 사례 (case_study)**        | "~사례", 특정 브랜드명, "후기", "인터뷰", "비하인드"                  | 인하대 졸업패션쇼 · 올인컴플리트 · 귤메달 팝업 · 뷰미디어 박람회           |
| **② 가이드 (guide_howto)**      | "만들기", "5분", "방법", "가이드", "~하는 법", "셀프 제작"           | 기업 행사 초대장 5분 · 모바일 명함 만들기 · 프로필링크 꾸미기            |
| **③ 비교 (comparison)**        | "vs", "대안", "한계", "왜 안 되나", "차이", "그만 쓸까"            | 이벤터스 대안 · PDF·플립북 한계 · 구글폼 한계 · 링크트리 대안          |
| **④ 비용/ROI (cost_roi)**      | "ROI", "절감", "비용", "원", "무료 vs 유료", "단가"             | 50인 명함 ROI · 모바일 명함 도입 ROI · 링크트리 무료 vs 유료       |
| **⑤ 소트리더십 (thought_lead)**   | 외부 브랜드 분석(레드불·넷플릭스·성심당), "전략", "인사이트", "GEO", "알고리즘" | 레드불 · 넷플릭스 하우스 · 성심당 · GEO 전략 · 인스타 알고리즘         |
| **⑥ 기능 출시 (feature_launch)** | "출시", "업데이트", "NEW", "소개", "기능", "레이어 추가"            | 상품 카드 출시 · 룩북 템플릿 소개 · 레이어 추가 업데이트               |
| **⑦ 프로필링크 (profile_link)**   | "프로필 링크", "링크인바이오", "링크트리", "미니 홈페이지", "멀티링크"        | 비즈니스 프로필링크 · 인스타 미니홈페이지 · 갤러리형 프로필링크             |
| **⑧ 라운드업 (roundup)**         | "추천 N가지", "Best N", "툴 N가지", "사이트 N곳", "비교 3"        | AI툴 5가지 · 무료 이미지 Best 18 · 레퍼런스 14곳 · 프로필링크 비교 3 |
| **(수식) 시리즈 (series)**        | 제목에 "시리즈 #N", "(시리즈 #N: ...)"                        | 디지털 카탈로그 #1~6 · 명함 시리즈 · 프로필링크 시리즈               |

**분류 규칙**
- 한 글은 **장르 1개** (가장 강한 신호). 애매하면 우선순위: 사례 > 비교 > 비용 > 라운드업 > 가이드 > 기능출시 > 프로필링크 > 소트리더십.
- **시리즈는 독립 장르가 아니라 수식어** — 본문 이미지 세트는 위 장르를 따르되, **커버(썸네일)에 "시리즈 #N" 라벨**을 붙임 (커버는 [[블로그/썸네일]] 영역).

## 1.1. 분류 기준 (결정론적 규칙) ⭐

> 같은 글이면 누가 돌려도 **같은 장르**가 나오도록 점수·오버라이드·동점 규칙을 고정한다.

### 1단계 — 신호 점수 계산

각 장르의 신호어(§1 표)가 등장하면 **위치별 가중치**로 합산:

| 위치 | 가중치 |
|------|-------|
| **제목** | ×3 |
| **소제목(H2/H3)** | ×2 |
| **본문** | ×1 |

→ 장르별 점수 = Σ(신호어 출현 × 위치 가중치). **최고점 장르 채택.**

### 2단계 — 하드 오버라이드 (점수보다 우선, 위→아래 순으로 먼저 맞는 것 적용)

1. 제목이 **외부 브랜드 전략 분석**(레드불·넷플릭스·성심당 등 CdBd 고객 아님) → **소트리더십**
2. 제목에 **"사례 / 후기 / 비하인드"** 또는 `「브랜드」의 「행사/제품」` 패턴 → **사례**
3. 제목에 **"추천 / Best N / N가지 / N곳 / 비교 N"** (열거형) → **라운드업**
4. 제목에 **숫자+"% / 원 / ROI / 절감 / 단가 / 무료 vs 유료"** → **비용/ROI**
5. 제목에 **"vs / 대안 / 한계 / 왜 안 / 차이 / 그만"** → **비교**
6. 제목에 **"출시 / 업데이트 / NEW / 소개 / 기능"** → **기능 출시**
7. 제목에 **"만들기 / N분 / 가이드 / ~하는 법 / 방법 / 셀프"** → **가이드**
8. 제목에 **"프로필 링크 / 링크트리 / 링크인바이오 / 미니 홈페이지 / 멀티링크"** → **프로필링크**

> 오버라이드 충돌 시 위 번호가 **작은 것 우선**. (예: "프로필링크 추천 3" → 3번(라운드업)이 8번(프로필링크)보다 우선 → 라운드업)

### 3단계 — 동점/무신호 처리

- 1·2단계로도 안 갈리면 §1 동점 우선순위(사례 > 비교 > 비용 > 라운드업 > 가이드 > 기능출시 > 프로필링크 > 소트리더십).
- 어떤 신호도 없으면 기본값 **가이드**.

### 4단계 — 시리즈 플래그 (장르와 독립)

- 제목에 **"시리즈 #N" / "(시리즈 #N: …)"** → `series=true`. 장르는 그대로, 커버에 시리즈 라벨 + 본문 히어로를 **A 다크 변형**으로.

> **출력 형식 (분류기 결과)**: `{ genre, series:bool, scores:{...}, applied_override:번호|null }`

## 2. 장르 → 이미지 세트 (핵심 매핑)

> 출력: 글 1편에 들어갈 **이미지 유형 시퀀스**. (유형 글자 = [[1-2-1. 레이아웃 유형 — 합성 (A~K)]] A~K + [[1-2. 레이아웃/1-2-2. 외부·실사 유형 (L~R)]] L~R)
> 장당 평균 2~9장. 도입부 1장(히어로) → 본문 섹션별.

| 장르 | 표준 이미지 세트 | 주력 유형 | 비고 |
|------|----------------|----------|------|
| **① 사례** | A(히어로) → **L(실사진 다수)** → 결과 풀스크린(A/G) | **L 실사진** | 실사진이 핵심 → Figma 합성 불가, 촬영/수집 |
| **② 가이드** | A(히어로) → **D·E·H(에디터 UI ×3~6)** → F(사용법) | **C/D/E 에디터** | 기존 11유형으로 거의 커버 ✅ |
| **③ 비교** | **B(Before/After)** → O(문제신) → D/E(UI) | **B 비교** | B가 글의 뼈대 |
| **④ 비용/ROI** | **R(수치 일러스트)** → A → I(에디터+통계) | **R 수치** | 큰 숫자 배지·시소·돈자루 (신규 R) |
| **⑤ 소트리더십** | **L(실사진)** + **N(인포그래픽)** + M(외부/인스타) | **L·N·M** | CdBd 목업 거의 없음 |
| **⑥ 기능 출시** | F(사용법) + D(에디터) + A/C | **F·D** | NEW 옐로 배지 |
| **⑦ 프로필링크** | A → **D·E(UI 다수)** → B(구글폼·카톡 vs CdBd) → **M(경쟁사)** | **D·B·M** | 경쟁사 캡처(M) 빈출 |
| **⑧ 라운드업** | **M(외부 캡처, 항목당 1장)** + P(가격표) + Q(콜라주) | **M 외부캡처** | 거의 전부 캡처. Figma 합성 X |
| (공통) | **커버 1장** = 썸네일 (타이틀 텍스트 박힘) | — | [[블로그/썸네일]] 영역, 본 폴더 아님 |

> ⚠️ **②·⑥·⑦의 일부만** 기존 Figma 슬롯(A~K)으로 자동 합성 가능. **①·⑤·⑧은 캡처/촬영 비중이 높아** 사람·스크래퍼 개입 단계가 필요 (§4).

## 2.1. 장르별 정밀 레이아웃 플랜 ⭐ (결정론적)

> 장르가 정해지면 **이미지 플랜(순서·유형·크기·개수·필수여부)**이 자동으로 나온다.
> 표기: `유형(크기)×개수 [필수|선택]` — 크기 `L`=1920×1200, `S`=1000×1000. 유형 글자 = [[1-2-1. 레이아웃 유형 — 합성 (A~K)]] A~K + [[1-2-2. 레이아웃 유형 — 외부·실사 (L~R)]] L~R.
> "개수 = 본문" = 본문 섹션 수에 비례(섹션 1개당 1장). "개수 = 항목" = 글이 열거한 항목 수만큼.

| 장르 | ① 도입/훅 | ② 본문 핵심 | ③ 보조 | ④ 마무리 |
|------|----------|------------|--------|---------|
| **① 사례** | `A(L)×1 [필수]` 결과 히어로 | `L(L)×2~4 [필수]` 현장 실사진 | `B(L)×0~1 [선택]` 전후 | `K(S)×0~1 [선택]` 디테일 줌 |
| **② 가이드** | `A(L)×1 [필수]`*(시리즈→A다크)* | `D/E(L) 또는 H(S) ×본문 [필수]` 에디터 how-to | `F(L)×0~1 [선택]` 단계흐름 | `J(S)×0~1 [선택]` 모달 |
| **③ 비교** | `O(L)×0~1 [선택]` 문제신 | `B(L)×1~2 [필수]` Before/After | `D/E(L)·H(S)×0~3 [선택]` 해결 UI | `K(S)×0~1 [선택]` |
| **④ 비용/ROI** | `R(L)×1 [필수]` 수치 훅 | `A(L)×1 [선택]` 결과물 + `I(S)×0~2 [선택]` 통계 | — | `R(S)×0~1 [선택]` |
| **⑤ 소트리더십** | `L(L)×1 [필수]` 실사진/커버 | `N(L)×0~2 [선택]` 개념도 | `M(L)×0~2 [선택]` 외부/인스타 | — *(CdBd 목업 거의 없음)* |
| **⑥ 기능 출시** | `A(L)×1 [필수]` (NEW 배지) | `D/E(L)·H(S)×2~4 [필수]` 기능 UI | `F(L)×0~1 [선택]` 단계 | `C(L) 또는 G(S)×0~1 [선택]` 결과 |
| **⑦ 프로필링크** | `A(L)×1 [필수]`*(시리즈→A다크)* | `D/E(L)·H(S)×2~5 [필수]` 에디터 | `B(L)×0~1 [선택]` 폼 vs CdBd | `M(L)×0~2 [선택]` 경쟁사 |
| **⑧ 라운드업** | `M(L)×항목 [필수]` 외부 캡처(항목당 1) | `P(L)×0~1 [선택]` 가격표 | `Q(S)×0~1 [선택]` 콜라주 | `A(L) 또는 Q(S)×0~1 [선택]` CdBd 소개 |

**플랜 적용 규칙**
1. **①은 항상 1장**(도입 히어로/훅). 없으면 글이 휑함.
2. **②(본문 핵심)는 필수** — 그 장르의 정체성. 비우지 않음.
3. **③·④는 선택** — 본문에 해당 섹션(전후 비교·통계·모달·경쟁사 등)이 실제로 있을 때만 생성.
4. **개수 상한**: 한 글 총 9장 권장 상한. 초과 시 ②의 본문 비례분을 우선 유지하고 ③·④부터 줄임.
5. **크기 선택 충돌**: 같은 ②에서 "메인 시연=L, 포인트 강조=S" ([[1-2-1. 레이아웃 유형 — 합성 (A~K)]] Step 1 그대로).
6. **트랙 주의**: ①사례의 L(실사진)·⑤⑦⑧의 M(외부캡처)은 합성 불가 → §4 캡처/소싱 큐로.

## 2.2. 이미지 빌드 플랜 (최종 출력) ⭐ — 글 → 자동 결정

> 🔑 **이미지는 "파트(divider 선)별"로 배치한다 — 가장 중요한 원칙.**
> CdBd 블로그 글은 **선(divider)으로 파트(보통 H2 섹션)가 나뉜다.** 장르 일반론으로 N장을 찍어내는 게 아니라, **각 파트를 읽고 "이 파트를 이해하는 데 도움이 되는 이미지 1장"**을 정한다.
> - 절차: ① 본문을 divider 기준으로 파트 분할 → ② 각 파트의 핵심 메시지 1줄 → ③ 그 메시지를 가장 잘 돕는 유형 1개(A~R) 매핑 → ④ 빌드 플랜.
> - **파트와 무관한 이미지는 만들지 않는다** (일반 통계 컴포넌트를 아무 데나 넣지 말 것). 이미지가 그 파트의 내용을 설명해야 한다.
> - 이미지가 불필요한 파트(FAQ·짧은 CTA·단순 도입)는 **건너뛴다**. (모든 파트에 강제로 넣지 않음)
> - 장르 플랜(§2.1)은 **후보 풀**일 뿐 — 실제 선택은 파트 내용이 결정.
> - 예시(추석 카탈로그 글): 도입→A / 6가지이점→B비교 / 인쇄비·변경→R(0원) / 바이어 페이지뷰→통계(영업데이터) / 박람회→QR배포 / FAQ·CTA→이미지 없음.
>

## 3. 배치 순서 (글 내 위치)

```
[커버/썸네일]  ← 글 대표 (썸네일 폴더)
   │
[도입부]       ← A 히어로(목업) 또는 장르별 대표 1장
   │
[본문 섹션 1..N] ← 섹션 메시지마다 1장:
   │   · "이렇게 하세요"   → D·E·F·H (에디터/사용법)
   │   · "A vs B"          → B
   │   · "수치/절감"        → R·I
   │   · "현장/사례"        → L (실사진)
   │   · "경쟁사/외부툴"     → M
   │   · "구조/로직"        → N (인포그래픽)
   │   · "문제/페인포인트"   → O (문제신)
   │
[마무리/CTA]   ← 결과 풀스크린(A/G) 또는 K(부분강조)
```

- **빈도**: 가이드·비교·비용 글은 본문 이미지가 많음(4~9장). 소트리더십·라운드업은 외부 캡처 위주.
- **L(관련글 추천 카드)는 본문 이미지가 아님 → 자동화 제외** ([[1-2. 레이아웃/1-2-2. 외부·실사 유형 (L~R)]] §제외 항목).

## 4. 제작 트랙 분류 ⭐ (자동화가 반드시 알아야 할 것)

유형마다 "어떻게 만드는가"가 다르다. 자동화는 유형을 정한 뒤 **트랙**으로 분기해야 한다.

| 트랙 | 해당 유형 | 제작 방식 | 사람 개입 |
|------|----------|----------|----------|
| **① Figma 슬롯 합성** | A·B·C·D·E·F·G·H·I·J·K + **N·O·P·Q·R** | 슬롯 템플릿 clone → viewer 캡처/3D자산/텍스트 fill | 자동 |
| **② 캡처** | **M (외부 화면·경쟁사·인스타·구글)** | Playwright 헤드리스 캡처 (CdBd viewer 캡처 인프라 재활용) | 반자동 (URL 지정) |
| **③ 소싱/촬영** | **L (브랜드 실사진)** | 실제 촬영 사진 아카이브에서 선택 | 수동 |

> 핵심: "글 던지면 전부 자동 생성"은 불가능. **L·M은 자동 생성 불가** → 파이프라인에 캡처/소싱 단계를 명시. 나머지(A~K·N~R)는 Figma 슬롯 합성으로 자동화.

## 5. 자동화 흐름 (갱신)

```
[블로그 글]
  └─ ① 장르 분류 (이 문서 §1)
       └─ ② 이미지 세트 결정 (§2) → 유형 시퀀스 + 배치(§3)
            └─ ③ 트랙 분기 (§4)
                 ├─ Figma 슬롯 합성 → [[1-2-1. 레이아웃 유형 — 합성 (A~K)]] §2.3 clone→fill
                 │     └─ 출력 크기·패턴([[1-2-1. 레이아웃 유형 — 합성 (A~K)]] §1) + 토큰([[1-1. 스타일]]) + 컴포넌트([[1-3. 이미지 규칙]])
                 ├─ 캡처(M) → Playwright ([[1-3. 이미지 규칙]] §4.1 인프라 재활용, URL만 외부로)
                 └─ 소싱(L) → 실사진 아카이브
  └─ ④ QA: 수치=본문 일치 / 더미데이터(실명·실로고 회피) / 오타 / 컬러
```
