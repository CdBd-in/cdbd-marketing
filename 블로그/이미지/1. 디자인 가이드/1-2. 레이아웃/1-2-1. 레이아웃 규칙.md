## 1. 결정 매트릭스 — 어떤 유형을 쓸 것인가

> 입력: **본문 한 단락 + "이 자리에 어떤 메시지의 이미지가 필요한가"**
> 출력: **출력 크기 1종 + 구성 패턴 1종**

### Step 1 — 출력 크기 결정

| 문맥 신호 | 선택 |
|---------|------|
| 글의 **메인 시각** / 섹션 도입부 / 비교·시연 핵심 | **1920×1200 (Landscape)** |
| 본문 흐름 중간 **포인트 강조** / 모달·디테일 줌인 / 짧은 보조 시각 | **1000×1000 (Square)** |
| 같은 내용을 가로·세로 두 곳에 모두 보여줘야 할 때 | **두 크기 모두 제작** |

### Step 2 — 구성 패턴 결정 (본문 메시지 → 유형)

**🟧 1920×1200 (Landscape) — 6가지 패턴**

| 유형 | 신호 (본문이 무엇을 말하는가) | 시각 구성 |
|------|------|----------|
| **A. 히어로 이미지 (목업)** | 글의 도입부·결론·메인 비주얼. "X라는 제품/페이지를 소개" | **기울인 폰 목업 2개**가 V자/평행으로 페어링 |
| **B. 비교 (vs)** | "A 대신 B" / "기존 vs 신규" / "PDF vs 디지털" | 좌·우 분할 — 각 사이드에 라벨 pill + 아이콘·캡처 |
| **C. 목업 + 목업** | 같은 viewer의 **다른 페이지** 또는 **같은 기능의 두 사례** | 폰 2개 나란히 + 상단 라벨 |
| **D. 에디터** | "**편집 / 관리** 화면에서 일어나는 일" — 빌더·통계·CRM | 에디터 UI 캡처 단독 (일부는 폰 small inset) |
| **E. 목업 + 에디터** | "에디터에서 만든 결과 = 폰의 viewer" 인과 관계 | 좌측 에디터 UI + 우측 폰 목업 |
| **F. 사용법 (Step-by-Step)** | 단계적 시연 — "이렇게 → 이렇게 → 이렇게" | 폰 3~4개를 `>` 화살표로 연결, 단계 라벨 |

**🟦 1000×1000 (Square) — 5가지 패턴**

| 유형 | 신호 | 시각 구성 |
|------|------|----------|
| **G. 목업 + 목업 (square)** | 컴팩트한 페어 시각 — 본문 흐름 중간 강조 | 폰 2개 + 퍼플/라벤더 카드 BG |
| **H. 목업 + 에디터 (square)** | 좁은 공간에 "에디터·결과" 요약 | 폰 1 + 작은 에디터 카드 |
| **I. 에디터 + 통계** | 빌더 + 결과 지표(통계·뱃지·결과 카드) | 에디터 UI + 데이터 카드/차트 |
| **J. 모달창** | 특정 다이얼로그 / 알림 / CTA 모달 줌인 | 모달 단독, 주변 dimming |
| **K. 부분 강조** | viewer의 **한 부분만** 클로즈업 ("이 카드 보세요") | 클로즈업 영역 + ✨ sparkle + 퍼플 BG |

## 3. 유형별 상세 룰

### 3.1. A. 히어로 이미지 (목업) — `1:11487`

> 글의 도입부·결론을 장식하는 **메인 비주얼**. 본문이 무엇을 말하는지 한눈에.

- **목업 2개**: 좌(-15° 기울임) + 우(+15° 기울임), 약간 겹침
- **배경**: 흰색 또는 연한 그라데이션
- **라벨 pill**: 선택. 있다면 상단 중앙 (없는 경우가 더 많음)
- **목업 화면 fill**: viewer의 hero 섹션 캡처 (포스터·표지 영역)
- **글로우**: 보라 글로우 (`#6C4CFF`, blur 30) 권장

### 3.2. B. 비교 — `1:11488`

> "A → B" "기존 vs 신규" 명확한 대비를 시각화.

- **좌·우 분할** 50:50 또는 45:55
- **각 사이드 구성**:
  - 상단: **라벨 pill** (예: "기존 카탈로그 - PDF" / "디지털 카탈로그")
  - 중앙: 자산 (폰 목업 / 파일 아이콘 / 종이 더미 / 차트 등)
- **분리 신호**: 가운데 얇은 세로선 or 화살표 `→` or 단순 여백
- **자산 다양성**: 비교 대상이 폰일 필요 ❌ — 종이 더미, 자물쇠, 차트, PDF 아이콘 등 **비유적 오브젝트** 적극 활용
- **컬러 위계**: "Before"는 무채색·종이 톤 / "After"는 퍼플 강조 — 가치 우위 시각화

### 3.3. C. 목업 + 목업 — `1:11733`

> 같은 viewer의 다른 페이지를 나란히 보여주거나, 같은 기능의 2개 사례.

- **폰 2개**: 평행 또는 V자 페어링
- **라벨 pill**: 상단에 1개 (둘을 한 마디로 묶는 컨텍스트)
- **각 폰의 화면**: 같은 viewer의 **다른 페이지** 캡처 권장 (`?page=N` 활용)
- **글로우**: 권장
- **A 유형과의 차이**: A는 "이 페이지를 소개" / C는 "이 viewer의 여러 페이지를 동시에"

### 3.4. D. 에디터 — `1:12233`

> 빌더·CRM·통계 등 **에디터 화면 자체**가 주인공.

- **에디터 캔버스**: 화면 가로 거의 가득 (좌우 여백 ≤ 80px)
- **상단 라벨 pill**: 어떤 에디터/기능인지 ("AI 디자인 카드", "예약 카드", "에디터 보드")
- **데코**: `✨ sparkle` 1~2개 — 새 기능·강조 영역 옆
- **부분 하이라이트**: 강조 UI 영역을 퍼플 outline 또는 sparkle로 표시

### 3.5. E. 목업 + 에디터 — `1:12543`

> "에디터에서 만든 결과 = 폰" 인과 관계 시각화.

- **레이아웃**: 좌측 에디터 패널(약 60%) + 우측 폰 목업(약 40%)
- **연결 신호**: 화살표 `→` 또는 폰을 에디터 위에 살짝 겹치기
- **라벨 pill**: 상단 — 무엇을 만드는 중인지
- **B 유형(비교)와의 차이**: E는 인과(만들기 → 결과), B는 비교(A vs B)

### 3.6. F. 사용법 — `1:13078`

> "이렇게 → 이렇게 → 이렇게" 단계별 시연.

- **단계 수**: **3개 또는 4개** (5개 이상은 ❌ — 시각 과밀)
- **레이아웃**: 가로 일렬 — `폰 ① > 폰 ② > 폰 ③` (화살표는 `>` 그레이)
- **단계 라벨**: 각 폰 아래 또는 위에 작은 숫자 원(`①②③`) + 1~3단어 라벨
- **각 폰 화면**: 단계별 viewer 상태 캡처 (실제 클릭 흐름)
- **그리드 오버레이**: 일부 프레임에 `Group 1818` 그리드 라인 — 정렬용, 출력에는 안 보임

### 3.7. G. 목업+목업 (square) — `1:15003`

> Landscape C의 정사각 버전. 본문 흐름 중간 컴팩트 강조.

- **배경 블록**: 흔히 **라벤더 또는 진한 퍼플 카드** (전체 또는 하단)
- **폰 2개**: 좁은 공간에 V자/X자 페어링 (각도 더 크게 ±20° OK)
- **라벨 pill**: 선택 — 공간이 좁아 생략하는 경우 많음

### 3.8. H. 목업+에디터 (square) — `1:16916`

> 좁은 공간에 "에디터·결과"를 압축. 폰 1개 + 작은 에디터 카드.

- **레이아웃**: 폰을 중앙 또는 하단 + 에디터 카드를 모서리에 겹침
- **에디터 카드**: 풀 에디터 ❌ — **카드 1개 또는 패널 일부**만 발췌

### 3.9. I. 에디터 + 통계 — `1:17813`

> 빌더에서 결과 지표를 강조. 숫자·차트가 핵심.

- **레이아웃**: 에디터 UI (좌·하) + 통계 카드/차트 (우·상) 겹치기
- **통계 강조**: 큰 숫자 (Pretendard Bold 60~80px) + 작은 라벨
- **컬러**: 통계 카드는 흰색 + 퍼플 강조선

### 3.10. J. 모달창 — `1:19148`

> 특정 다이얼로그·알림·CTA 모달을 단독 보여줌.

- **모달 단독 중앙**: 주변 약간 dimming(`#000000` 30%) 또는 흰 배경
- **모달 외 요소 ❌** — 시선 100% 모달에
- **사용 시점**: "이 모달이 핵심이야" 라는 본문 강조

### 3.11. K. 부분 강조 — `1:19887`

> viewer의 한 부분만 클로즈업 — "이 카드, 이 영역 보세요".

- **배경**: **퍼플 블록** (`#6C4CFF` 또는 라벤더) 전체 또는 절반
- **줌 슬롯**: viewer 캡처 중 강조하고 싶은 영역만 잘라 카드로
- **Sparkle**: ✨ 1~2개 카드 모서리 — 강조 시그널
- **카드 그림자**: 강한 drop shadow로 떠 보이게

## 4. 자동화 적용 절차 (MCP `use_figma`)

> Claude가 본문을 받았을 때 따르는 흐름. (자동화 체크리스트 별도 작성 예정)

1. **본문 분석** — 메시지 핵심 1줄 + 어떤 종류의 시각이 적합한지 (§1 매트릭스)
2. **출력 크기 결정** (Step 1)
3. **구성 패턴 결정** (Step 2 — 11유형 중 1개)
4. **레퍼런스 프레임 clone** — 해당 섹션의 첫 프레임을 자동화 출력 페이지로
5. **자산 fill**:
   - 목업 슬롯 → viewer 캡처(의미 영역 crop) + mockup instance
   - 에디터 슬롯 → 에디터 캡처 (PIL crop)
   - 라벨 pill → 컨텍스트 텍스트 (5~12자)
   - 데코 → sparkle 컴포넌트 instance
6. **마무리** — 슬롯 placeholder 제거 + 정렬 확인
