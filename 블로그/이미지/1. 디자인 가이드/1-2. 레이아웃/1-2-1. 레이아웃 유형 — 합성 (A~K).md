# 레이아웃 유형 — 합성 (A~K)

> 레이아웃 = **출력 크기(1920×1200 · 1000×1000) × 구성 유형**. 구성 유형은 **두 갈래(형제)**로 나뉜다:
> - **① 합성 유형 (A~K)** — CdBd 목업·에디터를 슬롯에 채워 만드는 유형. → **이 문서**
> - **② 외부·실사 유형 (L~R)** — 실사진·외부캡처·인포그래픽·문제신·가격표·콜라주·수치일러스트. → [[1-2-2. 레이아웃 유형 — 외부·실사 (L~R)]] *(동등한 형제 문서)*
>
> 공통 인프라 — **결정 매트릭스(§1) · 슬롯 운영(§2) · 자동화 절차(§4)** — 는 두 갈래 모두에 적용된다.
> ⬆️ 상위: 주제→세트 [[1-0. 주제]] · 노드 인덱스 [[1-2-3. 유형별 레퍼런스]] · 토큰 [[1-1. 스타일]] · 컴포넌트 [[1-3. 이미지 규칙]]

## 1. 결정 매트릭스 — 어떤 유형을 쓸 것인가

> ⚠️ **전제**: 이 매트릭스는 [[1-0. 주제]]에서 **글 주제 → 이미지 세트(유형 시퀀스)**가 정해진 뒤, **개별 이미지 1장의 크기·패턴**을 고르는 단계다. 유형이 L~R(외부·실사)로 결정됐다면 본 매트릭스 대신 [[1-2-2. 레이아웃 유형 — 외부·실사 (L~R)]]을 따른다.

**Placeholder 시각 약속** (2026-06-19 v3 — 캔버스 컴포넌트 BG 기반)
- **`BG_CANVAS`** = 캔버스 컴포넌트 instance (`✨ 컴포넌트` 페이지 §캔버스 목업 — `1:10840`·`1:10841`·`1:10838`·`1:10839`). **자동화가 건들지 않음**. `locked=true`로 잠겨있음. 그리드 라인은 마스터 컴포넌트 디자인이며 출력 이미지에는 반영 X (Figma 표시 가이드만)
- **실체 PNG fill** (`MOCKUP_PHONE_*`) = 폰 frame 이미지 (`36c4ee...`) — 자동화가 건들지 않음
- **점선 보라 stroke + 회색 fill** = 자동화가 캡처/자산으로 채울 슬롯 (`SCREEN_*`·`EDITOR_*`·`LEFT_ASSET` 등)
- **점선 보라 pill** = 라벨 텍스트 들어갈 자리 — **선택적** (콘텐츠 없으면 `remove()`)

**🆕 라벨 슬롯 처리 룰** (2026-06-19 추가)

> **라벨 슬롯은 들어갈 내용이 없으면 채우지 않아도 된다.**

- `LABEL_PILL` · `LEFT_LABEL_PILL` · `RIGHT_LABEL_PILL` · `STEP_LABEL_*` 등 **모든 라벨류 슬롯은 선택적**
- 본문에서 컨텍스트 라벨이 자연스럽게 도출되지 않으면 → **빈 placeholder 제거 + 텍스트 추가 ❌**
- 자동화 동작: 라벨 콘텐츠 없으면 `pillNode.remove()` 호출 — 깔끔하게 사라지게
- A 유형 TRINTAS 사례처럼 **시각 콘텐츠(폰+캡처)만으로 메시지 전달**이 명확하면 라벨 불필요

```js
// 라벨 슬롯 조건부 처리 패턴
const pillContent = decideLabelText(bodyContext); // 없으면 null
if (pillContent) {
  // 텍스트 노드 만들고 pill 안에 중앙 정렬
  pill.strokes = []; // 점선 stroke 제거
  // ... add text
} else {
  pill.remove(); // 빈 라벨이면 통째로 제거
}
```

**✅ 캡처 fill 실전 절차 (2026-06-22 A유형 end-to-end 검증)**

> ⚠️ **`upload_assets`의 `nodeId` 직접 배치는 슬롯에 fill되지 않았다** (SOLID 유지). 검증된 2-스텝 방식을 쓴다:

1. **이미지 업로드 → imageHash 확보**: `upload_assets`(count=N, nodeId 없이) 로 단일사용 URL N개 받기 → 각 URL에 PNG를 `curl -F "file=@cap.png;type=image/png"` POST → 응답의 `imageHash` 수집.
2. **`use_figma`로 슬롯 fill**: clone한 프레임의 `SCREEN_*`(또는 `EDITOR_*`·`ASSET`)에 직접 대입 —
   ```js
   n.fills = [{ type:'IMAGE', imageHash: HASH, scaleMode:'FILL', imageTransform:[[1,0,0],[0,1,0]] }];
   n.strokes = []; // 점선 제거
   ```
   - 캡처 aspect = 슬롯 aspect(A는 0.4654)면 identity transform으로 왜곡 0.
   - **z-order**: `MOCKUP_PHONE_*`(폰 프레임 PNG, 아래) → `SCREEN_*`(캡처, 위) 순서 유지 — clone은 원본 순서를 보존하므로 그대로 두면 됨.
- **출력 페이지**: `💻 AI 블로그 이미지 제작` (`1:20182`). clone을 이 페이지에 append.
