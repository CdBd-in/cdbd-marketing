## 1. 모바일 목업 — `1:10590`

![[블로그/이미지/assets/컴포넌트-모바일목업.png]]

| 이름 | 노드 ID | 크기(px) | 용도 | 사용 유형 |
|------|---------|---------|------|----------|
| **원페이지 목업** | `1:10623` | 208 × 433 | 정면 정렬된 표준 폰 — 단일 페이지 viewer 시연 | A·G·H·J |
| **멀티페이지 목업** | `1:10594` | 150 × 341 | 작은 폰 (상하 검정 마스크) — 페이지 일부 / 다중 viewer 시리즈 | C(C 멀티)·F(사용법) |
| **히어로 목업** | `1:10589` | 833 × 481 | 두 폰이 X자/V자로 페어링된 **히어로 페어 컴포넌트** | A(히어로) |

### 사용 패턴

1. **instance 생성**: `figma.createInstance(componentNode)` — Figma plugin / `use_figma` 통해
2. **화면 fill**: instance 내부의 IMAGE fill 영역에 viewer 캡처 hash 적용
3. **크기 조정**: `instance.rescale(targetWidth / originalWidth)` — `resize()` 쓰지 말 것 (자식 vector 잘림 — [[블로그/썸네일/1. 디자인 가이드/1-2. 레이아웃/1-2-1. 레이아웃 규칙]] §2.4 데코 룰과 동일 원칙)
4. **글로우 effect**: 강조 시 보라 글로우 `#6C4CFF` blur 20~30 추가

### 어떤 목업을 언제?

| 상황 | 목업 |
|------|------|
| **메인 히어로** (글 도입부) | `히어로 목업` — 이미 페어 완성, instance 1개로 끝 |
| **단일 viewer 강조** (한 페이지·한 기능) | `원페이지 목업` |
| **여러 페이지·여러 viewer 동시** | `멀티페이지 목업` 3개를 슬롯에 ×3 배치 |
| **사용법 단계 시연** | `멀티페이지 목업` ×3~4 + 화살표 `>` |

## 3. 에디터 캡처 및 모달 — `1:10970`

![[블로그/이미지/assets/컴포넌트-에디터캡처.png]]

> CdBd 에디터에서 자주 등장하는 **6개 핵심 UI**를 컴포넌트화. 매번 캡처·크롭 ❌, instance로 바로 끼우기.

| 이름 | 노드 ID | 크기(px) | 무엇을 보여주는가 | 강조 메시지 |
|------|---------|---------|------------------|-------------|
| **통계** | `1:11478` | 766 × 1003 | THE SIGNATURE DAY — 참여자 80명, 파이 차트, 답변 목록 | "행사 참여 통계 한눈에" |
| **예약카드** | `1:11479` | 400 × 360 | 예약 옵션 설정 다이얼로그 (날짜·시간·인원) | "예약 카드로 RSVP 받기" |
| **질문과 답변** | `1:11480` | 355 × 640 | 객관식·주관식 옵션 추가 패널 | "질문·답변 카드 빌더" |
| **카드 디자인** | `1:11481` | 470 × 712 | 카드 디자인 패널 (배경·테두리·모서리·여백) | "디자인 자유도" |
| **개인화 데이터** | `1:11482` | 556 × 330 | 데이터 추가/다운로드 테이블 (xx 이름·xx 이메일 주소) | "CRM·개인화 발송" |
| **페이지 통계** | `1:11483` | 1114 × 812 | 통계 요약 (페이지뷰 430 / 클릭수 150 / 클릭률 34.88%) + 라인 차트 | "페이지 성과 추적" |

### 사용 패턴

- **에디터 단독 유형 (D)**: 위 컴포넌트 중 1개를 `EDITOR_CANVAS` 슬롯 중앙에 배치
- **목업+에디터 유형 (E·H)**: 위 컴포넌트 1개 + 폰 목업 1개를 좌·우 배치
- **에디터+통계 유형 (I)**: 위 컴포넌트에서 **통계 카드만 발췌** (`페이지 통계`의 숫자 카드 부분, `통계`의 파이 차트 부분)
- **모달 유형 (J)**: `예약카드` 또는 다른 다이얼로그를 중앙 단독

### 어떤 에디터를 언제?

| 본문 메시지 키워드 | 추천 컴포넌트 |
|--------------------|---------------|
| "RSVP" · "예약" · "참여 신청" | `예약카드` + `통계` |
| "설문" · "응답" · "질문" | `질문과 답변` + `통계` |
| "디자인 자유도" · "커스터마이즈" · "꾸미기" | `카드 디자인` |
| "CRM" · "개인화" · "엑셀 업로드" · "이메일 발송" | `개인화 데이터` |
| "지표" · "성과" · "트래픽" · "조회수" | `페이지 통계` |
| "행사 참여" · "결과" · "후기" | `통계` |

## 4. Claude 자동화 매뉴얼 (use_figma)

> 블로그 이미지 생성 시 따라야 할 컴포넌트 사용 순서.

### Step 1 — 캔버스 결정
1. 본문 메시지 → 출력 크기 (1920×1200 vs 1000×1000) → 비교형이면 `1920x1200-비교`
2. 해당 캔버스 컴포넌트(섹션 2) instance를 출력 페이지에 생성

### Step 2 — 모바일 목업 fill
1. 유형(A/C/F/G/H 등) → 적합한 모바일 목업 컴포넌트 선택 (§1 표)
2. instance 생성 → `rescale()`로 슬롯 크기에 맞춤 → 화면 영역에 viewer 캡처 fill
3. 기울임(`rotation`) / 글로우 effect 적용

### Step 3 — 에디터 컴포넌트 끼우기 (해당 유형만)
1. D·E·H·I·J 유형 → 본문 키워드 매칭 (§3 표)
2. 컴포넌트 instance 생성 → 위치·크기 조정

### Step 4 — 라벨 pill / sparkle 데코
1. 컨텍스트 라벨 (5~12자) → 상단 pill 텍스트 노드 채우기
2. K·D 유형 등에서 `sparkle2/3/4` 인스턴스 추가 ([[블로그/썸네일/1. 디자인 가이드/1-2. 레이아웃/1-2-1. 레이아웃 규칙]] §2.4 화이트리스트 동일)

### 절대 원칙

- ❌ **컴포넌트 노드를 직접 수정 금지** (master 파괴 위험)
- ❌ **컴포넌트 없이 그리지 말 것** — 매번 새로 그리면 시리즈 일관성 깨짐
- ✅ **항상 instance** — `createInstance()` 후 instance 위에서만 변형
- ✅ **rescale 우선** — 자식 vector 비율 보존 (`resize()` ❌)
