# CdBd 이미지 자동화 — 무엇부터, 무엇이 필요한가

> ⚠️ **방향 정정 (2026-06-22)**: 이 문서는 기존 시스템을 모르고 작성했다. 실제 CdBd는 이미 **Figma 슬롯 템플릿 clone + viewer 캡처** 기반 자동화가 구축돼 있다([[블로그/이미지/1. 디자인 가이드/1-1. 스타일]] 등). 따라서 아래 §0의 "HTML/CSS 엔진" 권고는 **무시**하고, 렌더는 **Figma `use_figma`**로 한다.
> 단, **3트랙 분류(생성/합성/캡처)** 개념과 **장르→이미지 세트** 통찰은 유효하며, 이는 [[블로그/이미지/1. 디자인 가이드/1-0. 장르 → 이미지 세트 결정]] · [[블로그/이미지/1. 디자인 가이드/1-2. 레이아웃/1-2-3. 외부·실사 콘텐츠 유형]]에 **기존 폴더 체계에 맞춰 정식 반영**했다. → 실작업은 그 문서들을 사용.

## 0. 가장 중요한 전제 (방향 결정)

390장을 분석한 결과 CdBd 블로그 이미지는 **사진(photoreal)이 거의 없는 "플랫 그래픽 디자인"**이다.
폰 목업·UI 스크린샷·비교도·수치 배지·커버 — 전부 **고정된 레이아웃 + 텍스트 슬롯 + 브랜드 토큰**의 조합이다.

→ **결론: 핵심 엔진은 생성형(diffusion)이 아니라 "HTML/CSS 템플릿 + 헤드리스 스크린샷"이어야 한다.**
   - 이유: 픽셀 단위 브랜드 일관성, 텍스트(한글) 정확도, 수치 정확도, 수정 용이성, 무한 재현성 — 생성 모델로는 불가능한 것들을 템플릿이 보장.
   - 생성 모델은 **보조**로만: 재사용할 3D 오브젝트/배경 에셋을 "미리" 만들 때.
   - 실사진·외부화면은 **수집/촬영**(생성 불가).

이 한 줄이 전체 우선순위를 결정한다.

## 1. 런타임 파이프라인 (시스템이 글 1편을 받으면 하는 일)

```
[블로그 글(MD)]
  │
  ① 파싱: 제목 + 섹션 분할 + 슬롯 추출(브랜드명·수치·버튼명·비교대상·URL)
  │
  ② 장르 분류(LLM): 9개 장르 중 1개  → 이미지 세트 템플릿 결정
  │      (case_study / guide / comparison / cost_roi / thought_lead /
  │       feature_launch / profile_link / roundup / insight)
  │
  ③ 섹션→타입 배정(LLM): 각 섹션을 A~P 중 하나로 (L=제외)
  │
  ④ 트랙 분기:
  │     ├─ 생성·합성 트랙(A,B,C,D,E,F,G,I,J,K,O) → HTML/CSS 템플릿 렌더
  │     │      └ 슬롯에 텍스트 주입 + 에셋 라이브러리에서 배경/3D/스크린샷/디바이스 프레임 합성
  │     └─ 캡처 트랙(M,N,P,H) → 스크래퍼/촬영 큐로 (사람 개입 지점)
  │
  ⑤ 렌더: Playwright/Puppeteer로 템플릿 → PNG (원하는 해상도)
  │
  ⑥ QA: 수치=본문 일치 / 더미데이터(실명·실로고 회피) / 오타 / 컬러 검수
  │
  [이미지 N장 + alt 텍스트]
```

## 3. 무엇부터 — 단계별 우선순위 (Phase)

### ▶ Phase 0 — 기반 (먼저, 1순위) 〔없으면 아무것도 일관될 수 없음〕
1. **디자인 토큰 JSON 확정** (가이드 §5.3을 실파일로).
2. **에셋 라이브러리 폴더 구조 + 1차 수집**:
   - CdBd 에디터/데이터/통계/템플릿갤러리/게시모달/색상패널 **실 스크린샷** 캡처(가장 중요).
   - iPhone 목업 프레임(단일/2대 기울임/멀티), 다크·라이트.
   - 3D 데코팩 + 배경 3종.
3. **더미 브랜드 사전 정리** (이미 §5.5에 초안 있음 → 표준화).
> 산출: `tokens.json`, `/assets/{ui,devices,3d,bg}`, `dummy-brands.json`

### ▶ Phase 1 — MVP 엔진: 합성 트랙(C/E/F) 〔비중 ~40%, 가치 최대〕
- **타입 C(UI 스크린샷) 템플릿** 먼저: 에디터 캡처 + 디바이스 프레임 + 보라 손가락 커서 + 점선 강조 + 말풍선 배지를 HTML/CSS로 합성.
- 이어 E(단계흐름), F(결과 풀스크린) 템플릿.
- Playwright 렌더러 + 슬롯 주입 1건 end-to-end.
> 산출: 글 1편의 C/E/F 이미지가 실제로 나오는 데모. **여기까지가 진짜 MVP.**

### ▶ Phase 2 — 생성·구도 트랙(A/B/D/G) 템플릿
- A(히어로), B(수치/시소), D(Before/After), G(커버) HTML/CSS 템플릿.
- 배경·3D 오브젝트는 Phase0 에셋팩에서 가져다 배치(생성 모델 X, 합성).
> 산출: 가이드/비교/비용글의 표준 이미지 세트 자동 생성.

### ▶ Phase 3 — 두뇌: 장르 분류기 + 섹션 태거
- LLM 프롬프트 2개. §3 장르표 + §2 타입표를 few-shot으로.
- 글 → "이미지 N장 계획서(타입+슬롯값)" 출력까지 자동.
> 산출: 사람이 타입 안 정해도 글만 넣으면 계획이 나옴.

### ▶ Phase 4 — 캡처 트랙(M/N/P/H)
- 헤드리스 스크래퍼(경쟁사·외부툴·구글 AI Overview), 인스타 캡처, 실사진 아카이브 연결.
- 라운드업·인사이트·사례글 대응.
> 산출: 캡처 필요 타입 반자동화(사람 승인 1단계 포함).

### ▶ Phase 5 — 오케스트레이션 + QA + I/J/K/O 확장
- 전체 파이프라인 연결, 수치/실명 검수 자동화, 나머지 타입(I 인포그래픽·J 문제신·K 갤러리·O 콜라주) 템플릿 추가.

## 4. 추천 기술 스택

- **렌더**: React + Satori(→SVG→PNG) 또는 HTML/CSS + **Playwright** 스크린샷. (한글 폰트 Pretendard 임베드)
- **두뇌**: Claude API (장르분류·섹션태깅·슬롯추출·alt텍스트 생성). 프롬프트 캐싱으로 토큰표/few-shot 고정.
- **캡처**: Playwright(헤드리스) — 경쟁사/외부 사이트/Wix 본문 lazy-load 재수집까지 겸용.
- **에셋 저장**: 정적 폴더 + manifest.json (재사용 추적).

---

## 5. MVP의 최소 범위 (현실적 첫 목표)

> **"가이드/비교/비용 장르 글 1편 → C·D·F·G 이미지 4종 자동 생성"**

이 한 줄이면:
- Phase 0(토큰+에셋 일부) + Phase 1(C,F) + Phase 2(D,G) + Phase 3(분류기 최소)만 하면 됨.
- 캡처 트랙(M/N/P/H)·사례 실사진은 MVP 제외 → 후속.
- CdBd 글의 다수(가이드·비교·비용)가 이 범위에 들어와 즉시 효용.

## 7. 반드시 기억할 3가지

1. **생성 모델이 주인공이 아니다.** 플랫 디자인이라 **템플릿+스크린샷**이 정확·일관·저렴. 생성은 에셋 사전제작용 보조.
2. **합성 트랙(C/E/F)이 핵심이자 가장 어렵다.** 실제 UI 스크린샷 뱅크 품질이 시스템 품질을 결정. 여기에 가장 먼저 투자.
3. **장르 분류가 80%를 해결한다.** 글 장르만 맞히면 이미지 세트가 거의 자동 결정(§3). 분류기 정확도 = 자동화율.
