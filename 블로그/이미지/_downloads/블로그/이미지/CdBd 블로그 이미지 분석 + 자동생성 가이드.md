# CdBd 블로그 이미지 분석 + 자동 생성 가이드

> 블로그 6개 게시물 / 이미지 20장을 직접 다운로드·분석해 정리한 자료.
> 원본 이미지: `블로그/이미지/_downloads/` (게시물별 폴더)
> 목적: "블로그 글을 던지면 자동으로 이미지를 만든다"를 위한 **이미지 타입 분류 + 디자인 규칙 + 생성 프롬프트 템플릿**.

---

## 0. 한 줄 결론

CdBd 블로그 이미지는 **자유 일러스트가 아니라, 5~6개의 정해진 "이미지 타입(아키타입)"의 반복**이다.
글의 각 섹션이 어떤 **역할**(도입 / 효익 강조 / 기능 설명 / 경쟁 비교 / 완성 결과)을 하느냐에 따라 타입이 결정된다.
→ 자동화의 핵심은 **"섹션 역할 판별 → 해당 이미지 타입 선택 → 고정된 디자인 토큰으로 렌더"** 파이프라인이다.

## 1. 공통 디자인 시스템 (모든 이미지가 공유)

| 요소 | 값 / 특징 |
|------|-----------|
| **브랜드 강조색** | CdBd 보라 `#7C5CFC` 계열 (배지·버튼·커서·점선·하이라이트) |
| **제품/목업 배경** | 아주 연한 회색 + 미세 격자(그리드) 패턴 `#EFEFF1` 톤 |
| **감성/강조 배경** | 보라 격자 `#B9A6F5` 계열 (효익·수치 강조용) |
| **폰트** | Pretendard (한글), 영문 헤더 혼용 |
| **디바이스 프레임** | iPhone 15/16 Pro, 내추럴 티타늄 베젤 |
| **반복 데코 요소** | 보라 윤곽 손가락 커서 👆, 점선 강조 박스, 3D 이모지(돈자루·자물쇠·달력·핀·반짝이✨), 엑셀 아이콘, 말풍선/알약 배지 |
| **더미 데이터 톤** | 가짜 브랜드명(THE SIGNATURE DAY, THE SAGE, FINDERS), 가짜 명단(BTS 멤버 본명 등) — 실명 노출 회피 + 친근함 |
| **목업 그림자** | 부드러운 드롭섀도우, 디바이스는 살짝 기울이거나(히어로) 정면(설명용) |

## 2. 이미지 타입(아키타입) 6종 — 자동화의 핵심 분류

### TYPE A. 히어로 목업 (Hero Mockup)
- **언제**: 글 맨 앞(도입부). 게시물당 1장.
- **모습**: 연회색 그리드 배경 위 **아이폰 1~2대를 비스듬히** 배치, 화면엔 실제 CdBd 결과 페이지.
- **역할**: "이 글을 읽으면 이런 결과물이 나온다"를 0초 만에 보여줌.
- **예시**: `p1_01_intro`(FINDERS 명함), `p5_01_main`(인하대 패션쇼), `p6_01_main`(올인컴플리트, 브랜드 컬러 블랙 반영).

### TYPE B. 효익·수치 강조 일러스트 (Benefit / Stat Hero)
- **언제**: 핵심 효익이 "숫자"로 떨어지는 글.
- **모습**: 보라 톤 배경 + **3D 오브젝트**(돈자루·종이더미 등) + **큰 숫자 배지**("96% 비용 절감") + 비교 대상(종이 명함 vs 모바일 명함).
- **역할**: ROI·절감률·핵심 KPI를 감성적으로 각인.
- **예시**: `p1_02_operation`("월 800명 기준 96% 비용 절감").

### TYPE C. 제품 UI 스크린샷 (How-to / Feature Screenshot)
- **언제**: 기능 사용법·단계 설명 섹션. **가장 많이 쓰임**.
- **모습**: 에디터/데이터관리/통계 화면 캡처를 **둥근 카드**로, **보라 손가락 커서 + 점선 강조 박스 + 말풍선/배지**로 클릭 포인트 표시. 배경은 연회색 그리드.
- **역할**: "여기를 누르면 이렇게 된다"는 조작 흐름 안내.
- **예시**: `p2_03`(엑셀로 데이터 추가), `p2_05`(개별 URL 200개 생성 완료 모달), `p2_06`(미응답 엑셀 다운로드), `p3_05`(질문 구성 패널), `p3_06`(통계+엑셀), `p4_01`(에디터 전체), `p4_03`(레이아웃 디자인 탭).

### TYPE D. Before/After 비교 다이어그램 (Comparison)
- **언제**: 경쟁 도구·기존 방식 대비 차별점 섹션.
- **모습**: **좌우 2분할 + 가운데 점선 구분선.** 좌측=문제(흐림/회색, "일반 티켓팅"), 우측=해결(컬러, "CdBd"). 하단에 키워드 칩 나열.
- **역할**: "쟤네는 이게 안 되고, 우리는 된다"를 한 화면에 대조.
- **예시**: `p3_02_compare`(일반 티켓팅 플랫폼 vs CdBd 비공개 RSVP).

### TYPE E. 단계 흐름 / 프로세스 (Step Flow)
- **언제**: "URL 붙여넣으면 → 자동 채워짐" 같은 변환·단계.
- **모습**: 폰/카드 **2~3개를 `>` 화살표로 연결**, 빈 상태 → 입력 → 완성 순.
- **역할**: 입력→결과 자동화를 시각적 단계로.
- **예시**: `p4_02_editor`(빈 상품카드 → URL 입력 → 상품 자동 채움).

### TYPE F. 완성 결과 풀스크린 (Result Showcase)
- **언제**: 완성된 페이지 자체를 보여줄 때 / 브레드크럼 안내.
- **모습**: 폰 프레임 안에 **실제 페이지 한 장 전체**. 또는 상단에 보라 알약 **브레드크럼 배지**("CdBd 템플릿 > 초대·예약 > 비공개 세미나").
- **역할**: 결과물 디테일·브랜드 톤 확인, 시작 경로 안내.
- **예시**: `p3_03_preview`, `p3_04_template`(브레드크럼+템플릿 사용하기), `p5_02_time_location`, `p6_02_design`(테마 색상 팔레트 패널).

## 3. 게시물별 분석 (글이 왜 이 이미지를 필요로 했나)

### P1. 50인+ 전사 명함 도입 ROI
- **p1_01_intro** (TYPE A): FINDERS사 모바일 명함 2대 목업. → *비용 글은 추상적이라, 도입부에 "실제 결과물"을 보여 신뢰·구체성 확보.*
- **p1_02_operation** (TYPE B): "월 800명 기준 96% 비용 절감" + 돈자루/종이명함더미 vs 모바일 명함 2종. → *글의 최종 무기인 ROI 숫자를 한 장에 박제. 종이(과거) vs 모바일(현재) 대비.*

### P2. VIP 200명 1:1 개인화 초대장
- **p2_01** (TYPE C 변형): THE HERITAGE SUMMIT 초대장 + 데이터 관리 표(이름·번호) 오버레이. → *"엑셀 한 장 = 200명 개인화"의 데이터↔페이지 연결을 시각화.*
- **p2_02**: 데이터 표/응답폰/파이차트를 한 화면에 모은 운영 개요. → *발급·응답·통계가 한 곳이라는 메시지.*
- **p2_03** (TYPE C): "황영기 회장님께" 개인화 인사 + 대체어 데이터 표. → *1:1로 이름이 박히는 모습 증명.*
- **p2_04**: 데이터관리 화면에 발급된 개별 cdbd.in URL 목록 + 손가락 커서. → *URL 자동 발급 결과.*
- **p2_05** (TYPE C): "개별 URL 200개 생성 완료" 모달 + 손가락 커서. → *대량 자동 발급의 결정적 순간.*
- **p2_06** (TYPE C): 통계 화면 → 엑셀 → 봉투(재안내). → *미응답자만 추려 수동 리마인드하는 흐름.*

### P3. 이벤터스 대안 — 비공개 기업 행사 RSVP
- **p3_01_sample** (TYPE F): 비밀번호 입력화면 + 참석/사전정보 RSVP 폼 + 자물쇠 이모지. → *"비공개" 핵심 가치(링크 가드)를 그림으로.*
- **p3_02_compare** (TYPE D): 일반 티켓팅(공개노출·결제UX·브랜드부재·집계불가) vs CdBd(비공개·브랜드톤·소속집계). → *대안 글의 뼈대인 1:1 대조.*
- **p3_03_preview** (TYPE F): THE SAGE RSVP 초대장 풀스크린. → *완성 결과 디테일.*
- **p3_04_template** (TYPE F+브레드크럼): "CdBd 템플릿 > 초대·예약 > 비공개 세미나 템플릿" 배지. → *어디서 시작하는지 경로 안내.*
- **p3_05_questions** (TYPE C): 질문 구성 패널(필수답변·복수선택 토글). → *응답 항목 커스텀 방법.*
- **p3_06_stats** (TYPE C): 통계(265 참석/132 불참 파이) + 엑셀 다운로드 + 손가락 커서. → *소속별 집계·다운로드 운영.*

### P4. 상품 카드 — 큐레이션 카탈로그
- **p4_01_autofill** (TYPE C): 에디터 전체 — 무신사 URL 입력 시 이미지·상품명·59,000원 자동 채움. → *"URL 한 줄 = 자동 진열"의 증거.*
- **p4_02_editor** (TYPE E): 빈 상품카드 `>` URL 입력 `>` 상품 완성 3단 흐름. → *입력→결과 자동화 단계.*
- **p4_03_horizontal** (TYPE C): 가로형 레이아웃 + 디자인 탭(그리드/가로형, 간격, 구성 ON/OFF). → *진열 옵션 변경 방법.*

### P5. 인하대 졸업패션쇼 — 1일 2회 공연
- **p5_01_main** (TYPE A): 패션쇼 초대장 2폰 목업(스케치 키비주얼 + 16시/19시). → *실제 사례 결과물.*
- **p5_02_time_location** (TYPE F): 행사시간(16/19시)·장소(섬유센터빌딩 3F)·네이버지도 카드. → *1일 2회를 한 줄로 정리한 핵심 장면.*

### P6. 올인컴플리트 — 디자이너 브랜드 플래그십
- **p6_01_main** (TYPE A): 블랙 배경 + 옐로우 봉투/모자 키비주얼 초대장 2폰. → *브랜드 톤(블랙·라일락)이 결과물에 그대로.*
- **p6_02_design** (TYPE F): 초대장 풀스크린 + 페이지 테마 색상 팔레트 패널. → *디자인 자유도(컬러 통일) 증명.*
- **p6_03_lookbook** (TYPE C/F): 모자 그리드 룩북 + 착용컷 캐러셀 + RSVP 참석여부 폼 3폰. → *초대장+룩북+RSVP가 한 페이지라는 메시지.*

## 4. "글 → 이미지" 자동화 매핑 규칙 (의사결정 로직)

글의 섹션을 읽고 아래 신호로 이미지 타입을 결정한다.

| 글에 나타나는 신호 | 생성할 이미지 타입 |
|---|---|
| 글 도입부 / "사례를 소개합니다" / 결과물 언급 | **A. 히어로 목업** |
| %·원·배수·"절감"·"ROI"·비교 수치 | **B. 효익·수치 강조** |
| "이렇게 하세요" / 1·2·3 단계 / 에디터·설정 언급 | **C. UI 스크린샷** |
| "vs" / "대안" / "기존 방식" / "다릅니다" | **D. Before/After 비교** |
| "붙여넣으면 → 자동으로" / 입력→결과 변환 | **E. 단계 흐름** |
| "완성된 페이지" / "템플릿에서 시작" / 결과 디테일 | **F. 결과 풀스크린 / 브레드크럼** |

**배치 관행**: 글 1편 ≈ 이미지 2~6장. 도입부 A 1장 → 본문 섹션별 C/D/E/F → (수치 있으면) B 1장.

## 5. 생성 프롬프트 템플릿 (이미지 생성 모델용)

> 공통 접두사로 항상 붙일 것:
> `Clean product marketing graphic, light gray subtle grid background, CdBd purple (#7C5CFC) accents, Pretendard-style Korean typography, soft drop shadows, flat + 3D-emoji mix, no real logos.`

- **TYPE A**: `One or two iPhone 16 Pro (natural titanium) tilted on light grid bg, screen shows a mobile {명함/초대장} page for "{브랜드}", elegant minimal.`
- **TYPE B**: `Purple gridded bg, large badge "{숫자}{단위} {효익}", 3D objects ({돈자루/종이더미}) on left vs phone mockup on right, comparison feel.`
- **TYPE C**: `Rounded card screenshot of CdBd editor/{화면명}, purple outlined finger cursor pointing at {버튼}, dashed highlight box, small callout badge "{포인트}".`
- **TYPE D**: `Two-column split with dashed center divider. Left (muted/gray) = "{경쟁 도구}" with problem keyword chips. Right (color) = "CdBd {기능}" with benefit chips.`
- **TYPE E**: `2-3 phone/card frames connected by purple ">" arrows: empty state > input "{URL/데이터}" > completed result.`
- **TYPE F**: `Full phone frame showing finished "{브랜드}" page in its brand colors; optional purple pill breadcrumb "CdBd 템플릿 > {카테고리} > {템플릿}".`

## 6. 자동화 시스템 설계 메모

1. **입력**: 블로그 글(마크다운) → 섹션 단위로 분리.
2. **분류기**: 각 섹션을 §4 신호표로 A~F 타입 라벨링(LLM 분류).
3. **콘텐츠 추출**: 브랜드명·수치·버튼명·비교 대상 등 슬롯 채우기.
4. **렌더**: §5 프롬프트 + §1 디자인 토큰으로 생성(이미지모델) 또는 템플릿 합성.
5. **검수**: 실제 UI 스크린샷이 필요한 TYPE C/E는 생성 이미지보다 **실 캡처 합성**이 정확 → 에디터 스크린샷 라이브러리 별도 구축 권장.
6. **주의**: 더미 데이터는 실명·실로고 회피. 수치는 글 본문과 반드시 일치.
