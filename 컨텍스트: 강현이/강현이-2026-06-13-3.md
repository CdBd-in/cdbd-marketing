## 4. ⚡ 자동화 돌파 — 컴포넌트화·section 이동 자동화 검증

### 옛 제약 (이 세션에서 폐기)
> 가이드: "컴포넌트 변환·section 이동은 `use_figma`로 commit 안 됨 → 사용자 수동 마무리 필요"

이 가정은 실제로 검증한 적 없는 잔재였음.

### 신 자동화 (stethoscope 등록으로 검증 성공)
```js
// 1. Frame 빌드 (crown 컴포넌트와 동일 패턴 — outer transparent + inner image)
const outer = figma.createFrame();
outer.resize(100, 100);
outer.fills = []; // transparent
const inner = figma.createFrame();
inner.resize(100, 100);
inner.fills = [{ type: "IMAGE", scaleMode: "FIT", imageHash: HASH }];
outer.appendChild(inner);

// 2. Component 변환
const comp = figma.createComponentFromNode(outer);
comp.name = "stethoscope";

// 3. Section 이동 + 좌표 설정 (2 row × N col 그리드: x +126 / y=120(2D)·y=275(3D))
const section = await figma.getNodeByIdAsync("4:117");
section.appendChild(comp);
comp.x = 603; // 그리드 다음 컬럼
comp.y = 275; // 3D 행

// 4. 시안의 frame placeholder → instance로 swap
const inst = comp.createInstance();
inst.rescale(2.6); // 100 → 260
```

→ 향후 envelope·mobile-phone·church·cross·smartphone (이미 다운로드만 완료된 5종) 등록도 사용자 개입 없이 자동화 가능. 가이드 §4.1/§4.3 자동화 메모 갱신 완료.

## 7. 작업 흐름 인사이트

1. **본문 톤 vs 단어 표면 함정** — "위촉식"만 보고 crown(VIP)을 선택한 1차 실수. 본문을 직접 읽어야 함 (Wix 대시보드는 인증 필요 → 사용자에게 본문 키워드 요청해 우회).
2. **자동화 가정의 위험** — 옛 가이드의 "사용자 수동" 제약은 실제로 검증 안 했던 가정. 시도해보면 자동화 가능한 경우가 많음. 가이드 룰을 정기적으로 "이게 정말 못 하는 거 맞나" 의심 필요.
3. **사용자 사례 누적 = 룰 정밀화** — PICOHI 사례 1개로 서브타이틀 정책 전체가 재정립됨. 한 시안이 가이드를 5+ 라인 변경.
4. **연쇄 갱신의 함정** — 룰 변경 시 한 파일만 갱신하면 나머지가 outdated. Audit 정기 필요.
5. **자동 보정 룰 누락의 위험** — y 보정 룰은 가이드에 있었지만 빌드 시 깜빡함. 검수 체크리스트에 명시 항목으로 끌어올려야 재발 안 함.
