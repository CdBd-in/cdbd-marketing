## 핵심 설계 결정사항 (다음 세션이 따라야 할 새 기준)

- **캡션이 진실의 원천**: CdBd 블로그 본문엔 이미지 자리마다 `*캡션*`이 박혀 있다. **글을 장르로 분류하거나 이미지 수를 추론하지 않는다** — 캡션 1개 = 이미지 1장, 위치·개수·내용은 캡션이 결정. 캡션 없는 자리엔 이미지 안 만듦.
- **목적 5종은 per-image** (기본·강조·비교·나열·프로세스). 캡션 메시지 → 목적 1개 결정은 [[1-2-1-1. 공통]] §1 라우팅, 캡션→목적·템플릿·트랙 매핑은 [[1-2-2-2. 이미지 제작 가이드]] §5.
- **제작 = clone 모델**: 단일 출처 「템플릿」 `377:5848` clone → **교체 레이어(화면 스크린샷 rect·3D instance·텍스트)만 fill**, 베젤·BG·그리드·화살표·데코는 내장 상속. 레이어는 **타입+위치로 식별**(의미론적 슬롯명 없음).
- **트랙 3종**: 합성(5목적) / 캡처(외부·경쟁사) / 소싱(실사진). 실사진·외부캡처는 자동 합성 불가.
- **주제 분류는 영구 폐기** — 단, "글 성격별 어휘"는 텍스트 §2.5에 보편어로 잔존(분류용 아님, 단어 선택 일관성용).

## 기술 메모

- **Wix MCP API URL은 대화 컨텍스트에서만** — `SearchWixAPISpec`로 `lightIndex` 검색해 `method.publicUrl` 확보 후 `CallWixSiteAPI`. `body`는 실제 JSON 객체로 전달(문자열 ❌).
- **richContent 파싱**: 본문은 RICH_CONTENT 노드 배열(PARAGRAPH/HEADING/DIVIDER/BLOCKQUOTE/BULLETED_LIST). `*…*` 캡션은 평범한 TEXT라 텍스트 패턴으로 추출.
- **한글 경로 + Edit**: 린터/사용자가 동시 편집 → "File has been modified since read" 발생 가능 → **Edit 전 해당 구간 재-Read**.
- **삭제는 `git rm`** (obsidian-git 자동 커밋). 깨진 링크 검증은 `os.walk`로 파일명 집합 만들고 `[[...]]` 정규식 대조 (jq 없음 → python3).
